# 第二轮蓝牙提速：运行期 UART 921600

本轮只修改 FPGA 固件；现有 `gowin-control-0.2.1-gw25k-fast-debug.apk` 可直接连接。业务 UUID、GATT 属性、ATT MTU 23、20 字节特征值、B1 分片、256 字节块、窗口 1、CRC 和续传规则不变。

## 实现

启动仍使用 115200 / 8E1，下载原有 30147 字节补丁及原有配置，完成 HCI Reset。随后额外发送 Realtek `FC17`，参数 `04 50 F7 05`（速率编码 `0x05F75004`，921600）。只有成功的 Command Complete 和 H5 发送确认均到达后才进入切换。

H5 提供 `baud_idle`：要求 UART TX/RX 空闲、无待发送 ACK、无主机包及收发复制、收件箱已消费。连续空闲 20ms 后切换分频，再等待 50ms 才继续后续初始化。没有提前释放可靠包，不改变 H5 单包窗口、序号、重传或 ACL 额度规则。FC17 被拒绝时保持原速并报告初始化失败，避免两端速率不一致后继续工作。

`adaptations/bt_uart_fast.v` 是独立适配，原 vendor UART 和补丁包保持冻结。50MHz 时低速分频 434，高速分频 54；高速实际约 925926 baud，较目标高 0.47%。`debug[23]` 显示选择的目标速率；`FAST_BAUD=115200` 可在编译时保留原速路径，当前高速配置仅支持 921600。

## 实板对比

同板、同电脑、相同位置；各下载 32 块、8192 字节 PCM，不包含录制、连接和编译。两次均逐字节校验参考音频及块 CRC。

| SRAM 前后对比 | 上版 115200 | 本轮 921600 |
|---|---:|---:|
| 耗时 | 8.039 秒 | 6.899 秒 |
| 有效 PCM 吞吐 | 1019.0 字节/秒 | 1187.5 字节/秒 |
| READ 到 DATA 完成均值 | 190.5 ms | 156.3 ms |
| ACK 完成均值 | 60.7 ms | 59.2 ms |

吞吐增加 **16.5%**；内部串口提高 8 倍没有等比例转化为无线吞吐。当前小 MTU 通知、逐块 READ/ACK 往返和中央设备的连接调度仍占主要时间。测量记录见 [原版基线](../reports/speed2_20261020/baseline.json) 和 [高速 SRAM](../reports/speed2_20261020/fast_sram.json)。

手机上的实际速度仍需安装现有 APK 测试；电脑 BLE 实测不能替代 Android 系统 GATT、UI 和后台行为验收。最终资格、完整下载、固化后复验见 [本轮汇总](../reports/speed2_20261020/summary.json)。

## 最终验收

Flash 写入、校验及 Reprogram 重载通过，UserCode `02AD` / Status `70022020`。重载后连续 32768 字节下载 29.281 秒、1119.1 字节/秒，所有字节及 CRC 正确。与本轮同板基线相比约提高 9.8%；和 SRAM 短测一起如实报告 **1119–1187 字节/秒** 的观测范围。

APP 原始 Kotlin 的完整 192000 字节下载（含取消重开、断线续传与 WAV 保存）为 176.792 秒，上一轮 196.181 秒，耗时减少约 9.9%。主动丢一个命令分片后原 ID 重试恢复；完整 WAV SHA256 `2c492fa12189698f5abf3032cfd97aa322e8c4df5456b37f0c7bf56800d760ed`，与参考文件逐字节一致。

14 组回归通过。完整 UART 模型核验全部 30147 字节补丁；其他 UART 分支采用 253 字节双片模型覆盖边界，避免每个错误场景重复 120 片。原速路径、被拒绝切速保持原速且不进入业务、错误 ROM/随机数均覆盖。先前默认 120 秒超时和中途停止的重复运行保留为诊断，不作为通过证据。

固件 Fmax 50.314MHz，50MHz 约束下 setup/hold 违例 0/0。16003 LUT、8783 Register、10856/11520 CLS（95%）、30/56 BSRAM；资源及频率余量有限。后续扩展 MTU 或发送窗口需要同步考虑内存与时序。未实际断电，本轮 Flash 使用 Reprogram 重载。
