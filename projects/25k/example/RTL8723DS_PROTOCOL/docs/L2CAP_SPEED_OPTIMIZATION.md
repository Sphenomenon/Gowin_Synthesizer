# 第四轮：外设连接参数协商

上一版 ACK_READ 固件同板32768字节下载约1604字节/秒，通知回调常成组到达，组间间隔约28毫秒。本轮将传输订阅时的提速请求由 HCI LE Connection Update 改为 LE L2CAP Connection Parameter Update Request（CID=5、code=0x12），请求15毫秒、latency0、4秒 supervision timeout。

RTL8723DS 使用 BLE4.0 外设角色，L2CAP 信令是适用的外设请求路径。上一版 HCI 请求未记录控制器返回状态，不能仅凭代码断言具体拒绝码。本轮实板下载从20.43秒降到10.86秒（32768字节，1604→3017字节/秒，+88.1%）；较大通知间隔中位数约28→13毫秒。这是客户端回调时间证据，并非直接读取的链路层间隔；控制器参数更新结果和当前间隔未通过诊断接口导出。

固化后同样32768字节为10.73秒、3055字节/秒（较本轮基线+90.5%），UserCode `EBE1`、Status `70022020`，写入/校验、重载和无线复验通过。

## 调度与兼容

- 仅在本连接第一次启用 Transfer CCCD 后请求一次；断线或新连接清除请求状态。重复订阅不触发重复请求。
- L2CAP 请求属于 ACL 流量，受控制器公布的缓冲额度约束，占用一份额度，只有 Number Of Completed Packets 才补回。H5 UART、ACK、重试和窗口1保持原样。
- 请求长20字节（含ACL头），信令ID=0x25；ACL data length16、L2CAP length12、CID5、code0x12、参数长度8，小端interval min=max12（1.25ms单位）、latency0、timeout400（10ms单位）。
- 对端接受或拒绝的 code0x13，以及 Command Reject，都作为终止响应处理，不再生成 Command Reject 循环。拒绝或无响应不会阻塞业务数据，也不会宣称协商成功；继续使用当前连接参数。
- ATT23、20字节特征值、B1分片、Capability0x68、256字节PCM块、窗口1、CRC32、ACK_READ原子提交及同ID重试不变。
- Android0.2.2源码和APK保持不变；无需更新已装的0.2.2。旧APP仍可使用原READ/ACK，但其手机实际速率待验收。

## 验证

定向仿真检查请求字节、ACL额度消耗、接受/拒绝不回环、重复订阅不重复请求。完整14组RTL/主机回归含实际UART8E1/H5、完整30147字节补丁，以及新L2CAP信令帧的独立对端验证。

APP Kotlin实板完整192000字节下载约72.02秒，上一轮约135.22秒（两次均含取消重开、断线恢复和已执行命令响应丢失后的同ID重试等待）。WAV与参考逐字节一致，746个ACK_READ组合块通过；检查点持久化、CRC与末块独立ACK/CLOSE保留。独立录音边界、旧READ/ACK、旧确认写入协议均复验。

固化后结果、位流和APK哈希及原始记录见 [本轮汇总](../reports/speed4_20261020/summary.json)。手机原生GATT、权限、UI、后台行为与手机实际速率未测；新镜像未物理断电验收。

## 继续保留的启动标识限制

本轮未改变LE Rand初始化。上一轮观察到同镜像JTAG重载后boot_id重复，身份唯一性未通过，见 [原始失败](../reports/speed3_20261020/flash_boot_identity_repeat.json)。不能承诺跨重启的身份唯一性；板卡重启或重配置后，应先删除手机未完成下载，再开始新录音。同次启动内的取消和断线续传已经验证。本轮的传输提速资格不包含解决该问题。
