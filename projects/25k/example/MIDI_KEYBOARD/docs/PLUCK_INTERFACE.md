## 采样、检测与映射

- `midi_pluck_adc.v`：默认4 kHz CONVST、2.5 MHz SCLK，CONVST高2 µs；观察BUSY置位再等待释放，双DOUT读取64个时钟、16位有符号、MSB-first。CS下降后首位有效，SCLK上升沿更新、下降沿采样；输入两级同步，200 ns半周期留出同步延迟。
- 完整弹拨版及临时PWM探针用25kHz采样/2.5MHz SCLK，不擅自切换为“转换中读取”：BUSY先高后低后才拉低CS，CS整帧保持低，DOUTA依序V1..V4、DOUTB依序V5..V8，64次下降沿取样后发布八路完整帧。首下降沿距CS下降400ns，后续取样距SCLK上升200ns，覆盖手册输出延时及两级同步；50MHz实速仿真覆盖BUSY 3.45/4/4.2µs、CS到MSB35ns、SCLK到数据39ns及三态，不仅使用零延时理想模型。RESET仍是C36从3.3V耦合、R13/R72下拉的硬件网络，未接排线GPIO；FPGA复位不是ADC硬复位，未实测RC脉冲不宣称已确认上电复位。
- 完整八通道才发布一次采样。BUSY不置位、不释放或启动时已卡高均失败关闭：online清零、超时计数饱和累加、门控释放，后续时隙重试。没有RESET GPIO，不伪造软件硬复位；其他外设和USB不等待ADC。
- 新候选发射输出改为上述五路PWM，不再把发射使能复制成五路DC。临时诊断默认OFF；必须在GUI人工确认后启用。
- `midi_pluck_detector.v`：64次有效采样建立基线，空闲缓慢跟踪；差值绝对值≥1024触发、≤512才可重武装。门控50 ms，结束后连续安静10 ms才可再触发。阈值和时长是未实测的编译期初值，不是已验收灵敏度。故障后重新校准，不补播旧动作。
- 当前完整弹拨版及临时PWM探针启用`CARRIER_MODE=1`：50点/2ms不重叠有符号Vpp窗口，最低1kHz载波每窗口含2周期。启灯/重校准先等待50窗口/100ms，再无遮挡记录500窗口/1秒，每路取这些窗口Vpp的最小值R并冻结为载波参考，不再把有用载波当噪声最大值。ON/OFF为最小下降计数64/32，触发阈值`R-max(ceil(R/2),ON)`，恢复阈值`R-max(ceil(R/4),OFF)`；仅`R>2*ON`且阈值有迟滞时有效，低载波/无效路不触发。
- 每路先连续5窗口/10ms达到恢复阈值才武装，Vpp连续2窗口/4ms低于或等于触发阈值发一次50ms Note；持续遮挡不补发，必须先结束门控且恢复连续10ms才能再触发。短于窗口的动作仍可能漏检；这是待实物验证的“遮挡降低载波幅度”假设，而不是已确认光学极性。Vpp表格仍保持200ms，0x06和GUI图用最近2ms窗口，无显示保持延迟。关闭/ADC故障/重校准清参考和门控，计数保留，不自动跟踪吞掉动作。
- B1/B2历史模式仍保留并回归：250点/10ms，上升Vpp检测，B1绝对64/32，B2取100窗口噪声最大值加64/32、安静30ms重装填。它们没有五载波，不能用其“手盖全不触发”作为新PWM配置的物理验收。旧完整开发分支曾使用基线检测器，当前完整弹拨版已迁移为载波下降检测。
- 静止时第2/4路抖动已由操作者反馈确认，不能把B1实际MIDI当成成功弹拨。B2先抑制这类静态误触，不把ADC取反或发射低有效作为推断：`max(-x)-min(-x)=max(x)-min(x)`，原值取反不能改变Vpp。保持遮挡后没有反复触发与“一次50 ms弹拨”语义并不矛盾；遮挡瞬间与移开瞬间哪边产生峰值、是否都能独立识别，仍需操作者物理对照。B2没有擅自把下降沿/持续遮挡改为Note On。
- 用户更正：五路灵敏性来自示波器观察，没有已成功的Xilinx板/工程。此次增加载波的依据是2026-11-01用户明确给出的五路频率及更新网表，不是先前未经证实的频率推算。25kHz采样只能观察采到的峰谷，不能保证还原高于12.5kHz或短于采样间隔的模拟峰值；GUI不是示波器原始波形。
- 仅旧完整开发分支`midi_pluck_detector.v`五路共用一条算术路径，24位基线与8位持音倒计时打包成默认32位同步BSRAM字；安静计数、重武装保持寄存器，避免宽RAM造成物理碎片。每通道先读后更新，写当前通道时预取下一通道，明确推断SDPB，不依赖同址读写碰撞结果。每份ADC快照占一个接收周期加十个处理周期，远小于12500周期采样间隔；整帧完成后提交门控。处理未结束又收到新快照则释放门控、取消本帧并重新校准，饱和累加overrun，不阻塞采样或USB。RAM不做全阵列复位；校准首帧确定性写入各通道基线与零持音，校准完成前不输出Note。触发总数随全局复位清零，ADC故障重校准保留历史计数。
- 当前完整弹拨版使用`DIAGNOSTIC_DETAILS=1`，保留六路16位原始值、五路Vpp显示值／逐路计数、32位触发总数、采样／故障／overrun计数和参考／阈值。串行引擎每帧35拍后提交整帧，以原并行载波检测器为参考逐项比较。旧精简开发配置仍用word1 bit5表明能力；不支持详细统计时相关word保留零，GUI显示“—”，不伪装成测得零值。
- CHN1–5 **暂用**触摸逻辑键A–E，即`48,49,50,51,52 + transpose`。此表不是网表能确定的最终音阶表，实物顺序和产品映射仍待用户确认。通道、移调、On100/Off0、背压和USB/BLE会话清理复用现有`gw138k_panel_performance`，不增加第二套参数权威，不修改138K。
- 两份正式配置各自只有一个附件来源，不支持同时混合触摸和弹拨。检测计数不是USB成功交付数；长背压可合并短促键状态，沿用触摸键状态合同，不承诺无损事件录制。

## MK 只读诊断扩展

沿用`SCREEN_PROTOCOL.md`的16字节`MK`、version=1、CRC、sequence和EP2/EP82，不另建串口或私有MIDI消息。新增`GET_PLUCK=0x03`：arg0=0..15、arg1=0，仅`--pluck`及`--pluck-probe`配置启用；普通/旧位流返回bad_opcode，不得解码为零采样。

读word0时锁存全部512位并返回签名；word1–15来自该锁存快照，下一轮重新从word0开始。USB/控制会话复位使快照失效，首次成功读word0前其余word返回零，不暴露未初始化数据。命令不产生config_write，不修改音量、音色、通道、移调或屏幕。

诊断不在采样端再复制整份512位。word0先等待`pluck_diagnostics_valid`，再逐字复制16拍到MK快照RAM；复制期间有效窗口中断则重头采集，不返回半旧半新内容。完整弹拨串行处理占35拍，采样端继续按原节拍工作；后续word从冻结快照读取，不等待ADC。CRC、版本和参数错误不受此等待影响。ADC故障仍允许读取故障诊断，USB/MIDI和采样调度不等待GUI。

## 本地 GUI

从仓库根目录运行，依赖Python 3、Tk、系统libusb-1.0和Linux ALSA raw MIDI；无需PyUSB，不卸载MIDI内核驱动：

```sh
python3 projects/25k/example/MIDI_KEYBOARD/tools/pluck_monitor.py
python3 projects/25k/example/MIDI_KEYBOARD/tools/pluck_monitor.py --probe
python3 projects/25k/example/MIDI_KEYBOARD/tools/pluck_monitor.py --telemetry-file /tmp/gw25k-pluck-latest.json
```

显示六路原值、五路门控、触发总数、自动缩放图和**实际从ALSA接收**的Note、CC、Program、Pitch Bend；仅bit5存在时显示逐路幅值/计数，否则“—”。bit13存在时表格明确标注Vpp/200ms峰值保持；旧模式图用保持值，新bit15模式图用0x06最近2ms窗口，便于观察载波下降，短动作可能被20Hz界面跳过，须结合计数/MIDI日志而不能只看图。其他模式显示低速原值。图不是全速录制，不模拟或回发Note。日志/图有界，过期、断开、采样停滞和缓存覆盖明确提示。只允许唯一VID:PID匹配设备；厂商接口独占，不能同时运行其他MK客户端。`--telemetry-file`只原子替换一份最新JSON，含时间、快照、模式位、实际MIDI计数及最近20条日志，供只读观察者取证而不重复抢USB；不是无损录制。

临时Vpp配置独有`SET_PLUCK_THRESHOLDS=0x05`，arg0低16位ON、高16位OFF，必须满足`0 <= OFF < ON <= 65535`，arg1=0；成功结果回显arg0，其余配置返回bad_opcode。按bit15/14区分新载波最小下降计数、B2噪声余量和B1绝对值；不能向新候选套用旧算法说明。应用后重新校准、门控释放、计数保留；USB会话复位/断开恢复64/32，重连不自动重发。GUI要求移开双手；新模式等待100ms稳定及1秒无遮挡参考，表格明确“无遮挡载波参考”“触发≤/恢复≥”，弱载波路禁止触发。此为传感器诊断参数，不引入138K公共参数第二权威。

默认不发送任何写命令。只有临时诊断身份且ADC在线时，GUI才允许点击“电气确认后开启发射灯”；必须由操作者确认LED峰值/平均电流、120Ω限流和供电/接线，旧DC配置还须满足连续电流额定值。网表未填写发射灯型号，不能凭50%PWM认定安全。3.3V/120Ω的理想上界为27.5mA，实际电流随LED压降降低；工具不代替电流实测。

临时诊断独有`SET_PLUCK_EMITTERS=0x04`，arg0只能为0/1、arg1=0，响应回显arg0；完整`--pluck`等配置返回bad_opcode。该命令只写本地诊断使能，不是公共参数。上电/复位/USB会话结束/掉线/ADC离线均关灯，1续租2秒、0立即关灯，GUI显式开启后每0.5秒续租；GUI退出或故障停止续租，最长2秒关闭，重连不自动开启。ADC关灯时继续采样/Vpp/滑杆观察，但不校准/发Note。新载波模式开启后先稳定100ms，再500个2ms窗口校准；历史B2为100个10ms窗口，B1为16个，A2为64帧。GUI关闭尽力发送OFF，不能用软件清理替代硬件租约。

权限不足时保留MIDI监视、提示ADC不可用。2026-10-31早期实测USB节点无写权限；用户安装规则后，A2已能回读六路原值、4000 Hz增长计数，BUSY超时/overrun为0。USB总线地址会随枚举改变，不硬编码旧节点。规则只限定此VID/PID，不必动JTAG或以root运行GUI：

```sh
sudo install -m 0644 projects/25k/example/MIDI_KEYBOARD/tools/60-gw25k-midi.rules /etc/udev/rules.d/60-gw25k-midi.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --action=add --subsystem-match=usb --attr-match=idVendor=fb9a --attr-match=idProduct=fb9b
```
