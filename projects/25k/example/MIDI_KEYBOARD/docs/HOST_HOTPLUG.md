# 138K 面板与热插拔维护入口

25K 的产品入口是本目录的 `midi_keyboard_top`，默认 `HOST_PANEL_CONTROLS=1`。触摸板、两个编码器、PCA9685、WS2812 和 NV3007 屏接在 25K；25K 的 USB3300 数据口接 138K USB-A，Push 与 25K 轮流使用该端口。USB MIDI 与 PL 像素共用现有复合设备，线规见 [USB 配置](USB_PROFILE.md)、[PL 协议](PANEL_DISPLAY_PROTOCOL.md) 和 [主机规范](../../../../138k/push2_workstation/usb_a/GW25K_PANEL.md)。本页只说明维护和故障边界。

## 控件与会话

- 16 键为 MIDI 48–63，Note On 力度 100，Note Off 力度 0；物理电极与灯序沿用已确认 A–P 映射。
- E1 每物理档发送一项 CC7，短按一次发送 CC89=1；E2 每档按 73／40／56／12／0 选择音色，短按一次发送 CC88=127。两个长按未分配，远端页面期间控件继续工作。
- 滑条发送 Pitch Bend，释放回 8192；保留原触摸滤波及可调中心死区。
- 滑条本地位置和 PCA9685 灯条在未连接 USB／BLE、枚举中及传输背压期间均随有效触摸快照更新，松手回中。USB 接入不重置本地灯条；离线动作不进入 MIDI 队列，也不在重连后回放。
- USB 接入后本地控件缓存从音量 127、音色 73、弯音中心开始；138K 负责全局清音和音源初始化。25K 不重发旧初始化清理序列，也不把旧持音补播给新连接。
- 每次物理按下记录当时已在线的接收目标。加入另一链路不继承旧持音；移调先释放全部旧音，再向仍在线的原目标重发新音。USB 断开不抹去持续在线 BLE 自己的持音。
- USB 总线复位、取消配置、MIDI 接口复位清除对应传输队列；重新配置后不发送旧会话的排队消息。PL HELLO／重握手和仅 vendor 接口恢复不重置音源控件，不阻止 MIDI 演奏。没有 VBUS 输入时，物理拔线本身不能等同于已观测的 USB 总线复位；再次枚举的总线复位负责隔离设备端旧消息，138K 负责主机侧即时断开清音。
- PL 心跳超时回本地诊断页面；重新 HELLO 和完整重画恢复主机页。LCD 在途窗口安全结束，MIDI、触摸、灯光不等待画面。

## 背压与容量

`gw138k_panel_performance` 有 64 项离散控制队列及一个稳定输出槽，后面是既有双链路路由和各自编码／USB 队列。未被接受的输出保持消息、时间戳及目标不变；断开的目标从所有待发项删除，不能由重新连接继承。

队列载荷采用八个同步 BSRAM 银行，相邻环形地址分属不同银行；每拍最多六项写入按事件类型进入固定暂存槽，再由每银行的单写口提交。同拍受理项地址连续且互不重复，六项最多各占一个银行，因此写选择可用互斥合并。读端预取下一读地址；队首仍在暂存或刚发生同址写入时，等下一次同步读取完成再出队，不依赖 BSRAM 同址读写结果。空队列首项最多增加两拍等待，已有稳定输出槽及连续有数据时每两拍出队的节拍保持。仅小目标掩码阵列在断开时作废，载荷存储不逐项复位。深度参数要求为不小于 8 的二次幂，生产值保持 64。滑条分段公式在展开时计算成 256 项查表，逐点结果与原整数除法一致，不在运行数据通路生成除法器。

满队列时，尚未入队的连续弯音只保留最新样本、时间戳和原目标，包含只有一次采样的释放回中；恢复空间后排在已入队控制之后发送。离散旋转／短按不合并；超过有限容量时丢弃新离散控制并递增模块内 `control_overflows`，该计数不新增在线协议字段。按键按当前物理状态与已受理持音收敛，释放优先；不承诺无限背压下保留任意多次短促操作。离线测试验证 64 项满队列及路由／编码缓存中的 68 条短按保序，随后一次释放仍发送中心弯音。

内部载荷每项 32 位：13 位原时间戳、4 位 MIDI 通道及 15 位控制编码。弯音保存完整 14 位数据；Program 保存完整 7 位音色；CC 分支保存原数值及 CC7／88／89 的低六位，并恢复这些编号共有的 bit6=bit4 关系。出队重建原 MIDI 消息与长度，USB／BLE 线规不变。仿真对控制类型、CC 编号、长度及数据最高位作断言，后续增加控件需显式扩展编码并重新验证。每个银行只需一个 32 位 SDPB，避免 39 位载荷跨两个 SDPB；综合等效数与 P&R 物理 BSRAM 数仍分别记录。

## 构建与验证

从仓库根目录运行：

```sh
sh projects/25k/example/MIDI_KEYBOARD/run_sim.sh --output /tmp/gw25k-checks-new
sh projects/25k/example/MIDI_KEYBOARD/build.sh --user-code C1251031
```

`--user-code` 必须为新候选选择八位十六进制身份；示例身份属于 2026-10-23 本轮同步 BSRAM 候选，改变发布输入后另选身份。构建优先使用 PATH 中的 `gw_sh` 包装器，也可设置 `GW25K_IDE_DIR`。Linux 安装在用户目录时，先把相应包装器目录加入 PATH。临时目录由系统选择，综合与 P&R 分别启动；ROM 校验、时序门禁、输入哈希和生成位流身份随构建记录保存到新的 `results/build_时间戳/`，不覆盖导入的历史 `reports/last_build.json`。

Flash 固化需要先通过离线门禁，再确认目标 FPGA ID `0x0001281B`、Flash 型号与候选位流 SHA256，写入后校验、重载并读取 UserCode。读不到目标板时保留候选，不写入其他板卡。固化不等于断电冷启动或触摸板至 138K 实际音频／屏幕验收。

BLE 初始化复用既有 32 KiB 补丁 ROM，去除 260 字节寄存器发送缓存。HCI 头及短命令参数按地址生成；补丁按 H5 `host_copy` 每拍递增地址的固定顺序预取，地址 3 取首个补丁字节，地址 4 开始消费。H5 复制不在字节间停顿，UART 背压发生在后面的 pending RAM；不能把该预取接口当作任意随机地址组合读取。HCI 保持命令、长度、分片编号、回显检查、超时及错误 ROM 拒绝语义；原始固件、ROM 深度和哈希校验不变，完整 30,147 字节由真实 UART／H5 模型逐字节核对。

本轮状态和复现证据见 [2026-10-23 报告](../reports/HOST_HOTPLUG_20261023.md)。主机其他入口变化后的完整双向参数同步，以及尚未定稿的 4×4 专有效果上下文与 D 整机接入，继续按根接口规划单独实施，不由面板像素反推参数。
