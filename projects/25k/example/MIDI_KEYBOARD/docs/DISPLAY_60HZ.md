# 60 Hz 动态界面更新

当前显示架构以60 Hz抓取乐器场景快照，只发送发生变化的矩形区域。像素格式仍为RGB565，横屏画布428×142，NV3007原生窗口142×428；默认反向横屏坐标为`logical_x=427-native_y`、`logical_y=native_x`，MADCTL=00、列偏移12。SPI采用50 MHz mode0、MSB先发、RGB565高字节先发。这里的60 Hz指当前界面的动态区域提交节拍，不代表任意全屏像素每秒重写60次，也不代表已测得LCD的TE或实屏刷新频率。

## 场景、区域与一致性

`midi_landscape_display`用相位累加器从50 MHz产生60 Hz节拍。空闲时在节拍上发出`snapshot`，renderer和`midi_display_regions`在同一快照边沿锁存场景。区域比较针对上次snapshot，不跟随实时输入；后续输入变化留到下一场景，传输中不会拼接新旧键、数值或颜色。静态场景仍参与节拍比较，但掩码为0，不发送窗口命令或像素。

`dirty_regions[26:0]`包含一个全屏区域和26个不重叠的动态区域。首次snapshot、主题色或背景色变化仅设置bit0，以全屏重画覆盖所有局部更新。

| 位 | 逻辑像素范围（含端点） | 触发字段 |
| --- | --- | --- |
| 0 | x0..427，y0..141 | 首次snapshot、theme、clear |
| 1 | x168..369，y7..13 | USB、BLE、touch_ready、panic |
| 2..7 | 六卡x8/70/132/194/256/318..各自+57，y29..71 | 各卡对应的SHIFT、CH、VEL、STRIP模式、PROG、LAMP；focus改变时标记旧/新合法卡 |
| 8 | x8..139，y74..80 | S2 ready、touched、raw、filtered、error |
| 9..24 | 第i键x8+23i..27+23i，y82..126，i=0..15 | 对应key_bitmap位 |
| 25 | x384..419，y29..126 | strip_value、slider_mode、focus |
| 26 | x208..297，y133..139 | S2 ready、error、overrun、general_status、sample_count |

focus为6或7时不对应参数卡，focus变化仍保守重画右栏。S2 ready/error参与两行文字颜色，所以同时标记bit8与bit26。区域更新覆盖该矩形的文字、边框和背景，保证旧字形及旧焦点能被擦除。

## 连续SPI与像素预取

`lcd_spi_stream`以Gowin ODDRC输出SCK、MOSI、DC与CS，四者使用相同输出流水。SCK空闲低，上升沿采样；连续有效字节每8个核心时钟接受一次，字节间不插入空闲周期。每个区域先发送MADCTL/INV、CASET、RASET、RAMWR，再发送该区域所有RGB565像素，区域结束后等待物理CS释放。

renderer保留四级流水线：几何区域、字符选择、字模、颜色。扫描器在坐标改变后等待完整四级结果，以四像素FIFO存放已渲染像素；发送旧像素的同时预取后续像素，避免每个像素串行等待renderer。初始化及区域像素使用同一握手字节流，流量不足时SCK停低、CS保持有效；整批结束前不会抓取新场景。

## 时间预算与超时节拍

所有26个动态区域合计35,860像素。以真实50 MHz时钟运行、仅缩短初始化等待的RTL引脚仿真结果为：

| 情形 | 测得时间/行为 |
| --- | --- |
| 连续动态场景的snapshot间隔 | 16.666660或16.666680 ms，平均60 Hz |
| 26动态区域全部变化 | 11.539220 ms，包含窗口命令与传输收尾 |
| 完整428×142重画 | 19.450840 ms，超过一个60 Hz节拍 |
| 场景未变 | 0窗口、0像素、0 SPI传输 |

主题、背景或首次全屏重画在下一tick到来时仍可能忙。扫描器继续发送原快照的完整批次，每错过一个tick使`overrun_count`加1；完成后等下一tick再发snapshot。`completed_refreshes`计完成的场景批次，包含无需传输的静态场景；它不是实屏扫描帧计数。该策略保持场景数据一致，不保证长全屏重画期间无撕裂，因为当前不使用TE同步。

RGB565全屏像素每帧为`428×142×16=972,416 bit`，60 fps至少需要58,344,960 bit/s，尚未计窗口命令及收尾。50 MHz单线SPI仅像素传输的理论上限约51.42全屏fps；实际批次还含协议和调度开销。NV3007的PFSET=05/06分别对应16/18位格式，没有RGB444选项，不能以未支持的12位格式绕过带宽约束。

## 验证范围

`tb_midi_display_regions`以独立区域掩码校验每个场景字段、16键逐位变化、64种focus旧/新组合、首次/主题/背景全屏重画、无snapshot时输出保持及实时输入瞬态不污染比较。

`tb_midi_landscape_display`解码模拟物理SPI引脚，覆盖55个窗口、194,172个精确RGB565像素、全部动态区域、两个全屏批次、静态零传输、四级像素流水与场景快照一致性；验证60 Hz节拍以及全屏批次超时计数。上述测时来自这套RTL仿真，最终整机回归、构建、时序与烧录身份集中见 [BUILD_VALIDATION.md](BUILD_VALIDATION.md) 和 [FLASH_PROGRAMMING.md](FLASH_PROGRAMMING.md)。

50 MHz SCK的名义周期为20 ns，MOSI在采样沿前后的名义setup/hold各10 ns，恰为手册最低要求。理想ODDRC引脚模型验证逻辑边沿关系；FPGA STA验证其约束覆盖的芯片内部路径。二者都不包含本板走线、连接器、负载、探头和LCD实际输入时序，不能据此认定板级SPI已经获得裕量或TE同步已经验证。实板仍需观察SCK/MOSI/DC/CS波形、颜色、方向及持续更新效果，再记录外部时序和TE测量。
