# 触摸与灯光驱动

本次已把新增参考 ZIP 派生为可接入 MIDI 主工程的实际外设 RTL，参考原件完整保存在 `vendor/qt2160_reference/`，没有修改原件。板级线路依据 `TOUCH_INTERFACE.md`：I²C1 / U1 为 16 键，I²C2 / U2 为滑条，两者各自独立使用地址 `0x0D`；I²C3 / U3 为 `0x40` PCA9685；WS2812 为另一组 16 颗串联 RGB 灯。参考 ZIP 的第一/第二颗编号不能覆盖此板级映射。

## 接口与复位

所有模块使用 `clk` 和同步高有效 `reset`；复位清除内部状态，I²C 输出释放为高阻，WS 输出保持低电平。默认 `CLK_HZ=50_000_000`。没有 FPGA 可控的 QT2160 硬件复位管脚，软件配置/校准通过 I²C 完成。

| 模块 | 主要接口 | 行为 |
| --- | --- | --- |
| `midi_touch_frontend` | `change_n`；双向 `touch1_scl/sda`、`touch2_scl/sda`；`key_bitmap[15:0]`、`key_update`；`slider_position[7:0]`、`slider_touch`、`slider_valid`；`keypad_ready`、`slider_ready`、`errors[15:0]`；`slider_raw_position[7:0]`、`slider_general_status[7:0]`、`slider_overrun`、`slider_sample_count[7:0]` | `key_update` / `slider_valid` 是单周期完整快照脉冲，按键为QT原始位序、滑条经过位置滤波。两颗芯片并行执行。就绪电平在完成配置、校准和首个有效采样后置位。 |
| `midi_key_layout` | `raw_keys[15:0]`、`key_bitmap[15:0]` | 顶层把QT原始键快照重排为A=bit0..P=bit15；无额外状态或延迟。 |
| `pca9685_led_driver` | 双向 `scl/sda`；`led_bitmap[15:0]`、`brightness[7:0]`；`ready`、`errors[15:0]` | 滑条区域16路LED，顶层由滑条位置生成条形bitmap，亮度0..255。 |
| `midi_ws2812` | `key_bitmap[15:0]`、`brightness[7:0]`；`data_out` | 一颗灯对应一位键状态，按位置区分颜色，未按键为灭，每帧固定快照。 |
| `midi_i2c_register_master` | `request`、`read_request`、寄存器地址、字节数和低字节在前的数据；开漏控制 `scl_low/sda_low` | 单主机的寄存器事务引擎，默认最多 16 字节，可参数化为 PCA9685 的 64 字节。`busy=0` 时接收单周期 `request`，`done` 为单周期；忙时不接受新请求。 |

`key_bitmap` 是全部按下状态，不是仅按下事件。上层必须比较新旧快照产生 Note On / Note Off。I²C 错误、配置不匹配或运行期设备 RESET 会立即撤销该设备的 ready，并发出一次 `key_bitmap=0` 或 `slider_touch=0` 的快照，供上层释放音符/控制器；错误帧不会构造新的按下。滑条故障时位置保留最后读数，但 `slider_touch=0` 且 `slider_ready=0`，上层应以这两者判断有效性。按键没有真实力度传感器，固定力度由 MIDI 上层决定。

## QT2160 配置与低延迟采样

配置流程来自已提供的参考程序，并针对实板过于灵敏的反馈调整阈值与滤波。上电等待默认100 ms；芯片ID检查（寄存器0=`0x11`）通过后，先在`RESET_BASELINE`阶段读取状态，清除旧的上电RESET标记，再写入配置、逐项读回核对、写寄存器10触发校准并等待默认500 ms。配置之后不再豁免首帧：首个采样或运行期采样只要再次出现寄存器2 bit7，就立即报`07`、撤销ready、发布释放并重新识别/配置，避免校准等待期间复位却沿用已丢失的配置。

键盘配置：LP/BREP（寄存器12/13）为`01/01`，两项均写入并读回；NDIL（17）为1；滑条控制（20）关闭；AKS（22..37）清零；负阈值NTHR（38..53）为12；突发长度BL（54..69）为4。十六键状态使用寄存器3、4。按键仍须在帧前、帧后状态中都按下，且参考值不小于信号值；新按要求`reference-signal >= 12`，已按键保持要求`>= 10`。因此新按差值11不通过，已按差值10仍保持，降至9释放；负差不会无符号回绕成误触。相比旧版不区分新按/保持的差值≥8，现有迟滞减少边界反复触发，效果仍需实板调试确认。

2026-11-02按键NDIL从7降为1，以减少触摸到灯亮之前的芯片检测积分等待。QT2160手册6.14规定NDIL合法范围1–31，实际连续采集次数为NDIL+1，因此取消原连续8次配置后仍保留芯片最低2次确认，不能将0当作禁用积分。正常16 ms扫描下，积分预算由约128 ms降至32 ms，理论减少约96 ms；首次触摸内部数字滤波、轮询相位、I²C读取和灯带锁存仍有额外延迟，这不是实板测量值。逐帧前后状态复核、差值门限、迟滞、故障释放和滑条配置保持；这些过滤不等同于原8次连续抗扰能力，实际延迟和误触率须重新验收，历史板测结论不继承。本次未下载SRAM或写Flash。

不同于原程序固定 200 ms 的 UART 输出节拍，新驱动每次扫描按以下顺序完整提交：

1. 从寄存器 2 读取 5 字节状态。
2. 块读信号寄存器 100..115、116..131，各 16 字节。
3. 块读参考寄存器 132..147、148..163，各 16 字节。
4. 再读状态并计算完整 16 位快照，一次提交。

默认100 kHz I²C，四次块读加前后状态约占10 ms总线时间。此前5 ms轮询及共享`CHANGE12`持续为低时的立即重读，可能使滑条反复确认同一轮检测结果；当前改为从一次采样开始到下一次采样开始计时：默认`POLL_CYCLES=20 ms`，`MIN_SCAN_CYCLES=16 ms`。CHANGE低有效且经两级同步，只能把下一次采样提前至16 ms下限；CHANGE为高时按20 ms轮询。两路总线分别计时，共享CHANGE持续为低也不能绕过最小间隔。I²C事务本身尚未结束时不重叠启动。

采用块读将原逐键32次信号/参考事务缩短为4次，没有继承UART的200 ms输出限速。这里描述FPGA读出调度，不是触摸ASIC检测积分、MIDI/USB或实板整体延迟的实测；前后状态与信号/参考数据也不是ASIC保证的原子快照。

滑条配置：LP/BREP（12/13）为`01/01`，均写入并读回；NDIL（17）为3；寄存器20=`0x28`，21=`0x00`（8位位置）；22..29的八个Y0电极加入AKS组1；38..45阈值NTHR为12；54..61突发长度BL为8，其余八键突发为0。采样为同一笔5字节状态读，位置在寄存器5，触摸标志为寄存器2 bit0。方向由PCB物理电极映射决定。

`midi_slider_filter`对8位位置增加3 counts死区：与已接受位置的差值<3时保持位置，差值3..32的正常移动直接接受；差值>32时暂存候选，需连续两次I²C读样的候选位置相差不超过±3才接受。失触或故障立即提交`slider_touch=0`并保留末位置，不等待跳变确认。MOD/EXPR在应用层保持末值，BEND由应用层在松手时回中；滤波不把失触变成继续触摸。这些滤波边界已在此前基线中通过RTL回归并烧入；首次触摸、快速扫条和实际抖动效果仍需实板记录。

这里确认的是连续两次I²C成功读样。新增16 ms最小起始间隔针对LP=1约16 ms扫描节拍，减少重复读取同一检测结果，但芯片没有随数据返回可核对的扫描epoch；不能保证两次读样一定来自两个不同的ASIC扫描周期，也不能据此保证拒绝单扫描噪声。还须以本板原始位置、触摸状态和快速扫条记录评估效果。

当前键盘和滑条参数在`midi_touch_frontend`中分别以`KEY_*`、`SLIDER_*`编译期参数暴露：`NEGATIVE_THRESHOLD`、`DETECT_INTEGRATOR`、`BURST_LENGTH`。提高NTHR会要求更大的电容差值；NDIL是芯片检测积分设置，调整时须同时观察抗扰和延迟；BL需结合电极、覆层和扫描表现调试。这些参数须重新构建、烧录才生效，当前USB屏幕控制协议不提供运行时灵敏度设置。此前完整键序、独立参数及滤波已随`0x00006712`基线完成回归、构建、Flash校验和重载。本轮节拍、RESET和诊断新增修改的回归/构建/烧录状态集中见 [BUILD_VALIDATION.md](BUILD_VALIDATION.md) 与 [FLASH_PROGRAMMING.md](FLASH_PROGRAMMING.md)；实际抗扰效果尚未实测验收。

完整物理键映射为A–P对应原始0基位`5 3 1 7 13 11 9 15 4 2 0 6 12 10 8 14`。该映射位于顶层原始快照之后，不参与电容阈值判断，详情见 [KEY_ORDER_AUDIT.md](KEY_ORDER_AUDIT.md)。

## 滑条芯片独立诊断

U2已单独配置为8电极滑块模式：寄存器20=`0x28`，寄存器21=`0x00`，并读回验证。无需因为屏幕没有位置变化而再次切换模式；应先根据独立诊断区分初始化、触摸识别、数据与滤波问题。顶层已将U2的实际诊断信号接入屏幕，全部字段随帧snapshot锁存：

| 屏幕字段 | 来源与含义 |
| --- | --- |
| `S2 R1 T0` | `R`为滑条ready；`T`为经过位置滤波器的触摸标志，失触/故障立即释放 |
| `RAW128 POS128` | `RAW`为最近成功读取的寄存器5原始位置；`POS`为滤波后位置，均为三位十进制 |
| `G02` | `G`为实际寄存器2 General Status的十六进制值；bit0=SDET，bit1=CC，bit6=CYCLE OVERRUN，bit7=RESET。`G02`的CC位为正常状态，不是错误码 |
| `E00` | 当前滑条错误码，即`errors[15:8]`；含义见下表，成功有效采样后清零 |
| `OV0` | 从成功状态读取中看到过bit6即锁存1，直到FPGA reset清零；重新配置和恢复采样不会擦除历史 |
| `N7F` | 成功完整采样次数，8位十六进制循环计数，`FF`后回`00`；错误发布的释放快照不计入 |

`G`在成功状态读时更新，包含使采样失效的RESET；I²C故障保留最后一次成功读取的状态，不从错误码推造General Status。`N`增长说明读出路径持续工作，不证明手指触摸已被正确识别。原始位置变化而`POS`稳定可检查死区/跳变确认；`G`长期不含SDET且`RAW`不变时应继续核对电极、阈值与校准，不能从ready单独推断滑动响应正常。

## I²C 事务、故障恢复和错误码

SCL、SDA 只驱动 0 或高阻，使用子板的 4.7 kΩ 上拉。默认半周期 250 个 50 MHz 时钟，约 100 kHz；读取管脚经两级同步，并等待时钟拉伸。寄存器读沿用参考芯片要求的“写地址/寄存器 → STOP → 总线空闲 → START/读地址”，总线空闲默认 100 µs。每个地址、寄存器及数据字节都检查 ACK，读最后一个字节由主机发 NACK。

拉伸超时默认 20 ms。START 前总线一直忙时，驱动发出 9 个恢复时钟并尝试 STOP，再以错误结束当前事务；上层等待后重新识别和初始化。SCL 被外部永久拉低时恢复也受超时限制，释放主机输出并持续重试，不会无限停在 busy。各总线互相独立，触摸或灯光错误不会阻塞 MIDI 传输。

| 错误值 | 含义 |
| --- | --- |
| `00` | 最近一轮已成功；重新配置/有效采样后清除故障 |
| `01` / `02` / `03` / `05` | 写地址 / 寄存器地址 / 读地址 / 数据字节 NACK |
| `04` | QT2160 ID 不符 |
| `06` | QT2160 配置回读不符 |
| `07` | QT2160 运行期 RESET 标记 |
| `40` | START 前总线忙超时，已经尝试 9 时钟恢复 |
| `80` | SCL 拉伸超时 |
| `FF` | 非法事务长度或状态 |

触摸 `errors[7:0]` 为键盘，`errors[15:8]` 为滑条；PCA9685 的低字节为上述总线错误，高字节保留 0。错误是最近故障状态，不是累计次数。

## PCA9685 初始化和完整 PWM 帧

用户确认此组LED位于滑条区域。顶层将应用`strip_value`经`midi_slider_led_map`转换为连续亮起的0..16段：0全灭，128前8路，255全16路；`slider_ready=0`时全灭。MOD/EXPR松手保持，BEND松手回中，LAMP仍控制亮度。WS2812按键状态不再送入PCA。

真实线上地址为写 `0x80`（7 位 `0x40`）。初始化顺序为 MODE1=`0x30`（AI + SLEEP）→ MODE2=`0x04`（非反相、OUTDRV 推挽、OCH=0）→ PRE_SCALE=30 → MODE1=`0x20` 唤醒 → 等待至少 500 µs → MODE1=`0xA0` 重启。默认目标 `PWM_HZ=200`，按 25 MHz 内部振荡器计算的标称实际频率约 196.9 Hz，实物振荡器有自身误差。

普通 LED 阴极接地，因此输出高时点亮，MODE2 必须源电流，不能套用常见阴极驱动板的反相/开漏设置。亮度 0 使用 FULL_OFF，255 使用 FULL_ON，中间值扩展为 12 位占空比。驱动先锁存LED条形状态和亮度，再从 LED0_ON_L (`0x06`) 连续 AI 写入 **64 字节**；OCH=0 使全部 16 路在同一个 STOP 更新。输入在发帧过程中变化会触发下一完整帧，不混用新旧亮度。默认 50 ms 定期刷新，变化时立即安排新帧；NACK/超时会撤销 ready 并重新执行上述初始化。

图纸表明普通 LED 阴极接地及存在串联限流器件，但每路限流电阻数值、LED 正向压降/额定电流仍须对照装配 BOM。驱动亮度是 PWM 占空比控制，不能替代限流电阻。PCA9685 与 WS2812 两组灯共用 TC_3V3，尚未实测供电、压降、温升和满亮电流。

## WS2812 波形

16 颗按 GRB 顺序、每色 MSB 先发，共 384 位；输入逻辑位按A=0..P=15，实际从DIN第一颗起按用户确认的`ABCDHGFEIJKLPONM`链序转换，颜色跟随逻辑键。完整QT原始通道映射已由用户确认并经`midi_key_layout`转换，WS链序不随原始通道表改变，见 [KEY_ORDER_AUDIT.md](KEY_ORDER_AUDIT.md)。16 位键状态和亮度仅在帧边界锁存。默认 50 MHz 时采用交替 62/63 个时钟的位周期（1240/1260 ns），平均准确 800 kbit/s；0 高电平 17 时钟=340 ns，1 高电平 42 时钟=840 ns；帧之间保持至少 300 µs 低电平。上电/复位也先输出完整低电平复位间隔。数据输出和 I²C/MIDI 无相互等待。

`CLK_HZ` 应填写实际工作时钟，纳秒数参数可按装配料号手册覆写；当前测试验证的是 RTL 的引脚时序和编码。实板仍须确认具体 WS2812B-2427-V6 在图中 3.3 V 供电下的电压范围、DIN 门限、连线波形与料号手册时序，没有用仿真替代电气验证。
