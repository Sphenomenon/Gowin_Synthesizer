## 决策与边界

完整触摸＋弹拨单个位流经资源优化仍为23664逻辑，超过GW5A-25K的23040限制，未产生可部署位流。用户随后提出分别提供触摸、弹拨两套代码。本轮采用**同一版本化工程、两个显式构建配置、两份不同身份位流**，不复制完整项目，不再继续大改BLE以强塞双前端。失败记录保留在[合并实验报告](PLUCK_INTEGRATION_20261101.md)。

两版均是原25K完整交互适配器，不是临时USB诊断探针。只裁去另一个附件前端：

弹拨附件没有触摸条输入，PCA保持无有效条位置；这不新增CHN6控制映射。弹拨板自身WS2812仍固定低，未虚构此前没有实现的灯效。电脑HS能力不代表138K端支持HS；不修改138K源码或USB线规。

## 构建与使用

从仓库根目录：

```sh
sh projects/25k/example/MIDI_KEYBOARD/build.sh --input-panel touch --user-code C125C201 --opt-goal area --replicate-resources 0
sh projects/25k/example/MIDI_KEYBOARD/build.sh --input-panel pluck --user-code C125D201 --opt-goal area --replicate-resources 0
```

不传`--input-panel`仍为触摸版；`--pluck`是完整弹拨版的兼容别名，不再生成触摸／弹拨自动选择位流。`--pluck-probe`仍是独立临时诊断配置，不能与附件配置组合。脚本在启动工具前拒绝冲突参数，新的候选身份不可用于不同发布输入。

换附件需断电接线，并另行授权加载匹配固件；没有运行时自动切换／双附件并行承诺。弹拨完整版在ADC正常BUSY握手后自动给五路50%PWM：CHN1–5依次1660、3400、6970、1000、4860Hz，无需电脑GUI续租；启动／0x05重校准时保持无遮挡约1.1秒。ADC故障释放门控并关闭PWM。临时探针仍默认OFF／两秒人工租约，不能用探针专属0x04控制完整版。

CHN1–5进入同一原演奏器，暂用A–E即48–52加原移调；On100／Off0、通道、USB／BLE清理规则不变。25kHz双串行读法、两毫秒Vpp窗口及载波下降迟滞保持已通过用户操作反馈的算法语义；串行共享引擎和完整版集成仍需新的板测，不能继承C125B101整机验收。
