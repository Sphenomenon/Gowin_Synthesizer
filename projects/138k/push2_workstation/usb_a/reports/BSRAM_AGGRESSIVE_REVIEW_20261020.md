**TASLP 接入边界与整机 BSRAM 激进优化评估**

日期：2026-10-20。仅做源码、历史记录与已布线网表审查；没有实现 TASLP，没有裁剪功能，没有修改 RTL、重编译固件、综合候选或访问板卡。

**后续约束更新：** 用户确认后续自有板采用 High-Speed USB，见[指引帧率与 HS 内存修订](CNN_GUIDANCE_RATE_USB_HS_20261020.md)。本文 45 块第一轮目标保留为旧 FS 条件下的候选；USB CPU RAM 缩容的 16 块先移出优先预算，其余五项约 29 块待验证。HS 包缓存及最终固件另行核算。

**结论**

1. TASLP10 是钢琴模型。当前工程尚未接入，五种音色仍使用 DDS 加法音源。若先做“钢琴专项接入”，钢琴走模态模型，另四种仍走旧 DDS。这里的 DDS 查询正弦函数，并按分音频率／幅度叠加，不是整段乐器采样回放。
2. 模态求解器可作为另一种打击类音色的计算核心，但琴槌、弦、音板参数不会自动变成笛、弓弦或铜管。若最终只保留钢琴和马林巴／钟类，可考虑统一模态核心并整体移除旧 DDS；需要先完成第二音色的建模和验收。取消 A/B 本身不释放旧 DDS 的 22 块。
3. 先以不降低音频字长、不减少复音、不删除主要功能为目标，争取释放约 45 块：USB RAM 16、寄存器堆 4、CNN 特征缓存重排 12、HDMI 行缓存 8、录音 FIFO 3、曲谱缓存 2。**45 是六项候选全部成立时的目标，不是已综合成果**。
4. 进一步做 CNN 分块计算、较深的存储串行化、降低 XY 点阵分辨率，并移除 chorus，可以提出约 60–80 块的激进目标。不能与第一轮 45 块直接相加，其中多项改同一存储。
5. 建议先释放这些空间，再接钢琴 TASLP。无需一开始就因容量压力放弃现有其余四种音色。是否最终裁掉它们，是音色产品选择。

**统计边界与已布线账本**

基准为完整整机 `results/timing_p27_uart_cdc_route1_20261018_142516_456857/Prj1`；它是已保存的布线快照，不是当前运行板卡的查询结果，也不代表之后未综合的活动源码。其 BSRAM 为 262/340，DSP 157.5/298，CLS 54862/69120（约 79.4%）。只按这一份 PNR 物理原语计数，不与综合阶段块当量相减。

重新统计所有 SDPB、SDPX9B、pROM、pROMX9，得到 199+19+35+9=262，与同目录 PNR 报告完全一致。此前只统计 RAM 原语的脚本结果不能代表整机全部 BSRAM。

|---|---:|---|
| 音频及音频扩展 `u_managed` | 60 | DDS 22，矢量音源 12，chorus 4，reverb 8，录音 FIFO 6，LED 曲谱 4，其余 ROM 4 |
| HDMI／分析显示 `u_video` | 58 | 分析 30，renderer 其他 6，scanout 16，data_reader 6 |
| 音乐识别 `u_music` | 54 | 特征缓存 32，权重缓存 8，平面缓存 2，管线缓冲 3，Viterbi 9 |
| USB Host `u_usb_host` | 36 | VexRiscv 共用代码／数据 RAM 32，寄存器堆双读副本 4 |

历史审计把 USB 的 32+4 描述成“端点 RAM＋程序存储”，归属不准确。`iosys2.v` 实际是 64 KiB 共用程序／数据 RAM；网表另四块属于 `RegFilePlugin_regFile`。源文件顶部“128KB”注释也与实际数组不符，以数组和网表为准。

**已经实施了哪些节省**

- **长 delay 已迁 DDR，真实释放 64 块。** full79→full80 的完整 PNR 从 279 降到 215。音频侧两条异步 FIFO 映射到分布式 RAM，因此没有重新占 BSRAM。历史报告有 45000 样本逐位等价与用户板上听感验收。这一收益已经包含在当前 262 中，不能再次相减。它仍占分布式 RAM、复用与跨域逻辑，不是零资源。
- **CNN 的大部分长期存储已在 DDR。** 包括模型后备、特征后备、CQT 信号／系数、NormLog 平面和 DP 历史等。单一 DDR 控制器与统一仲裁已实现，并没有两份重复控制器可删。
- **CNN 后来为吞吐加回了 45 块。** 全 DDR 逐 MAC 读取权重及激活，每个 256-bit burst 只取一个 16-bit 半字，历史记录约 0.37 帧/s。full81→full82/83 由 215 增到 260，新增特征 32、权重 8、平面 2、管线缓冲 3；本次快照为 262。约 18 倍加速是当时的解析预期，不能当成完整板测吞吐结果。重新省缓存应改批量装载与计算调度，不能简单恢复该慢路径。
- **TF 的长音频后备和 HDMI 帧缓冲使用 DDR。** TF 子树仍需 5 块片内桥接与文件名存储；HDMI 已经不是把 1080p 完整帧塞片内，但分析、双行缓存和局部缓存仍有 58 块。
- **现有 DDS 已分时共享。** A/B/C 共用引擎和 RAM，不能把取消 A/B 解释为删掉两套独立硬件。这主要节约算术硬件，不能另记成待释放的大笔 BSRAM。

**第一轮：保留音色和主要功能，目标 45 块**

| 候选 | 当前块数→目标 | 预计释放 | 依据与必要验证 |
|---|---:|---:|---|
| USB 共用 RAM 64→32 KiB | 32→16 | 16 | 本快照固件二进制 19288 B，代码＋数据＋BSS 合计 25003 B，静态末地址 25004；32 KiB 尚余 7764 B 给栈／运行余量。先做编译栈分析与栈高水位、USB 热插拔／异常描述符测试；同步修改链接、启动 SP、RAM 深度、地址越界处理及固件填充脚本 |
| VexRiscv 寄存器堆改分布式 RAM／寄存器 | 4→0 | 4 | 每个逻辑副本仅 32×32 bit，两个读端口造成副本；每份又拆成两片 16-bit BSRAM。保留读延迟、写后读转发、x0 与 CPU 时序；不能只删属性就宣称实现 |
| CNN 特征缓存显式分 bank | 32→20 | 12 | 7×88×32=19712 个 16-bit 词，即 38.5 KiB。当前网表为 1-bit 宽、两段深度、共 32 块；20 个 1024×16 bank 容量足够。保留单写单读协议、地址边界、零填充及一拍读语义；新增输出选择必须满足时序 |
| HDMI 双行 RAM 用 32-bit SDP／非对称端口 | 16→8 | 8 | 256×256 bit 共 8 KiB，当前分为 16 个 16-bit 原语，宽而浅。八个 32-bit 写／读片足以维持 256-bit 宽字；也可改 DDR 宽写、像素窄读，保留两行和跨域所有权。需验证目标器件合法映射、读延迟、消隐及欠载 |
| 录音 FIFO 显式 32-bit SDP | 6→3 | 3 | 256×96 bit 共 3 KiB，改为三片 32-bit。保持序列号、丢样可检测、满队列同时读写与转发语义 |
| LED 曲谱缓存显式 32-bit SDP | 4→2 | 2 | 256×64 bit 共 2 KiB，两片 32-bit；保留 256 个 cue、32-bit 时间和 32-bit LED mask，不删除指引 |
| 合计 | **262→217** | **45** | 均未实施／未重新综合 |

Gowin UG285 给出的 SDP 存储模式包含 1024×16、512×32，以及独立读写宽度。上述行缓存、录音、曲谱的收益是使用更宽 SDP 映射的设计目标；当前综合自动推导没有选到这一配置，不能假定只改 RTL 数组类型就会得到目标。必须针对本器件做小模块映射与完整整机 PNR 复核。

64→32 KiB 是这里唯一明显减少运行余量的项目。若栈不够，先用 48 KiB 释放约 8 块，或压缩固件静态缓冲，不能让 RAM 地址静默回绕。除这一容量取舍外，其余五项的设计意图均为保留数据、精度与队列深度，但读写碰撞处理和额外选择器仍可能改变时序，需实际验证。

**第二轮：目标约 60–80 块，接受更大架构调整**

以下为一套互不重复相加的方案；特征缓存、scanout 等替代第一轮同项收益。

| 项目 | 相对当前预计释放 | 实际代价 |
|---|---:|---|
| USB RAM 缩到 32 KiB | 16 | 栈与固件运行余量必须实测 |
| 寄存器堆移出 BSRAM | 4 | 增加少量逻辑及读端口选择 |
| CNN 按频率／通道 tile 计算，特征缓存 32→8–16 | 16–24 | 重排卷积循环，带 halo 装载，保证全层逐位相同；小 tile 会重复读邻域，吞吐需核算 |
| 权重按输出通道组装载，8→2–4 | 4–6 | 与 tile 卷积绑定，利用 256-bit burst 的多个半字；不能退回逐 MAC DDR 访问 |
| HDMI 行缓冲压到 4–8 | 8–12 | 八片 32-bit 是第一步；更低目标需将 256-bit 响应拆拍写较窄 bank，并验证行时限及跨域地址映射 |
| 录音 FIFO 压到 2–3 | 3–4 | 更低目标需将 96-bit packet 串行存成多个 32-bit 词，并保持主机出口语义 |
| 曲谱缓存压到 1–2 | 2–3 | 一片目标需串行访问两个 32-bit 字，事件预取到寄存器 |
| XY 点阵从 256×256 双 bank 改为 128×128 双 bank | 6 | 位图 16 KiB→4 KiB，8→2 块；点阵分辨率下降，可仍缩放到相同屏幕区域 |
| 构建时移除 chorus | 4 | 失去合唱效果；钢琴同音弦拍频需由音源提供，二者不等同 |
| 合计 | **63–79** | 整机容量目标 **183–199**；尚未实施 |

第一轮 45 块与第二轮 63–79 块是两个方案，不相加。XY 分辨率下降是这组方案明确的显示质量取舍，chorus 移除是明确的功能取舍；CNN tile 只调整调度，目标是保持数值结果，但性能必须另验。

还可继续探索：

- 正弦 ROM 四分之一波对称复用。当前正弦插值共 6 块，目标 2–4，预计省 2–4。需保留双相邻样本读取、象限边界、符号和插值精度。小音高／音色参数表可改逻辑或合并，另有少量收益，未列入总数。
- FFT 显示从 2048 降到 1024，可能再省约 6–10 块，但 48 kHz 时频率格距从 23.4375 变成 46.875 Hz，影响低音与相邻音的展示，未列入优先方案。先优化存储映射，保留可用于比赛证据的频谱能力。
- AE350 启动存储 16 块：精简启动 ROM、把非关键代码／数据迁 DDR，可能省约 4–8。当前启动 ROM 分配 16 KiB，最后非零字到约 10832 B，不能直接砍成 8 KiB；需要链接与启动链路调整。彻底移除 AE350 可望移除该 16 块子树，但必须先接替其显示／控制／启动职责，属于系统重构。
- 矢量音源占 12 块，若产品允许整体移除可回收其存储，但它是独立声音生成能力，不能把“删矢量音源”描述成只改 XY 显示。先保留并优化表复用更合理。

**更大胆的产品方案：演奏和分析采用不同镜像**

若比赛展示允许放弃运行时 AI 扒谱，可制作以演奏为主的构建，把 `u_music` 的 54 块整体移出；LED 曲谱仍可读取预生成事件，TF 播放和 MIDI 实时演奏也可独立保留。当前这些功能如何组合需重新验证，不能把关闭 UI 当成释放硬件，也不能宣称两个镜像的功能可以同时运行。

按当前子树粗算，移除识别 54 与 chorus 4，262→204；保留旧 DDS，再加模态核心 40–60、将旧混响换成空间模型的净增 8–12，约为 252–276。该方案的收益大于只删 A/B，但代价是运行时自动识别功能；此处只列选项，没有执行删除。

不要以“两个 CPU 都有 RAM”为由直接合并两份存储，也不要删共享 DDR 控制器的 32 块。它们有实际端口、时钟、职责及吞吐约束；当前并无重复 DDR 控制器。把所有缓存改 LUT RAM 也不适合：CLS 已接近 80%，可能用另一种紧张资源换掉 BSRAM，并加重布线。

**TASLP 核心本身怎样避免继续堆 BSRAM**

- 主模态按活动声部池分配，避免给全部 88 键都常驻一套最大的主模态状态。主声部可以是 32；要保留全键交感共鸣，仍需覆盖未按键的少量次级模态，不能把仅更新活动键称作完整交感模型。
- 低、中、高键采用不同模态数，按照截止频率与听觉误差决定，避免每键一律分配同样上限。分配改变要与最坏吞吐预算一起设计。
- 一架琴共享音板，房间共享空间尾音；不为每个声部复制音板和长混响。
- 预设保存每键基本物理参数，生成／装入当前需要的系数，或者从 DDR／Flash 批量预取。避免每套预设常驻 `88×64×4×27 bit` 的完整主模态 ROM；这额外约 74.25 KiB，按 18 Kibit 理想容量也要约 33 块，实际 bank 映射还可能更多。
- 已装载的实时反馈状态与活动系数放片内；不要让每次 SOS 更新都依赖 DDR 单词事务。一次多取、分 bank、按流水端口需要布局。
- 不优先压低音直接二阶系数到 18 bit。前一份评估对 27.5 Hz 极点的直接量化示例已出现明显音高偏差；那不是所有滤波器形式的通用结论，但足以否决未经误差验证的直接截位。先省空洞和冗余，再评估增益、输入等参数量化；状态和极点精度需单独验证。

前一份 TASLP 40–60 BSRAM 是降阶设计预算，含主模态、全键少量次级库和共享音板，不含额外完整全键系数 ROM，也不含新房间模型。不能把完整论文实现规模与这个降阶预算混为一谈。

**推荐路线与容量目标**

先做寄存器堆、特征缓存 bank 和浅宽 RAM 的小模块映射验证，再按栈峰值决定 USB 32 KiB；合计目标 45 块。保留五种旧音色，用钢琴 TASLP 做同条件干声对比。chorus 可在钢琴演示构建移除，3D 混响后置。

若上述六项实现目标兑现：262−45−4=213；保留旧 DDS 新增模态 40–60，再以 16–20 块空间模型替换当前 8 块混响，容量预算为 **261–285/340**。这比此前未先优化整机时的混合音源预算 306–330 留出更多余量。全部只是沿层级归属相加减的候选预算，须完整 PNR；新增音源、片上端口、逻辑布局和音频时序仍是独立约束。

完成钢琴后，再决定保留现有笛／弦／铜管，还是让一个模态求解器承担钢琴与马林巴／钟类并整体回收旧 DDS 22 块。后者是精简产品的长期选项，不能在其他音色仍走旧 DDS 时提前减去这 22 块。
