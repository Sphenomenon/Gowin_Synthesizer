# 138K 控制与装配边界重整（2026-10-21）

## 1. 范围与状态

本轮不是复制整机或改写 DSP，而是把资源时序开发候选的组合根、会话控制、公共参数、播放服务及最终音频观察点归位。维护入口是 [原生装配说明](../rtl/workstation/README.md)，整体约束见 [架构文档](../../../../../docs/architecture/README.md)。

**源码重整、定向验证及新候选离线门禁已完成；`0xC110210A` 已 SRAM 下载、读回及核心 smoke，不是完整硬件发布。** 本轮用户授权修改、验证、综合和上板；实际操作收敛为 SRAM 下载及读回，不写 Flash。离线门禁未通过的位流不下载。最差 setup 仅 9 ps，SRAM 后自动启动标志也单独列为未完成的硬件验收项。

阶段 A 的基线输入闭包与本轮运行边界重整是两批不同证据。阶段 A 的 prepare 逐字节一致结论见 [来源闭包报告](SOURCE_CLOSURE_20261021.md)；本轮有意改变第一方 RTL，不能继续声称整个输入集与 T24 相同。

## 2. 责任与装配关系

```text
USB/CPU/MIDI 适配
    → 既有仲裁与 FIFO
    → workstation_session：生命周期、初始化屏障、事件寄存器
    → gw138k_event_workstation：实时事件执行、音符/延音、声部与帧调度
        → workstation_parameters：公共参数唯一应用点
        → 合成/矢量引擎 → 既有效果链 → workstation_frame_delivery → 合成串行 DAC

选曲/模型/拔卡状态
    → workstation_playback_service：排队、取消、等待与恢复
    → 既有 TF/识别读取链 → 独立 TF 串行 DAC

合成 DAC + TF DAC
    → workstation_output_router：安全选择、引脚与最终输出 tap
    → 组合根保留的 CDC → 共享显示
```

| 维护边界 | 唯一职责 | 不放入此处的行为 |
|---|---|---|
| `rtl/workstation/gw138k_push_workstation_top.v` | 时钟、复位、引脚、CDC、就绪及组件连接 | TF/识别播放恢复业务状态机 |
| `rtl/control/workstation_session.sv` | 生命周期优先、旧事件作废、13 条初始化默认事件、真实模式提交屏障 | 音频渲染或另一套参数状态 |
| `rtl/control/workstation_parameters.sv` | 已接受命令的音量/表情/模式请求/音色/效果/矢量/TF/面板应用点 | held/deferred 音符表或显示端权威副本 |
| `rtl/audio/gw138k_event_workstation.sv` | 实时接受、音符与延音释放、声部、帧汇合、deadline | 再新增一套公共 CC 参数分支 |
| `rtl/services/workstation_playback_service.sv` | 模型等待、选曲排队、取消、拔卡恢复和超时 | 音频采样节拍或串行 DAC |
| `rtl/audio/workstation_frame_delivery.sv` | 取消的显式零帧、一次性交付、迟到结果丢弃和异常重复统计 | 第二套 PANIC/参数权威状态或掩盖普通渲染缺帧 |
| `rtl/audio/workstation_output_router.sv` | 串行输出选择、最终 PCM 与 128-bit tap | 新的效果作用范围或未实现的通用录音后端 |

保留 18-bit 事件、原有 CC/MMIO/USB PL/BLE 契约及 PANIC 语义。没有凭空增加 source/session/revision 字段。实际模式仍由声部引擎提交；参数模块只拥有请求和 pending。显示与面板观察投影，不成为第二个写入权威。

合成/矢量沿用合成效果与录音支路；TF 仍独立，未冒充“TF 已经过所有效果、可从现有录音点完整录制”。最终 tap 的高低位依次是 PCM32、触发参考32、声部掩码32、合成健康字32；TF 被选中时参考和声部掩码为零。健康字不等于 TF 全链路健康。

## 3. 构建来源与失败行为

- `tools/workstation_composition.py` 静态选择九份第一方文件，验证编译启用次数、目标路径与内容哈希。三份 native 装配文件不再由字符串补丁实现。
- `--resource-rework --resource-timing` 使用 native 组合根；accepted full83 与 pinned timing85 保留自己的顶层/CNN 来源策略，只显式加入共享会话/参数依赖。
- `TIMING_OPTIMIZED` 是编译期配置：资源时序候选显式取 1，普通工作站维持 0；两种结构分别做独立旧实现对比。
- 锁定基线、vendor、原始 manifests 与历史 T24 候选身份没有改写；没有新增长期编号生产构建器。
- `--resource-rework` 不得与 `--current-workstation`／`--cnn-timing85` 混用；直接报错，不按分支顺序静默忽略来源策略。
- PNR/all 必须显式给新 `--user-code`；不再默认重用历史编号。工具成功但 timing/CDC/PLL 失败时返回非零，工具结果和离线可用性继续分别记录。
- 高扇出物理实验显式使用 `--replicate-resources`，绑定实际 Tcl 与元数据，默认关闭。不降低时钟、不增加宽泛例外、不删功能。

首版关键路径集中在 Push/audio-ready、事件控制扇出；route1 另有 TF 控制与 note-drop 路径。功能逐周期等价不保证布局布线时序保持，不能继承 T24 的 +0.022 ns 离线结论。`0xC1102103/04` 资源复制实验在发现下述取消交接缺陷后主动停止，未形成物理验收、未下载；停止原因各有 `trial_stop.json`，不当作时序失败或通过。修复后的 `0xC1102105/06` 按独立来源和 UserCode 重新构建，不以旧工具 exit=0 或已有位流为下载理由。

`0xC1102105/06` 全局复制改变了 FIFO 清除拓扑，CDC 审计拒绝；复制后的 event-release/pixel-ready 寄存器还出现真实复位 recovery/removal 负余量。因此不能只看音频 setup 改善。没有为复制节点补宽泛例外，也没有放宽 PLL 的 10 ns 审计。`0xC1102107/08` 关闭全局复制、分别使用布局算法 3/4，CDC/复位恢复正常，但 setup 与 PLL 仍未闭合，均不下载。

进一步将资源候选的公共命令提交从音符/逐音表情 ready 选择器中解耦：对参数模块有意义的命令，其有效接受条件严格等价于 `event_valid && dispatch && !releasing`。原普通表达式保留，资源编译期分支采用简化表达式；最终源码两种结构各 1,365,022 周期 A/B 对比再次通过。随后 `0xC1102109/0A` 固定 place2/route0、关闭 P&R 全局复制，分别显式采用综合 `max_fanout=64/128`。此选项来自已安装 Gowin 1.9.12.03 的 Tcl/综合文档，与 P&R 复制不是同一机制；安全性仍由实际网表 CDC/复位和 routed timing 判断，不预设通过。两目录的完整输入清单对比仅 `scripts/build.tcl` 不同（编号/综合扇出）；所有 RTL/ROM/约束相同，因此在 09 实际暂存上完成的最终功能见证绑定到 0A 同一源码。

写前通过 JTAG 确认唯一目标：GW5AST-138C，IDCode `0x0001081B`，调试器序列号 `2025030317`，读回 UserCode `0x00000085`、Status `0x00026020`。串口按稳定 by-id 路径并持板卡锁操作。

旧 full85 的 CNN 模型最初未就绪；仅向易失 DDR 上传 104,478 字节模型（CRC32 `AF01A61B`），模型状态变为 `0xE`，没有写 Flash。旧板公共控件 21 项通过，覆盖 A/B/C、音量/表情、调制/滑音、延音、四路输出、效果队列/总开关及 PANIC。采用稳定快照读回后，旧板 32 声部 A 模式、单键释放、PANIC、矢量三声部、几何与静音也通过；但串行欠载健康字从初次 `00010000` 累积到 `000A0000`，整体 smoke 仍失败。**这是旧版本的真实健康故障，不是新候选验收，也未放宽健康检查。** 早期固定等待工具曾报快照未完成及静音非零；稳定读回复核静音通过，因此不把前两项旧工具观测单独定性为产品静音缺陷。

遥测工具原先固定等候 1.25 秒会误判“没有新状态”；现改为五秒上限内等待新序号且期望值一致，仍拒绝旧快照、错误状态及超时，并有独立单元测试。

快照原先固定等两秒也可能尚未读到新完成状态；现核对新请求 token、完成计数和采样序号，并在另一条新鲜完成记录稳定后取数，六秒上限，真实 snapshot error 立即失败。旧状态、错误 token、重复记录及 token 回卷均有独立用例；不通过忽略非零 PCM 或健康字来制造通过。板端 32 声部检查仅声明模式 A 的状态与离散非零快照，不冒充模拟频谱/听感测量或所有模式的最大负载验收。

进一步相位扫描复现了既有取消交接缺陷：PANIC/生命周期取消引擎与效果作业后，串行端没有明确的取消零帧；迟到的单边引擎响应还可能重新设置 joined，阻塞下一帧。修复不改 18-bit 命令或 PANIC 清音符语义：PANIC 当拍不启动新渲染，汇合只接收当前有效帧的引擎响应；native 串行端读取既有 PANIC 静音投影，明确交付取消/静音零帧。普通缺帧仍由 serializer 报错，非取消重复仍进健康统计；没有清零或屏蔽计数器。最终源码的普通/优化事件对照回归和完整相位扫描分别验证，不能用原抽取等价结论代替新增修复的测试。

补零只作用于串行交接，不向已有 render-complete 录音扩展重复灌入采样；连续录音的取消时间表达没有因这项修复自动完成。

### 5.2 SRAM 操作与核心实测

2026-10-21 06:20:45 开始，先核对旧码 `0x85`，仅执行 SRAM Program（operation 2），后读回精确新码 `0xC110210A`；三步工具检查全部成功，实际下载 SHA 与预检一致。原始操作记录位于仓库的 `projects/138k/push2_workstation/results/sram_20261021_062045_522145/`，紧凑清单保留其路径/哈希。除 SRAM 编程所必需的配置过程外，没有额外执行 Flash 写入、Flash 重载、手动复位或物理断电。

仅向易失 DDR 重载同一模型 104,478 字节，CRC32 `AF01A61B`，状态 `0xE`。06:24:54—06:26:02 的严格联合 smoke 通过：公共控件 21 项、A 模式 32 held/active 声部、单键释放至 31、PANIC 清零、矢量三声部、非对角几何快照、静音零输出及 PANIC 零输出；CRC 错误 **0**，末次音频健康字 **`00000000`**。06:26:57—06:27:29 的额外稳定观察也通过，29 次运行报告间精确增加 1,392,000 样本，即每报告 48,000，健康字仍为零、CRC 错误仍为零。以上是 UART 状态与离散内核输出快照，不是 DAC 引脚、听感或 HDMI 图像实测；没有保存音频流。

**状态寄存器不概括成“完全正常”**：SRAM 操作后及核心检查后均为 `0x00026230`，Done Final=1，CRC/Bad Command/ID Verify/Timeout 位均为 0，但 bit4 `Auto_Boot_2nd_Fail` 与 bit9 `Auto_Boot_1st_Fail` 为 1。位定义依据本机厂商 UG704-1.0.4E 第 65–66 页。历史 SRAM 操作也有该值，但这不能代替当前自动启动证明；本轮未定位其置位机制，也未清标志或通过重启制造正常读数。故核心 smoke 成功与完整硬件/冷启动验收明确分开。当前 SRAM 留在上述候选，Flash 仍是 full85，后续需独立授权及冷启动/自动启动调查。
