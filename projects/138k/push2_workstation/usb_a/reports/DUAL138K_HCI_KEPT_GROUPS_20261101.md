# W11 实测 HCI 身份比较的八位分组修复

本阶段完成维护源码和离线等价验证。新源码尚未完成全量综合、P&R 或实板验证，不声明资源、时序或声画收益；W11、M13 已封存候选及其物理输入保持原字节。详细来源和证据身份见 [JSON](dual138k_hci_kept_groups_20261101.json)。

## 实测触发与范围

W11 `D2110101` 的实际 50 MHz 路径从 `decoder/handle_o_2_s0/Q` 到 `host_rx/pending[0]_15_s0/CE`，setup −4.876 ns、26 个逻辑层级、数据延迟 24.676 ns，其中 cell 9.106 ns、route 15.265 ns、C2Q 0.306 ns。`tokens[0]` 的 −4.801 ns 路径使用相同前段。实际 VG 和 VO 的 55 个路径单元逐项对应。

此前完整宽度 XOR 归约被 Gowin 重新识别为 `ALU_MODE=3` 串行比较：先比较 12 位连接 handle，再选择 `close_generation`，然后比较 32 位 host RX generation。后段还经过 owner drift、返回命令资格、共享发送接受及 host RX 更新优先级；本次只修复这两级比较边界。

`workstation_hci_native_transport.sv` 为两条 handle 各保留 8+4 位 mismatch 组，末级仍按原顺序归约和选择。`workstation_hci_host_rx_owner.sv` 为每个 handle 保留四组八位 generation mismatch，供原有两处断连身份判定共用。各组输出采用现有维护源码使用的 `syn_keep` 风格。

没有新增寄存器或周期，没有修改接口、信用、返回命令、租约、默认零值、last-match 优先级或故障/业务顺序。精确来源重建将两个修改块和 2+1 处谓词替换之外的全部生产字节，与已锁定的 W10 来源及此前审核的身份表达式变更逐字节核对。

## 验证

- 完整旧/新 host RX 对照：17,674 周期、33 个公共输出、39 组状态一致；原 host RX 回归 160,228 检查、13 个行为负控和 8 个非法参数均通过，严格 lint 无豁免。
- 完整旧/新 native transport 对照：6,545 周期、33 个公共输出、2,716 组状态一致，包含真实队列和包 RAM。原 native 回归 268 检查、11 个负控及 UART8E1/H5 仿真通过。
- 12/16/32 位二态全域关系及八位分组关系均为 UNSAT。实际源码分组块的有限四态验证为 12 位 601 组、32 位 1,651 组，每组检查原值及反值两个槽位，共 4,504 次比较；覆盖 X/Z、每位差异和跨八位边界组合。
- 完整对照中的 11 个负控全部拒绝，包括四项 keep/分组边界来源失活检查、两项实际分组漏位函数检查和五项既有负控。来源边界负控与功能负控分别记录，不把 keep 属性的存在当作物理映射或时序验收。
- `git diff --check` 通过。全部证据位于外部 cache，生成的仿真产物未加入源码。
