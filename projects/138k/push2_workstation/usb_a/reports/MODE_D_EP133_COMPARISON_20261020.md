# D 模式现状与 EP-133 工作流对照

核对日期：2026-10-20。依据当前 RTL、实际顶层控制和本次定向仿真；EP-133 依据当天可访问的官方产品页及 ver 2.5 指南。本文只整理现状及建议，不修改 RTL、控件分配或既有 A/B/C 功能。

## 1. 首先区分“独立 D 后端”和“已经交付的整机模式”

**当前有可以独立仿真、独立综合的 D 采样器后端，但整机尚未实例化它，也没有可进入的第四种音源模式。**

- `rtl/audio/gw138k_event_workstation.sv:351` 的 CC80 只接受 0/1/2；`:375` 的 CC89 仍在 0/1/2 之间循环。
- RTL 中 `sampler_mode_d` 和 `sampler_storage` 只有模块定义，未被生产顶层实例化。`rtl/sampler/MODE_D_INTEGRATION.md:7` 也明确标为未接入。
- `RESOURCE_TIMING_CANDIDATE.json:1` 的 T24 是既有整机的离线时序闭合候选，不是 D 整机交付。不能把 T24 的 234 块 BSRAM 或时序通过当成 D 已集成的证据。
- D 是短 PCM 素材驱动的采样乐器，不是 TASLP 钢琴物理建模，也不是 CNN 扒谱。其素材不局限于钢琴；合规单音、单次打击都可以成为声音来源。
- 采样器内的四个声音组 A/B/C/D 与现有整机音源模式 A/B/C 是不同概念，不能混用。

目前最准确的定位是：**面向 25K 现场演奏目标的、16 声部采样音源 + 四轨十六步音序器候选后端，而不是已完成的 EP-133 复刻。**

## 2. 当前后端的完整数据流

```text
离线 PCM WAV + 单音/单击审核声明
                  |
          import_samples.py
      单声道 PCM16 / 48 kHz + manifest
                  |
   TF 字节流 / 主控制器逐事务导入   [整机控制尚未接通]
                  |
       sampler_storage + sampler_pool
       reserve -> WAV 解码 / CRC -> commit
                  |
         DDR PCM + 有效 descriptor
                  |
         配置 64 个逻辑 pad 的引用、裁剪、包络等
                  |
现场输入 -> sampler_push ----+---- sampler_sequencer
                            |      实录音符/力度/按住时长
                            |      定时播放已存事件
                            v
                  事件仲裁及配置快照
                            |
                 sampler_voice，最多 16 声部
               DDR 读取 -> 插值变调 -> 包络/增益/声像
                            |
                    Drive -> BitCrush
                            |
                    加入合成节拍器
                            |
                     双声道 PCM16
                            |
           接既有混音 / Delay / 空间混响 / DAC
                         [尚未接通]
```

`sampler_mode_d.sv:4` 已把 Push 映射、音序器、voice、两客户端 DDR 仲裁和局部 FX 接起来；`sampler_storage`、TF source、切片器、显示网格及外层 DDR CDC 是独立模块或整机接入责任，并未全部包在这个顶层内部。

### 2.1 素材加载与内存

- 工具接受整数 PCM WAV，统一转换成单声道 PCM16/48 kHz；立体声取平均。离线采样率转换是线性插值，不是高品质带限 SRC。
- 当前保守策略允许 `single_note` 最长 6 秒、`single_hit` 最长 2 秒，要求显式审核声明；节奏循环、乐句和预编排音乐不在当前允许导入范围。它是工程策略，不是音频内容自动识别，也不能仅凭 CRC 防止虚假声明。
- 声音先写 DDR，长度、CRC 和事务均成功才提交 descriptor；失败则 abort，不能让 voice 读到半份样本。
- 有 64 个 descriptor 槽和 64 个逻辑 pad。多个 pad 可以引用同一个样本而采用不同 trim/loop 范围，切片不必复制 PCM。
- `sampler_pool.sv:5` 默认从地址表的 growth pool 管理 104 MiB、以 1 MiB 为分配粒度。这是独立模块配置的外部 DDR 预算，不是已经交付的 D 存储容量，也不是占用 104 MiB 片上 BSRAM。
- `sampler_tf_source.sv:4` 的文件名是编译参数。已有模块不能在运行时任意浏览 TF 文件；多素材导入还需要主控制器和可运行的文件选择/字节流来源。
- 复位后 pad 配置无效，必须先完成素材装载及 pad 配置写入，才具备发声条件。没有自动扫描 TF 并建立完整音色库的启动流程。

### 2.2 现场演奏、变调和切片

每个 pad 指定素材槽、root note、正反向、裁剪/循环边界、ADSR、音量和 pan。voice 用收到的 note 与 root note 算 Q16.16 播放步进，线性插值取样，最后输出双声道声像信号。

- `ONE_SHOT`：触发后自行播放；同一 key 重触发会截断并重启该 key 原有 one-shot，不是无上限叠加尾音。
- `GATED`：按键控制释放；`LOOPED`：在配置的样本区间循环。这里循环的是单个素材的播放区间，不等于允许导入已有节奏编排。
- 最多 16 个活动声部；满声部后新触发返回 `E_CAPACITY`，没有一般性的最老/最弱声部抢占策略。
- 引擎支持力度与逐音压力，但硬件面板是否能产生这些数据是另一回事。
- 变调采用变速读样本，音高和时长联动；没有独立 time-stretch。当前也没有完整的“选择一个样本，然后把整块键盘切成该样本半音键盘”产品上下文。
- `sampler_slice.sv` 提供 16 等分切片和 16 个手动起点；输出范围须由主控制器写回 pad。没有自动瞬态切片或已经接好的切片编辑页面。

### 2.3 音序器：当前限制比 16 声部更重要

`sampler_sequencer.sv:22` 使用全局 16 个 pattern，每个 pattern 四轨，每轨 16 步；每个格子只存一份 `{note, velocity, gate_frames}`。

- 现场录入按照逻辑 pad 所属组映射到四条轨道，对最近的 swung step 量化；松键时把实际按住的样本数写回 gate。
- **同一轨、同一步只能保存一个音符。** 同组同一步再录一个 pad 会写同一个格子，而不是自动叠加一条事件。
- 播放中一条轨道触发新音符时会向该轨之前保持的音符发 off。voice 的释放尾音、one-shot 和现场弹奏仍可带来超过四声的实际叠加，但这不意味着音序器能够保存同组同一步的和弦或多鼓点。
- 四组共同使用一个 pattern 编号和 step 游标；不是每组有自己的 16 个 pattern、独立长度和播放头。
- BPM 30–300，swing 0–50%；16 步对应当前固定的四拍十六分节奏结构。最多 16 项串链，运行中选 pattern 在下一轮 16 步边界提交。
- 已有 start/stop、节拍器、实录、单步编辑和串链接口；没有完整项目管理、scene、参数自动化记录、外部 MIDI clock 传输/同步工作流或掉电保存。

具体依据：`sampler_sequencer.sv:330` 的 live_track/live_step，`:341` 的单地址写入，`:421` 的全局切换，`:441` 的每轨 off/on 派发。

### 2.4 效果：两项实际 DSP，加一项外部发送控制

`sampler_fx.sv:10` 的实际信号顺序固定为 **Drive -> BitCrush**，处理的是混合后的采样器母线，不是每组独立一套效果。

| 控制 | 已实现的行为 | 不能据此宣称的功能 |
|---|---|---|
| CC20 | BitCrush 深度，0 关闭 | 不是完整的 EP-133 Punch-in 效果集合 |
| CC21 | Drive 增益及饱和，0 关闭 | 没有每组独立的效果链 |
| CC22 | 独立保存并导出 Delay Send 深度 | D 内没有 Delay 缓冲或回声 DSP；外部发送/返回尚未接通 |

三个状态可以独立变化，不必停掉正在播放的声音。模块本身只是“收到值就保持该值”；按住生效、松开取消或再次按键锁定，要由面板控制器明确产生对应 CC，不是模块自动区分的手势。

既有整机的 chorus/delay/空间混响不因此自动进入 D。后续适合接公共效果母线并复用现有资源，不应为 D 另复制一套长延迟/混响 RAM。

### 2.5 控件与显示并未形成 25K 闭环

历史 `sampler_push.sv:21` 按 Push 的 note36–99 和 8×8 行列解析：左下 4×4 演奏、顶行左侧四键切组、右上 4×4 选 pattern；已按下的映射保留至松开。

当前 25K 是连续 note48–63、On100/Off0 的 16 键，以及既有编码器/弯音滑条约定。它不能直接套用上述 Push 布局；否则部分键会被当成非主 pad 而吞掉。`reports/GW25K_CONTROLS_20261019.md:19` 记录的基础控件已落地，但没有 D 专属演奏/效果上下文或完整效果页面。

用户已经确认的目标是“同一 4×4 在不同上下文用于演奏或效果，并可在播放过程中独立组合效果”。当前缺的是这个控制/状态闭环，而不只是再写几个 DSP 算法。`sampler_grid.sv` 也只是独立的 16×4 网格渲染模块，并非已经显示在真实面板上的界面。

## 3. 与 EP-133 K.O. II 的区别

### 3.1 比较版本与规格口径

官方指南当前显示 ver 2.5；产品页当前标示 128 MB、16 mono / 12 stereo 声部。下表按当前官方工作流比较，不沿用首发参数；对于具体机器，仍须按其硬件与固件核实能力。**这些页面没有提供足以判断所有旧机器升级后容量/声部变化的依据，本文不作该推断。**[E1][E6]

以下主要比较工作逻辑，不把存储数字或采样率单独当作音质排名。

| 维度 | 当前 D 后端 | EP-133 官方工作流 | 实际影响 |
|---|---|---|---|
| 使用链条 | 多模块接口已存在，尚缺真实整机入口、加载控制和 UI | 集成采样、编辑、演奏、录制及保存 | 首要差距是闭环，不是声部数 |
| 声音组织 | 四组 × 16 个逻辑 pad，共 64；组与轨道在实录时对应 | 四组 × 12 个声音键 | 我们多四个键不等于编排能力更强 [E2] |
| 编排结构 | 全局 16 pattern；四轨各 16 步，共用 pattern/step | 各组 99 pattern，独立长度，scene 组合各组 pattern | D 缺少组间独立变化的组织层 [E2] |
| 同一步叠音 | 每轨每步一条音符，后写覆盖 | 面向组内多个声音的事件编排 | 同组踢鼓+踩镲的保存是 D 的明显短板 [E2][E4] |
| 节奏与手感 | 实录吸附到当前固定十六步网格，带 swing | 多种步长及三连音、量化或自由时间录制 | D 尚不能保存任意微时序的现场手感 [E5] |
| 实时表情 | DSP 支持力度/压力；25K 当前固定力度、没有压感输入 | 力度/压感键和现场效果控制 | 不能用软件假称获得真实压感 [E1][E3] |
| 现场效果 | 全局 Drive、BitCrush，以及尚未接外部音频链的 Delay Send | 选择一项 send FX；另有可组合的压感 Punch-in | 多个 CC 状态不等于完整 Punch-in 演奏系统 [E3] |
| 参数自动化 | 音序器只保存音符/力度/gate，不保存 FX 参数变化 | 可录制 fader 参数运动并擦除/撤销 | 当前效果变化可以现场听见，但不会自动随 pattern 重演 [E4] |
| 声源采集 | TF/字节流导入候选；受限单声部内部回录；无 ADC | 可通过麦克风/输入口采样，也可重采样 | D 当前不能拿手机/麦克风现场录声 [E1][E5] |
| 素材编辑 | trim、reverse、等分/手动切片、线性插值变速 | 完整声音编辑，含 beat/time-stretch 等功能 | D 缺少独立时长调整及其工作流 [E7] |
| 半音键盘 | 有 root note 和变调计算，但没有完整采样键盘上下文 | KEYS 可将选定样本映射到半音键盘 | 有变调运算不等于已有可用的样本旋律演奏入口 [E4] |
| 保存/同步 | 没有完整 project/scene/自动化持久化链及外部时钟工作流 | 有项目/scene 管理与 MIDI/同步设置 | 完整演出组织不只是循环播放一个 pattern [E2][E6] |
| 业务边界 | 当前仅接收审核后的单音/单击，录音序器事件再实时合成 | 通用采样器，不沿用本工程素材审核限制 | 不应照搬其整段素材玩法而绕过当前项目约束 |

### 3.2 一个能直接体现差异的例子

假设组 A 放 kick、snare、closed hat，希望第 1 步同时有 kick 和 hat：

- 当前 D：实录会把它们都写到轨 A 的第 1 步同一个 RAM 地址，后写者覆盖前者。即使现场同时能听到两个声音，回放也不一定保留两者。
- 可以暂时把 kick 和 hat 分到不同组，但会占用两条轨道，还不能解决同组和弦问题。这是工作流妥协，不是 EP-133 等效能力。
- 要补齐，应改变事件存储模型，允许同一组同一时刻多事件；不是把 voice 从 16 加到 24 就能解决。

## 4. 建议的建设顺序（未实施）

### 第一优先：让现有能力接成真实可用的演奏闭环

1. 明确并实现 25K 的演奏/效果上下文与状态回传，保留已确认基础控件，不把旧 Push 布局直接挪用到 16 键。
2. 接通素材加载、descriptor/pad 配置、真实 DDR 仲裁与 CDC、PCM 公共混音链和错误反馈。D 的产品入口须统一设计，不能把旧 CC80/89 草案当成已确认方案。
3. 保持播放期间效果可独立开关，明确按住/锁定、作用母线和松开规则；先复用已有 Delay/空间混响，不重复建设长缓冲。
4. 给用户可见的组、pattern、录制、运行和效果状态，实际面板与音频行为一致。

### 第二优先：补最影响“像 EP-133 那样演奏”的事件结构

1. 同组同一步多音符、多 pad 事件，避免录入覆盖；保持实时触发与录后回放一致。
2. 组 mute/solo、清楚的 overdub/erase/撤销，再考虑组独立 pattern/长度和 scene。
3. 编排继续存音符/控制事件，而不是存整段混音 PCM。事件 RAM 可以紧凑打包并采用同步 RAM；具体资源必须综合，不在本报告给未验证节省数字。
4. 效果记录优先存稀疏参数事件，不按 48 kHz 保存参数曲线。低存储的 Drive/BitCrush/调制类效果先于长回放缓存或更多混响实例。

不建议为追求表面相似，第一步就复制 12 个 Punch-in、全部效果、立体声采样或大型 time-stretch。它们应在闭环完成及资源评估后再排期。这里不建议删除现有功能，也不把建议写成已完成。

## 5. 验证与资源口径

本次执行：`python3 sim/sampler/run.py --test tb_sampler_mode_d`。

结果：PASS；5022 个集成帧；三次同采样帧起音断言；本测试集成抖动 0 samples；本测试最大 render 62 clocks；播放中遍历三个独立效果状态的 8 种组合，8 次切换。输出：`out/sampler_20261020_234900_974876/verification.json:1`。

该结果证明独立 D 测试台中状态组合与播放连续性；**Delay Send 的状态验证不证明实际外部 Delay 已经发声；62 clocks 也不是 16 声部最坏帧界。** 本次没有重跑全套 sampler 测试、独立综合、整机 P&R、下载或板测。

历史独立综合及压力测试见 `rtl/sampler/MODE_D_INTEGRATION.md:105`：

| 项目 | 历史结果 | 边界 |
|---|---:|---|
| `sampler_mode_d` | 23,675 logic / 16,904 regs / 9 BSRAM | 独立综合，估算 Fmax 81.269 MHz，不是整机 P&R |
| `sampler_storage` | 11,128 logic / 10,080 regs / 0 BSRAM | 不含完整 TF source、外层 CDC 和所有控制/UI |
| voice 压力测试最慢帧 | 1405 audio clocks | 模型 DDR 及既定竞争条件，不是板上最坏服务保证 |
| 最大采样读带宽模型 | 49.152 MB/s | 16 声部每帧各两次 32-byte 读取、48 kHz |

因此 D 的资源风险不能只看“9 块 BSRAM 很少”：逻辑、寄存器、DDR 服务时间、外层连接及 76.8 MHz 时序余量同样重要。不能把独立模块数字简单加到 T24 后宣称资源或时序已经满足。
