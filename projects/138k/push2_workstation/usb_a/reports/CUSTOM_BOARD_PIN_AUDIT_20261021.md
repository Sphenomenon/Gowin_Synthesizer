## 2. TF：确定的一处 SPI 球位变化

新卡座为 `U16`。以下按其实际引脚功能核对，不把蓝牙 FPC 上的同名 `SD_*` 当作 TF 卡。

| 顶层端口 | 现有约束球位 | 自定义底板球位 | 新板证据 |
|---|---|---|---|
| `sd_miso` | AA15 | AA15，保持 | `BANK5_AA15` → `U16.1`，DAT0 |
| `sd_mosi` | Y16 | **W14** | `BANK5_W14` → `U16.8`，CMD |
| `sd_sck` | V15 | V15，保持 | `BANK5_V15` → `U16.7`，CLK |
| `sd_cs_n` | W15 | W15，保持 | `BANK5_W15` → `U16.5`，DAT3 |

新板的 Y16 接 `U16.3`，即 DAT2；AB15 接 `U16.2`，即 DAT1。继续把 MOSI 约束到 Y16 不会到达 CMD。以上仅确定物理映射，未验证 SPI 电气、读卡或文件播放。

## 3. HDMI：四对线的连接极性均与旧板相反

HDMI 插座在新网表中名为 `USB3`。不能因为位号以 USB 开头而当作 USB 接口。

| 信号 | 旧约束的 P / N 球位 | 新板连接到插座的 P / N 球位 | 串联电容与插座脚 |
|---|---|---|---|
| TMDS D0 | J14 / H14 | **H14 / J14** | P 经 C23 到 `USB3.7`；N 经 C22 到 `USB3.9` |
| TMDS D1 | J15 / H15 | **H15 / J15** | P 经 C25 到 `USB3.4`；N 经 C24 到 `USB3.6` |
| TMDS D2 | K17 / J17 | **J17 / K17** | P 经 C27 到 `USB3.1`；N 经 C26 到 `USB3.3` |
| TMDS CLK | G15 / G16 | **G16 / G15** | P 经 C21 到 `USB3.10`；N 经 C20 到 `USB3.12` |

这是板上连线的 P/N 身份，**不是已经通过器件合法性检查的 `IO_LOC` 顺序**。迁移须结合 PG484A 差分输出资源、串行器及输出缓冲，确定用合法极性补偿还是调整硬件；不能只倒写四条成对 CST 就宣称可用，也不能只处理数据对而漏掉时钟对。

另外两项：

- `hdmi_hpd` 的 K13 仍经 R19 接插座 `USB3.19`，并有 R20 与 D3；这里只核对拓扑，不替代电气验收。
- 旧 `hdmi_tx_en` 的 K14 **不再是收发方向选择**：新板 K14 经 R21 接 `USB3.13`（CEC），该网络另经 R22 上拉。当前原生顶层将 `hdmi_tx_en` 固定为 1，不能原样解释成新板方向使能；新配置需要显式处理这一不再适用的端口，不能随意移到其他脚。

## 4. USB：USB-A 的 PHY 路径已经改变

| 新板接口 | 数据路径 | 与现有工作站的关系 |
|---|---|---|
| `USB1`，USB-C | D+ 经 R33 到 H13；D− 经 R34 到 G13 | 对应现有 FPGA Full-Speed 软 PHY 球位，但不是旧板的 USB-A 插座；Host 接法、CC、供电与转接仍须核对 |
| `USB2`，USB-A | D+ 经 R31 到 `U2.7`；D− 经 R32 到 `U2.8`；U2 为 USB3300 | 经外置 PHY／ULPI，不是 H13/G13 的直接 USB 线；不能靠重映射 `usb1_dp/dn` 接入 |
| `USB4`，USB-C | D+/D− 接 U12，原理图标注供电用途 | 不作为工作站 USB 数据口 |

2026-10-21 用户确认“接入到usb-2”：**Push／25K 使用新底板 `USB2` USB-A，经 USB3300／ULPI 接入，不使用 `USB1` 直连 H13/G13 的路径。** 两种交互设备仍交替使用同一 Host 端口，不假定同时连接。

现有 Push／25K Host 保持 Full-Speed 语义。存在 USB3300 或原理图上的 High-Speed 注记，不证明当前工作站已有 ULPI Host 或 High-Speed 支持；选择 USB2 本身也不等于要求或实现 High-Speed。25K 的 USB3300 **设备端**工程不能直接当作 138K Host 后端。

### USB2 的 ULPI 物理映射

下表通过原理图 U2／U4／U5 的符号引脚名称与新网表逐段核对。U4 为 TXS0108EPWR，U5 为 TXS0104EPWR；不能把电平转换器两侧当成同一个网表网络，须按 A/B 配对通道追踪。

| ULPI 信号 | 相对 FPGA 的方向 | USB3300 管脚 | 转换器 A → B 通道管脚 | FPGA 球位 |
|---|---|---|---|---|
| DATA0 | 双向 | `U2.24` | `U4.1` ↔ `U4.20` | A21 |
| DATA1 | 双向 | `U2.23` | `U4.3` ↔ `U4.18` | B21 |
| DATA2 | 双向 | `U2.22` | `U4.4` ↔ `U4.17` | A20 |
| DATA3 | 双向 | `U2.21` | `U4.5` ↔ `U4.16` | B20 |
| DATA4 | 双向 | `U2.20` | `U4.6` ↔ `U4.15` | A19 |
| DATA5 | 双向 | `U2.19` | `U4.7` ↔ `U4.14` | A18 |
| DATA6 | 双向 | `U2.18` | `U4.8` ↔ `U4.13` | B18 |
| DATA7 | 双向 | `U2.17` | `U4.9` ↔ `U4.12` | B17 |
| CLKOUT | 输入 | `U2.14` | `U5.2` → `U5.13` | C18 |
| DIR | 输入 | `U2.12` | `U5.4` → `U5.11` | F16 |
| NXT | 输入 | `U2.11` | `U5.5` → `U5.10` | D16 |
| STP | 输出 | `U2.13` | `U5.3` ← `U5.12` | E17 |

以上球位均标为 Bank 2。U4／U5 的 A 侧供电为 `VDD_1V8`，B 侧为 `3V3_USB3300`，OE 接 `VDD_1V8`；FPGA 连接的是 B 侧，不可把 PHY 的 1.8 V 电压直接套到 FPGA 约束。实际 Bank 2 VCCIO、转换器延迟、负载及 60 MHz ULPI 时序仍需独立核对。`U2.9` RESET 在新网表中直接接 GND，没有可映射的 FPGA 硬复位脚，不能虚构 `phy_reset` 球位。

### Host 实施边界

现有 `vendor/usb_host_fs_8fc3/src/iosys2.v` 在 `usbh_core` 与 `usb_fs_phy` 之间已有 UTMI 信号边界，后接直连 D+/D− 的 `usb_transceiver`。因此可以评估在这一边界增加独立的 ULPI 适配层，保留 Host 事务、MIDI／PL 和工作站业务；但它不是已经实现或验证的替换。当前活动 RTL／工具／仿真目录中没有发现 ULPI 实现。

后续 USB2 适配至少需要 PHY 初始化及 Host 配置、UTMI／ULPI 收发转换、DATA 总线换向、RXCMD／线路状态与拔插传播、48 MHz Host 域和 USB3300 时钟域的明确交接，以及总线争用／背压／复位恢复测试。不能把两域信号直接相连，不能绕过既有断开取消／初始化语义，也不能移用 25K 设备端时序例外来使 Host 路径过关。上述内容尚未修改源码或进入构建。

## 5. 音频：底板连接已知，子板功能定义缺失

原理图将 `FPC2` 标为 DAC 解码功放接口。网表给出了十根 FPGA 信号线，但没有指出哪根是 BCK、WS、DATA、MCLK、控制总线或功放使能。

| FPC2 脚 | FPGA 球位 | FPC2 脚 | FPGA 球位 |
|---|---|---|---|
| 8 | C17 | 13 | B15 |
| 9 | D17 | 14 | A14 |
| 10 | A16 | 15 | A13 |
| 11 | A15 | 16 | B13 |
| 12 | B16 | 17 | C13 |

FPC2 的 1／2／23／24 脚接 +12V，5／20 脚接 +5V，3／4／6／7／18／19／21／22 脚接 GND。电源脚不能当作备用 GPIO；排线同面／异面及子板插座编号也不能仅凭底板网表推断。

旧板 `hp_bck=Y17`、`hp_ws=AB17`、`hp_din=AA16`、`pa_en=AB16` 不在新 FPC2 的这些信号线上，不能保留旧约束后称为完成音频迁移。当前发送器是 `pt8211_tx`，采用 PT8211 的右对齐格式，不是任意 DAC 都兼容的标准 Philips I²S。还需要子板原理图或排线信号表、DAC 型号、串行格式／位宽、是否需要 MCLK／初始化、功放使能有效电平。

`FPC3` 标为蓝牙／Wi-Fi；其 `PCM_*` 不能当作上述 DAC 音频线，`SD_*` 也不能与 TF 卡混接。其 5 脚明确标出 T14；其余 UART、PCM、SDIO、唤醒和禁用线多数只给出 J2 连接器脚号，不能仅从这些功能名猜出封装球位。

## 6. 保持与待核对项

- 若仍采用同一块 30354 核心板，核心板 50 MHz 时钟 V22、DDR 和配置 Flash 不因底板改线而自动重分配；本轮查看了核心板原理图第 5／6 页，不能据此代替新底板与核心板的连接器兼容性验收。
- 新网表没有给出旧底板 AB13 演奏／复位按键的同等接法；不能拿 SW1 的配置模式、重配置或其他用途脚直接替代 `button1_n`。
- U15／V14 的调试串口如需继续使用，应核对核心板调试口和外接 3.3V 串口适配器。新底板没有旧 NEO Dock 的 BL616 串口桥证据，不能沿用“插底板调试 USB 就有原 UART”的说明。
- FPC1 摄像头、FPC3 蓝牙和 FPC4 LCD 属于各自接口，不因为有可用 GPIO 就擅自加入工作站或挪作音频线。

## 7. 实施与验证边界

三个完整工作站入口采用锁定基线，修改活动 `p11.cst` 不会可靠地更新三条构建路径。后续应在已有构建入口增加**显式自定义底板配置**，对实际暂存约束应用经核对的适配；旧 NEO Dock 默认配置、accepted full83、pinned timing85 和资源候选的来源政策保持不变，不编辑 `baselines/objects/` 或原始清单。

USB Host 的实体接入路径已确认，ULPI Host 适配尚未实现。开始完整底板迁移前仍须补齐 FPC2 子板与排线定义，以及新板复位／调试接法。之后再完成差分极性合法性检查、端口覆盖与重复球位检查、针对性仿真和 `sim/test_current_workstation_sources.py`；涉及基线准备适配时还须运行固件、基线回归及三路径干净 prepare。引脚和输出缓冲变化后，旧 routed timing／CDC／PLL 结果不能继承，需要新候选与新实现证据。硬件操作仍另行授权。

本轮离线核对解析了 185 个网络，对 TF、四对 TMDS、电容两端、HDMI CEC 及两条 USB 数据路径完成 28 组网络成员断言。该结果只证明源网表中的连接关系，不是综合、P&R、音视频实测或硬件验收。

确认 USB2 后，另完成 12 条 ULPI 信号路径的转换器两侧网络断言，并核对符号通道名称、两侧供电、OE 与 RESET 网络。仍未执行 USB Host RTL 仿真、综合、P&R 或板测。
