# M9 实测后的 TF 小增量加法修复

2026-10-31。M9 `D2103107` 完整 P&R 的最差 setup 是 DDR 100 MHz 域内 `available_bytes_8/Q → accepted_used_30/D`，slack −3.643 ns、data delay 13.584 ns。前次同拍占用计数消除了宽总量减法，但读响应资格仍经七位有符号增量进入整条 32 位进位链；本阶段据此修改实际维护 DMA，未改已封存 M9 输入。

占用更新现在先用当前计数独立计算高26位的 +1／−1 候选，晚到增量只参与低6位相加及高位候选选择。结果仍是同一边沿提交的模 2³² 有符号加法，保留负增量借位、正增量进位和两端回绕；未增加请求、响应或输出延迟，未缩窄计数容量。DDR 分配和原始协议保持不变，两份显式 DEMO 的来源锁只更新 DMA 与 provenance 两项。

两种容量各通过 400,007 次旧版公共输出／完整状态对照。每种容量另以独立全宽33位加法核对全部64种低位、128种有符号增量、54种高位进位边界，共442,368组；未以分段公式作为期望值。漏记输入、错误借位、漏记高位进位、同时读写丢失四个真实 RTL 负控全部被拒绝。四种独立 byte／ring oracle 继续通过即时／延迟响应及 native stall。

最终源码另通过完整 TF DDR／WAV／policy 路径的23场景与677帧输出（两种 command-buffer 配置）、128帧旧默认路径逐拍对照，以及两配置各6组停高／停低时钟清理与真实 restart ACK 回归。SD／FAT 输入在这些回归中是字节边界 fixture，不冒称实卡验收。[机器证据](dual138k_tf_small_delta_20261031.json)封存实际来源、完整日志／结果和 M9 触发路径。新的综合／P&R 收益尚待下一完整候选测量，未下载 SRAM 或写 Flash。
