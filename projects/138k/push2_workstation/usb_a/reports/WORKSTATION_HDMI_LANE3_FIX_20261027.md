# 优化版 HDMI 修复：lane3 局部布局实验

日期：2026-10-27，Asia/Shanghai。用户重新要求修复 HDMI；目标是保留 C1 的 BLE 业务与资源优化并恢复显示，不把回退 B3 当成新版修复。此前接受的 B3 恢复出图记录仍有效，但不扩大其验收范围。

## 本轮改动

前置实板证据见 [DDR 读校准记录](WORKSTATION_DDR_READ_CALIBRATION_20261027.md)：C3/C5 卡在读校准，lane0–2 观察到完成脉冲，lane3 未见；C5 观察时序有违例，不能据此认定电气原因。此次不再增加 GAO 位宽或改变采样点，避免诊断逻辑再次扰动布局。

使用 C1 自己的 `.p/.pr` 做增量 P&R，完整保留 a26 业务 VG、SDC、400/100 MHz DDR 时钟、DDR 地址图、官方三项硬资源定位、既有 hold 区域和 16-bit GAO 信号集合。只增加两项位置约束，并使用新身份 `C11027C6` / GAO `27C6`：

| 实例，位于 `u_memory/u_ddr3/gw3_top/u_ddr_phy_top/u_ddr_init/` | C1 实际位置 | C6 要求位置，来自 B3 |
|---|---|---|
| `read_calibration_logic_gen[3].rburst_neg_s0` | `R88C173[2][A]` | `R87C174[0][A]` |
| `read_calibration_logic_gen[3].rburst_neg_r_s0` | `R88C173[3][B]` | `R87C174[2][A]` |

这两个寄存器处于 lane3 的负沿 RBURST 采样/延迟链。位置取自成功出图 B3 的实际 routed timing 表，不凭空选择区域。它们是否决定校准失败尚未证明；**本轮是单一局部布局变量的因果实验，不能提前称作根因修复**。仍需核对工具是否真正采用位置、最终时序和实板校准/BIST/前台帧。

## C7：先纠正 DDR 控制参考时钟的路由类别

进一步追踪 `RLOADN` 的公共 `pause` 驱动，发现它由 DDR IP 的 `ddr_sync/cs_memsync_2_s0` 寄存器产生，**时钟是输入 50 MHz，不是 DDR UI 100 MHz**。实际 P&R 的时钟表还存在以下区别：

| 对照 | 50 MHz 控制时钟实际路由 |
|---|---|
| 官方独立 B1 | `clk_d` → PRIMARY |
| 工作站隔离 B2 | `clk_50m_d` → PRIMARY |
| 整机 B3 / C1 / C6 | `clk_50m_d` → LW；整机日志存在 PR1014 普通布线时钟偏斜警告 |

B3 在 LW 下仍有成功记录，因此**该差异不是根因证明**；它为优先消除敏感 DDR 控制时钟的普通布线依赖提供了明确依据，不必先改加密 IP 或继续试搬两个采样寄存器。原生全板全局时钟较紧，是否能合法分配还必须由工具和所有时钟/路由检查证明，不强行降级其他业务时钟。

C7 从精确 C1 输入重新准备，不包含 C6 的两个位置约束，CST 只增加：

```text
CLOCK_LOC "clk_50m_d" BUFG = CLK;
```

配置语法依据本机官方 `SUG1018-1.7E` 第 2.7 节。不改变输入/派生频率、SDC、CPU、音频、USB、LCD、BLE 业务或 DDR 分区。使用 C1 自己的增量数据库，UserCode 为 **`C11027C7`**；GAO 身份和信号集合逐字复用 C1 的 **`27C1`**，避免为区分候选而同时改动观察核心。图像身份仍以独立 JTAG UserCode、输入及位流 SHA256 区分，不把 GAO ID 当成新的发布验收。

准备/捕获脚本通过显式 `--global-reference-clock` 选择 C7，其默认 C6 模式保持独立。C6 机器摘要中的脚本哈希是当时执行版本，后续扩展不改变 C6 已保存的九份实际工具输入或原始记录。C7 输出为 `out/workstation_resource_a26_20261027_c7_refclock/`，不混入活动工作区其他 USB/音频修改。
