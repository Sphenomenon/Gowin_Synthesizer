# 25K现场演奏目标与EP-133借鉴边界（2026-10-19）

本页记录用户本次明确的产品方向，并核对独立D代码。用户已明确：接入Push时的特有功能是CNN扒谱及谱面引导；接入25K时，特有功能借鉴K.O.II／EP-133的演奏逻辑，同一4×4按键既用于发声，也在进入相应模式后对应效果，播放已有声音期间可以随时独立开关并组合效果。用户进一步要求在不违反题目要求的情况下多借鉴EP-133。

## 已确认的目标和系统分工

| 项目 | 已确认目标 | 当前状态 |
|---|---|---|
| Push专有 | CNN扒谱与谱面引导交互 | 138K已有识别／跟奏链，Push负责交互；用户认为基本完成，仍按现有验收和时序边界表述 |
| 25K专有 | 4×4演奏与效果控制；已有声音持续播放时组合开关效果 | 目标已明确，完整产品链未接入；基础MIDI／PL Host页不是该功能完成证明 |
| 138K职责 | 音源、采样播放、效果计算、公共状态与资源 | 复用已有主机实现，不在25K复制音源／FFT或新增DDR客户端 |
| 25K职责 | 触摸／控件、按当前上下文发MIDI、本地移调、SPI屏与外围驱动 | 完整设备源码现已导入，已确认控件已接真实应用；不因设备功能归属而把DSP迁到25K |
| 连接 | Push或25K轮流接138K板载USB-A，热插拔自动识别 | 原已定连接不变，25K继续隔离曲谱业务 |

这里的“进入模式”只确认按键用途有上下文切换；不等于已经确定要新增音源D模式入口、修改CC89的A/B/C循环，或分配编码器长按。普通演奏层16键MIDI48–63、力度100、释放力度0及原有编码器／滑条约定保持。

## 可以优先借鉴的工作流

官方EP-133指南的effects／11.7以按垫临时效果和效果组合为核心参考。本工程采用用户的16键触摸板及现有协议，以下内容按“目标已确认”或“候选”分别落地，不能把整机仿制当作已授权清单。

| 借鉴方向 | 对本工程的落点 | 状态 |
|---|---|---|
| 演奏与现场效果使用同一组按键 | 16键随已定义上下文变为发声或效果控制；已有播放继续 | 已确认目标；进入／退出动作和具体16键表待定 |
| 多个效果可独立开关 | 保留各效果自身状态，关闭其中一项不清掉其他项或重置播放 | 已确认目标；三项现有后端已补组合验证 |
| 按组组织声音 | 可复用已有4组／64逻辑pad与配置，不要求25K实现Push的8×8物理布局 | 候选；不能自动分配新的组选择控件 |
| pattern演奏和小节边界切换 | 可复用已有音序器、pattern、运行中边界提交；记录和触发音符事件 | 候选；现有模块能力不表示新产品入口已确定 |
| 单音素材切片与变调 | 可复用现有16切片、trim、loop／reverse和变调能力 | 候选；遵守素材范围与实际资源，不自动扩大导入对象 |
| 演奏时明确反馈当前状态 | 从138K已有状态驱动现有PL小块页面，标清当前按键用途和生效效果 | 后续接口／UI候选，未设计专有菜单或新线规 |

EP-133的压感、全部效果清单和按键组合不是直接移植要求。这里仍使用已定固定力度与触摸规则；各效果的具体深度、按住生效／松开取消或再次按下锁定开关、作用于哪些音频路径及效果顺序，需要形成明确接口后实施。当前CC20／21／22的0释放、1–127深度、默认0含义保持。

## 现有雏形的代码依据

- `rtl/sampler/sampler_voice.sv`：16声部采样播放、loop、变调等基础；`sampler_sequencer.sv`：pattern和事件编排基础。
- `rtl/sampler/sampler_fx.sv`：三个独立状态是CC20 BitCrush、CC21 Drive及CC22 Delay Send。Drive／BitCrush处理D voice PCM，Delay Send只导出给外部现有P10效果，不能把发送深度输出当作已经听到Delay效果。
- `rtl/sampler/sampler_mode_d.sv`：把voice、音序器、FX和独立DDR客户端边界接在一起，但当前完整工作站未实例化它；现有A/B/C、TF PCM和整机DDR／UI没有据此自动接通D。
- `rtl/sampler/sampler_push.sv`：按Push的note36–99／8×8行列解析主pad、组与pattern，不是25K的48–63连续16键适配器。它不能直接用作25K产品映射。
- `gw25k_panel.h`：只有通用音源基础状态页，没有16键效果上下文、完整效果状态或D专有页面；完整25K设备工程仍未导入。

因此，已有的是可复用的独立采样／音序／三项效果后端，25K特有演奏功能仍未形成整机闭环。此结论不改变Push／generic已有能力或上一批功能验收结果。

## 本次实际补充的离线验证

修改`sim/sampler/tb_sampler_mode_d.sv`：在真实循环voice与音序器运行期间，用单项控制变化遍历三项效果的全部8种组合，再回到全关。验证开启／关闭一项后其余状态保持、voice和active mask保持、sample_time每次推进、PCM持续非零、Drive实际改变PCM，移除内部效果后恢复原干声。Delay仅核对发送控制，外部P10音频不在该测试中。

结果：[verification.json](gw25k_performance_scope_20261019/verification.json)为`passed=true`。5022帧、3次原音序同采样起音、jitter0、最大渲染62 clocks、8种效果组合和8次单项切换；未报告deadline／voice／DDR／sequencer错误。生产RTL／固件未改，未重新跑完整18道整机门禁；上轮报告仍对应其原输入，不重写历史哈希。

复现：在`projects/138k/push2_workstation/usb_a`执行`python3 sim/sampler/run.py --test tb_sampler_mode_d`。原始输出位于验证汇总指定的`out/sampler_*`，报告仅归档JSON和日志，未写入对象或可执行文件。
