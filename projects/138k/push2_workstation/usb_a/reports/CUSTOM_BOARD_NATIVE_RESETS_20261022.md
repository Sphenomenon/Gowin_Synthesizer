机器记录：[verification.json](custom_board_native_resets_20261022/verification.json)。[a3 时钟证据](CUSTOM_BOARD_NATIVE_CLOCKS_20261022.md)及更早候选保留原身份、输入与验证范围，不追改成 a4。

## 1. 修复的是异步复位释放，不是延长业务等待

原桥接已经有 CPU／ULPI 各自两级 `cpu_session_q`／`ulpi_session_q`，但事务寄存器的异步复位仍直接使用 `channel_reset_n`，只用本地 ready 门控正常更新。CE 门控不能把触发器异步复位端的释放变成同步释放。这是复位恢复／移除检查前的结构缺口，不是已经测到板上亚稳态。

- CPU 事务组改由 `cpu_session_q[1]` 异步置复位、在 CPU 域同步释放；ULPI 事务组对应使用 `ulpi_session_q[1]`。
- 原两级释放链仍由原始取消条件异步清零；取消、generation、IRQ、描述符与结果握手、超时和恢复策略不改变。
- TX／RX 仍是两个独立双时钟 512×8 RAM，不给存储内容新增异步复位；有效性继续由事务状态和会话隔离。
- 不停止或延长音频采样计划，不以显示、PL、USB 或诊断操作等待替代实时音频交接。

新增 Yosys 结构检查在修改前实际失败于 `transmit_count_q` 的 ARST 来源；修改后验证全部 17 个事务寄存器组的本地时钟、复位源、复位极性和值，以及四条两级释放链的 D 连接。原 CPU 快于／接近／慢于 ULPI 三组行为回归继续通过。

## 2. 从真实 Gowin 网表验证复位扇出

`tools/workstation_synthesis_netlist.py` 由原时钟审计解析器抽出，时钟与复位审计共享实际模块／实例／参数解析。它支持这里实际使用的标量、单比特非零下标端口及简单向量切片映射；相关连接若需要未支持的拼接投影则拒绝，不能猜测。无关子模块的连接不作为复位锥验证结果。

Gowin 在完整装配中把 CPU 全局释放链合并至上层 `u_native_usb`，并通过 `[1:1]` 端口传递 ready。审计沿真实祖先层次和位选择解析，不把“释放链必须留在 bridge 内”当作硬件事实，也不只根据寄存器名称接受结果。

- 实际 bridge 为 `u_native_usb/host/usb/bridge`；四条释放链均为两级、同域时钟、链内共享异步清零输入、无条件移位。
- 实际网表中 CPU／ULPI 分别有 225／169 个桥接寄存器由相应本地释放链驱动；事务组分别覆盖 77／96 位。
- 复位锥只接受已解析的常量、反相器与 LUT 组合，验证其对最后一级 ready 确为反相，不能绕回原始异步源或其他时钟域。
- a3 的真实旧网表在新审计下明确失败于 `transmit_count_q_9_s0` 绕过本地释放；新组件及完整装配均通过。
- 实际新网表中把 CPU／ULPI 事务 CLEAR 改回原始异步源的负例均被拒绝。独立 MMIO 综合保持 4 SDPB、1,074 寄存器。

这不是完整 CDC 或物理复位时序验收。**没有新增 false path、全域异步时钟组或放宽频率。** SDC 仍来自原单一时钟计划，DDR UI 不透明目标仍 deferred；`physical_reset_timing_verified=false`、`cdc_constraints_complete=false`。
