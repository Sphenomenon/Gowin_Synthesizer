# Display observation loss policy

`workstation_runtime_controlled.sv` exposes `display_observation_fault_o`, a sticky level in the continuous 50MHz domain. Either physical-frame observation FIFO overflow or compute-to-50MHz display-mailbox overflow sets it. Only the common runtime `rst_ni` clears it; CPU/APB reset, rate switch, serializer restart and later good frames do not rearm this display path. The top must include its inverse in HDMI's `observation_trusted_i`. Audio sampling, event/parameter ownership and stream epoch remain independent.

The display mailbox crosses one complete 203-bit tuple: the previous 194-bit physical PCM/context/reference/voices/health fields followed by the three-bit effect mask and six-bit order sampled on the same compute observation edge. No independent multi-bit 2FF effect copy remains. Only `display_valid_o` makes these fields consumable; reset/idle effect order can be zero while the first complete tuple is unavailable. The 448-bit performance layout and the 204-bit downstream HDMI tuple (203-bit display tuple plus trust) retain their existing field contracts.

The small `workstation_display_observation_health` helper is defined in the same source file, so no additional compile dependency is needed. Its two input counts belong to compute domain. Physical `observation_drop_o` already crossed from selected MCLK via the observation bridge's registered post-drop Gray counter and may jump by several drops; it must never be re-encoded as a unit-step Gray count. The helper converts each count to a sticky **single-bit loss level** and synchronizes the two independent levels through two stages into 50MHz, which latches the final display fault.

Each source level is `source_sticky || current_count_nonzero`. If the first drop increments a producer's registered count on the last compute edge, the helper sees the old count on that edge. The current-nonzero term still raises a stable asynchronous level after the edge and does not need another compute clock. Once source_sticky is set, display-counter wrap cannot lower the level. The physical observation counter saturates. Both counters and the helper share common runtime reset; an independent count reset is not a permitted rearm path. Compute-clock or DDR/backend failure remains a separate platform-guard responsibility.

This phase deliberately chooses fail-closed display behavior after any upstream observation loss. A previous completed framebuffer may continue scanning, while new display publication remains unavailable until common runtime reset. Automatic recovery would need an explicit loss generation bound into every subsequently accepted frame snapshot, plus fresh-window verification; a later valid pulse alone can refer to a held tuple from before the loss.

`sim/audio/tb_workstation_display_observation_health.sv` uses the real physical observation FIFO/post-drop CDC and the real 203-bit display mailbox. It creates one final drop in each path with no following input frames, stops the corresponding source immediately, checks sticky fault and common-reset recovery while clocks are stopped, and injects a near-wrap counter seed before its normal increment to zero. The complete controlled-runtime bench also connects the output and requires it to remain zero through actual 48k/44.1k operation, I2S/PCM comparison, CPU reset and two rate switches. An independent source-edge effect-pair oracle is stored by physical epoch/sequence and checked for every received display frame, including mask/order changes at both physical rates.

Run `sim/audio/run_display_observation_health.py` with explicit prepared `--project` and a new `--output`. It runs the directed real-transport test and the complete controlled-runtime nonzero-epoch regression, recording all source hashes and rejecting source drift. An optional `--controlled-evidence` may reuse an already completed successful full regression only when every input hash still matches current bytes. This is offline verification, with no hardware, SRAM, Flash, or default profile change.
