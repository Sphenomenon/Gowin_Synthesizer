# Paired M composition

The paired provider is explicit and does not replace the independent M direct-TF candidate or a task2 profile. The maintained top remains untouched. `tools/workstation_task3_m_paired_profile.py` applies 12 exact, hash-checked, reversible stage edits; it refuses drift. After physical acceptance the exit plan is to integrate this composition into maintained top-level source and retire the stage adapter.

M retains the native 32-voice ordinary/vector engines, committed parameters, effects, final gain, selected-MCLK DAC serializer and HDMI. The remote PCM command aperture selects the existing real `workstation_ae350_pcm_owner`, with its original PCM1 contract and interpolation/history policy. The local F806 aperture explicitly errors in this profile. Clock requests from the local CPU and remote phone use one bounded arbiter before the original clock service. No second phone decoder, recording store or parameter authority is created on M.

The common paired adapter supplies actual nonzero CPU-configured boot/session/generation identities, physical LCD transport and measured-budget gate. This module cannot grant readiness. `task3_pair_record_arm` and `task3_pair_record_cancel` are explicit clk50 configuration pulses. W may also request/cancel the M tap using the bounded ch9 control lane before its existing recording object accepts START. M allocates recording generations independently and monotonically until common root reset; recording rearm does not disturb the phone session. A renewed W demand cancels a stale existing tap before a fresh ARM. The demand queue holds one request for at most one second and never holds shared RX credit. Phone rearm requires a strictly increasing common generation, and the CPU must never replay old link identities. Power-cycle restart safety additionally requires a fresh software-provided boot nonce; W maps wire recording identities to its own monotonic ingress generations.

M's native SPI/FAT/WAV owner serves both direct playback and a dedicated offline analysis pass. An analysis launch drains prior physical TF ownership, then atomically starts the existing analysis producer and the same native decoder. PCM backpressure holds that decoder rather than skipping unseen frames. Analysis bypasses physical playback and does not assert TF audio ownership. Actual file LAST releases the native reader; W recognition may continue without retaining M's media-stop grant. A stalled analysis launch fails after the existing finite quiet timeout. This initial analysis path explicitly selects stereo16 at 48 kHz, matching the current remote CNN descriptor format; unsupported input is an explicit file/ingress failure, not relabeled 44.1 kHz audio. Direct playback retains its existing 48/44.1 kHz runtime checks.

Each file reserves 65,536 consecutive task/generation IDs. FAT32's 32-bit byte size permits fewer than 65,536 chunks of 96,000 stereo16 frames. The allocator is monotonic across CPU session/configuration changes until common root reset, so delayed results cannot alias a later file. It refuses exhaustion. The 256-frame analysis producer and 2,048-note score collector preserve descriptor/PCM/seal order and require the actual final-file terminal before publishing Push guidance. Model readiness comes only from matching, fresh W status, never from link readiness. The local PC performance input remains independent of remote model loading.

The final recording tap crosses the actual selected-MCLK serializer-completion tuple to clk50. It has no ready return to the DAC. Drops, sequence/epoch/rate mismatch, overflow, link loss, cancel and committed PANIC revoke recording without stopping base samples. The 256-frame export queue is finite; the W acknowledgement must arrive before it overflows. W owns the single real recording object and download path. The remote HCI identity crosses using the existing PCM session contract; a changed identity revokes ready for at least one complete clk50 cycle. W status expires after 100 ms. Physical CDC timing, actual LCD throughput, contention and latency remain separate acceptance gates.

All typed payloads follow `task3_paired_channels.vh`. Analysis results, physical PCM observations, commands and observational status remain distinct. A normal LCD/link loss is not a fatal DDR memory fault. A changed committed runtime PANIC epoch fences remote jobs and recording. No cross-board credit enters the base audio sample schedule.

This source implementation is not physical board acceptance. Target boards are disconnected; electrical pin direction/level verification, measured LCD/Bluetooth budgets, whole-board synthesis/P&R/CDC/STA, firmware nonce provisioning and end-to-end DAC/Push/phone/TF/CNN/recording evidence are still required. Flash remains separately authorized.
