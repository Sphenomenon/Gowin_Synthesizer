# Optional stopped-compute USB event queue fence

`STOP_CLOCK_QUEUE_FENCE` is a default-zero parameter on `push2_usb_a_control` and `workstation_usb2_input`; the wrapper forwards it without adding another queue. An explicitly selected runtime composition may set it to one. Zero retains the earlier queue reset and six-compute-edge release behavior. The generated `gw138k_usb_event_fifo` bytes and the 18-bit event/lifecycle layout are unchanged.

The observed failure is a short MMIO detach/reattach or PANIC while compute is stopped. The generated FIFO asynchronously asserts its read reset, then releases it after two resumed compute edges. Its producer Gray pointer needs two synchronization edges and a third edge before read logic can use the reset zero. If reset was removed before compute resumed, that third edge can arrive after read reset has already released. Old RAM entries can then appear as queued events after a new lifecycle boundary.

When enabled, the owner drives the original FIFO reset with `input_reset || !queue_release[5]`. The existing six-edge compute release pipe holds that reset through six actual destination edges, so the synchronized producer zero is available by edge three and the read pointer remains reset through edges three to six. The generated buffered output is drained through its original read port. A second six-edge pipe begins only after the held FIFO reset falls; it keeps normal output fenced and the read port draining until read reset has released and pointer/buffer feedback has settled. Its ready level passes through the existing two-USB-edge `queue_write_release` before normal MMIO data writes can resume.

At the runtime's continuous 48MHz USB and at-most-76.8MHz compute clocks, read pointer zero by compute edge three precedes the ready level at edge twelve by at least `9 * 13.020833ns = 117.1875ns`. This exceeds the USB pointer synchronization/application budget of three USB edges (`62.5ns`) and the generated buffered-consume return path's four USB edges (`83.333333ns`). Write release then adds two USB edges. Stopping compute inside either hold or drain keeps ready low and increases this wall-clock interval. If USB itself stops or resets, that belongs to its separate USB reset/session contract; this budget does not claim recovery of an independently stopped USB clock without reset.

Control MMIO and lifecycle cancellation remain available independently of normal event writes. New note/parameter stores stall until the fence finishes, while cancellation and attach/default/barrier semantics remain those of the existing owner/session. Source-side boundaries that recur during a stopped destination restart the queue fence. The existing connection state still coalesces repeated detached/latest-attachment changes; this option does not add a new lifecycle event log or change PANIC toggle semantics. No retained note, parameter owner, stream epoch or physical sample scheduler is reset by the fence.

The directed regression uses the actual service adapter, owner, generated FIFO and session with modeled final note/volume application. It checks stopped-compute hotplug, PANIC and repeated connection boundaries, pauses again inside hold and drain, and checks actual FIFO read/write pointers, buffered-consume feedback and read-reset release at each first fresh write. The default-zero negative control must reproduce old RAM replay. The earlier complete adapter reset-isolation regression also runs with the new default-zero RTL and must retain its original metrics. Full USB enumeration, DSP, physical timing/CDC and board checks remain separate stages.
