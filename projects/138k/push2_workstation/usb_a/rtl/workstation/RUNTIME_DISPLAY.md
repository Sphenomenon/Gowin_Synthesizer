# Explicit native runtime display composition

Only `WORKSTATION_RUNTIME_NATIVE` selects this path in `workstation_hdmi_display.sv`. `workstation_profile_hdmi.sv` does not define that macro. With it absent, preprocessed HDL tokens equal the previous native HDMI composition; all original HDMI timing, scanout, arbiter, BIST and reset relationships remain. The provenance's exact reverse edits reproduce the original parent bytes.

## Top boundary

The existing `sample_valid`, `output_pcm`, `trigger_reference`, `active_voices` and `status_data` inputs are the same atomic completed-frame display tuple in `clk_50m`. Runtime-only inputs are `frame_44k1_i`, `frame_error_i`, `frame_epoch_i[31:0]`, `frame_sequence_i[31:0]` and `observation_trusted_i`. The owner must explicitly use nonzero epochs; epoch zero is rejected, never mapped. Trust must revoke on owner switch/quiesce/fault and on any upstream observation loss that cannot be detected by a later sequence gap.

`display_observation_drop_o[31:0]` is the 50MHz source-side count of the new display CDC's dropped tuples. `ddr_client_reset_no` and `ddr_client_ready_o` are memory-domain observations: respectively `ui_rst_n` and `ui_rst_n && memory_calibrated && bist_done && !bist_failed`. They do not change reset behavior. The platform owns its fail-stop guard after a DDR/video client reset or readiness loss. Video-PLL reset still resets the current DDR clients; true reset-domain separation is a separate integration stage, with accepted transactions and common epoch fencing still requiring validation.

## Atomic observation and scheduling

`workstation_display_runtime.sv` crosses one 204-bit held tuple through maintained `gw138k_stream_cdc`: trust, physical rate/epoch/sequence/error/PCM, reference, voices, status, effect mask and effect order. It also synchronizes the one-bit trust level so revocation does not wait for a later PCM packet. Metadata fields are held together rather than sampled through independent multibit synchronizers.

The mailbox has no audio ready input. Its source drop counter changes by at most one per 50MHz edge and crosses with the maintained registered-Gray counter CDC. Any destination change cancels all observation workspaces, even after the final dropped packet. The 50MHz source clock remains active independently of audio-rate switching. The reused count wraps; reaching its maximum sets a sticky source trust fault until common reset before wrap can hide loss. The physical implementation must retain held-data settling and Gray-bus timing constraints for this additional instance. Sequence gaps and frame errors independently cancel analysis.

The A07 producer performs real waveform/FFT/XY analysis in memory/UI clock and exports with explicit minor1 writer/reader. Export runs independently of raster rendering. A pending coherent reload waits until the raster lease is idle; no local-cache swap can occur during its raster or final P5 metadata write. HDMI holds that lease from renderer_start through frame_pending, which is asserted only after the final metadata DDR acknowledgment; renderer_busy/write_req and the start pulse also guard the transition gaps. The renderer runs `ENABLE_ANALYSIS=0, RENDER_ANALYSIS=1, SHARED_EXPORT=0, SHARED_RENDER=1`: its retained wave capture provides frame pacing, while displayed wave/XY/spectrum and metadata come from the validated minor1 reader. `ENABLE_ANALYSIS` selects a local FFT producer; `RENDER_ANALYSIS` independently enables the two dashboard analysis pages. Its default inherits `ENABLE_ANALYSIS`, and it is appended to the parameter list to preserve existing positional arguments. The native composition must explicitly enable rendering while keeping its duplicate local FFT disabled. No new audio scheduling dependency is introduced.

The initial raster waits for one complete current-context reader publication. Every writer start records source rate/epoch/local cancellation generation. A successful current writer completion makes a pending load eligible for a registered request; reader acceptance follows one clock later and separately checks enabled, live transaction, reader idle/loading and raster busy/start. The loss/context comparator chain ends at the request register. A context break on the acceptance edge can start at most one obsolete private-cache read: up to 365 ordered BL8 reads for one complete minor1 snapshot, with the existing single outstanding-read limit. It drains and is discarded; there is no retry of the cancelled transaction. Current-image and raster/summary eligibility still revoke immediately on source-context loss. A valid accepted loading token, enabled/live transaction, reader success and exact current rate/epoch/local cancellation generation remain necessary at completion.

Disabling revokes pending/request/loading and current local-image eligibility, and summary output is gated immediately. The export-live bit stays cancelled after re-enable until a new actual export starts, so a disabled writer tail or reader result cannot revive its old transaction. DDR request/return handling stays with the existing writer/reader owners; it can drain after re-enable. Loss at a stalled writer tail may likewise let the sealed old DDR packet drain with old tags, but cannot trigger a new raster/summary. The previous physical framebuffer may continue scanning with its existing image. A new context needs complete fresh analysis before becoming eligible. Reader failures within the same context may retain a previously validated local image.
