# Python 串口控制台

`tools/instrument_gui.py` 启动原生 Tkinter 窗口。界面负责演奏参数、预设和状态显示；UART 在独立工作线程中处理，实时音频继续由 FPGA 输出到板载 HEADPHONE。

当前控制台使用 32 个活动指示格和 8 页声部卡片，每页 4 个声部。旧版四声部外观可见 [早期离线界面](images/instrument_gui.png)，该图不代表本轮分页布局。

## 启动与连接

需要 Python 3.10+、Tkinter 和 pyserial。Windows 官方 Python 通常已包含 Tkinter；可用 `python -m tkinter` 检查。以下命令从 `Dev/Prj1` 运行：

```powershell
python -m pip install -r tools/requirements.txt
python tools/instrument_gui.py --port COM26
```

这条命令预选 COM26，点击“连接设备”才打开串口。也可用 `python tools/instrument_gui.py --port COM26 --connect` 在启动时连接。界面固定采用 115200 baud、8N1，与本工程位流一致。

本机此前验证 COM26 是可用的 B 接口；COM25 是 A 接口，PING 超时。端口列表基于系统提供的接口描述显示 A/B，不按端口号猜测，也不会自动打开其他端口探测设备。点击“刷新”重新枚举；更换 USB 插口后重新确认实际端口。若端口被占用，先退出同端口的 CLI、串口助手或另一实例。

低延迟主机更新需要退出并重新启动 GUI 进程。连接后自动在后台准备全部声部音色，显示“音色就绪 32/32”后，同一音色的起音只需一条 NOTE_ON；改换预设后点击“应用到 32 声部”重新准备。尚未就绪的槽会先确认参数，起音等待可能更长。实物调度证据与测量边界见[主机延迟说明](host_latency.md)。

连接流程依次发送 PING、PANIC、VOICE_STATUS（`0x0D`，4 个快照字节），随后同步当前总音量（`0x10`）和 LR 平衡（`0x11`）。两个输出设置分别收到成功 ACK 或旧位流的未知命令回复后才启用琴键。因此连接新会话会清除原有持音。旧位流对 `0x0D` 返回未知命令时，控制台明确提示并限制为前 4 个声部；高声部起音和参数下发会被拦截。旧位流不支持输出控制时，仅禁用相应滑块并标明“旧位流不支持”，演奏仍然可用。其他通信错误仍会结束连接。断开、关闭窗口和通信失败都会清空待发队列并尽力清音；通信失败不会自动重连或重放旧音符。退出时窗口等待工作线程结束。

未接开发板时运行：

```powershell
python tools/instrument_gui.py --offline
```

也可在未连接时勾选“离线预览”，再点击连接。离线模式显示“离线模拟”，只模拟命令 ACK、声部开关和输出设置，不访问硬件、不输出音频、不模拟真实包络尾音或模拟电平。回到硬件时先断开，再取消勾选并连接实际端口。

## 总音量与 LR 平衡

串口栏下方的输出控制作用于混音总线，与每个声部的力度和 ADSR 分开。总音量范围 0–100%，默认 100%；0% 静音，100% 为单位增益。单个声部可按自身力度和包络达到满幅，不再固定占总满幅的 1/32。声部力度滑块现在也覆盖 0–100%，原有出厂预设力度保持原值。

LR 平衡默认居中，两侧各为单位增益。向左调只衰减右声道，向右调只衰减左声道；L 100% 为仅左声道，R 100% 为仅右声道。“居中”按钮恢复左右等增益。当前合成器源为单声道，平衡在总音量之后生成独立 L/R 输出，因此 HDMI 的最终 PCM 频谱、声道峰值和结像场会反映调节结果。

每个输出滑块每 20 ms 最多提交一次最新位置，工作线程继续合并同一控制尚未发送的旧值；松键和 PANIC 仍优先。起音会立即提交仍在等待这 20 ms 定时器的设置，后来的 NOTE_ON 不越过已经排队的输出命令，且不额外等待其 ACK。显示“待确认”直到当前设置收到匹配 ACK；过期 ACK、其他连接的 ACK 和失败提交不会显示成已应用。PANIC 保留已经确认的输出值，并在清音命令之后补发尚未完成的设置。

未连接时可预先调整滑块，连接时在清音状态同步。断开和重新连接保留界面位置；输出值不跟随音色预设导入/载入，也不保存在声部 JSON 中。FPGA 在采样边界接收目标值，并逐样本平滑变化：总音量 0↔100% 和平衡 L 100%↔R 100% 最长 256 样本，约 5.24288 ms；居中到单侧最长 128 样本。ACK 表示目标值已接收，不表示平滑斜坡已结束。

混音保留全部声部的宽位求和结果，再经过总音量和平衡，最后饱和到输出范围。多音叠加超过满幅时会削波，可降低总音量保留和弦余量；没有根据当前发声音部数自动缩放的音量变化。总音量与 LR ACK 会使旧的主机/FPGA 延迟配对失效；重新读取 `0x0E` 可查看这次 `MASTER_VOLUME` / `LR_BALANCE` 的记录。其数字端点为应用新目标版本的首个输出帧，不代表平滑斜坡已结束，也不表示模拟耳机声压已稳定。

## 演奏与编辑

1. 选择“四组预设”中的一种并点击“载入”。默认“三角 · 温和起音”可与首版位流配合使用；正弦预设需要下载本轮新版位流。
2. 点击鼠标琴键，或在非输入框区域按电脑键盘 `A W S E D F T G Y H U J K O L P ; ' ]`，对应 C4 开始的连续半音；鼠标琴键覆盖 C4—C6。松开即发送 NOTE_OFF。
3. 琴键自动循环分配 32 个主机槽，优先选择最近活动状态为静音且没有主机持键的槽，再回退到未持键的尾音槽；第 33 个同时按键忽略，不抢占仍按住的键。循环游标可避免状态快照尚未更新时连续复用刚释放的槽。电脑键盘映射仍覆盖 19 个半音；要测试全部 32 声部，可逐页使用手动“起音”，或通过 CLI/协议批量控制。尾音槽被重新分配时，新版 FPGA 会保留当前相位和音量，从当前电平重新起音，避免突然截断。
4. 32 张声部卡片分为 8 页，每页 4 张，可独立选择音色和力度。始终可见的 01–32 指示格显示所有声部，点击编号会打开对应页面和 ADSR 编辑器；绿色表示主机持键且 FPGA 活动，琥珀色表示活动尾音。音高输入采用 MIDI 数字，支持小数；修改正在按住的声部音高后按回车或使用微调按钮，发送连续相位 PITCH。手动“起音”重触发指定槽；“松键”释放该槽。GUI 编号 01–32 对应协议/CLI 的 0–31。
5. 点击声部编号选择右侧 ADSR 编辑对象。修改起音 A、衰减 D、保持 S、释放 R 后，点击“应用参数”；“应用到 32 声部”发送所有卡片各自当前参数，共 192 条命令。旧位流兼容连接时按钮变为“应用到 4 声部”。曲线用于观察参数形状，改变图形本身不会生成 PCM 音频。
6. 按 `Esc` 或红色“全部清音”立即请求 PANIC。窗口失去焦点时会清音；导入/保存预设打开文件对话框前也会清音。

“载入”和“导入 JSON”先更新界面参数；点击应用后下发，或者在下一次起音前自动写入对应声部。参数可以有界流水发送，但同一槽起音必须等其先前参数全部成功 ACK；多参数应用不是同一音频帧内的原子提交。持续拖动力度或重复修改参数时，只保留同类尚未发送的最新值。

释放操作优先于待发参数，并取消该声部尚未发送的 NOTE_ON，防止松键后旧起音重新播放。PANIC 清空整个待发队列。默认队列上限为 512 条命令，足以容纳全部 32 声部参数；队列满时会明确报错。硬件连接最多保留 16 包在途，每次发送完整一包并保持至少 1.5 ms 间隔；后续就绪命令可在先前 ACK 返回前发送。释放与 PANIC 受发送间隔和窗口容量约束，并按 UART 顺序排在已派发数据之后；新演奏可在状态字节 ACK 返回前中止快照，未读完整的数据不会显示。“立即清音”不是零延迟的硬件中断。

## 四组预设与 JSON

| 预设 | 波形 | 力度 | A / D / R（ms） | S |
|---|---|---|---|---|
| 三角 · 温和起音 | triangle（0） | 20% | 5 / 120 / 100 | 62.5% |
| 正弦 · 柔和长音 | sine（2） | 22% | 18 / 180 / 250 | 60% |
| 三角 · 短拨弦 | triangle（0） | 25% | 2 / 230 / 90 | 8% |
| 脉冲 · 复古音色 | pulse（1） | 14% | 5 / 90 / 140 | 45% |

每组出厂预设将相同参数复制到 32 个声部，之后可以逐声部修改。JSON 保存 32 个声部的音色、力度和 ADSR，不保存总音量、LR 平衡、音符、串口、录音或 FPGA 配置。使用“保存预设”导出，“导入 JSON”载入。

可直接导入完整的 [32 声部正弦预设样例](examples/sine_preset.json)。该文件由项目预设模块生成并重新载入验证；硬件模式需要新版位流，离线模式可直接预览。

新格式为 `version: 2`、`name` 和含恰好 32 项的 `voices` 数组。仍支持导入 `version: 1` 的旧四声部文件：保留前四项，并按原顺序重复到其余 28 个声部，各项均为独立副本。再次保存时写成 32 声部的 version 2；新文件不能导入旧版 GUI。每个声部对象必须包含以下全部字段：

```json
{
  "waveform": 0,
  "velocity": 0.2,
  "attack_ms": 5.0,
  "decay_ms": 120.0,
  "sustain": 0.625,
  "release_ms": 100.0
}
```

`waveform` 是整数 0/1/2；`velocity`、`sustain` 范围 0…1；A/D/R 范围 0…10000 ms。名称长度为 1…80 个字符，文件最多 64 KiB；非法数值、缺失字段或未知声部字段会拒绝导入。建议由界面保存生成完整 32 声部 JSON，再按需修改。

界面“满幅 R”表示从全量程到零的释放时间；实际从松键时的包络高度下降，尾音可能更短。在稳定保持 S 时松键，图示尾音长度约为 `S × R`；D 则按从满幅降到 S 的实际时长展示。ADSR 转换为每样本整数步长，存在取整误差，曲线不是逐样本精确时序或音频测量。

## 状态与故障判断

- “已确认活动 n / 32”和全部指示格由后台约每 300 ms 读取的原子 VOICE_STATUS 快照更新。`value=0` 捕获完整 32 位活动掩码并返回低字节，接着依次读 `value=1..3`。普通 ACK 仅包含低 8 位，界面只更新声部 0–7，保留高位直到下一份完整快照；PANIC 成功确认清空全部指示。旧位流使用 PING 轮询并显示 n / 4。活动表示 FPGA 的 ADSR 非 IDLE，可能包含静音保持或释放尾音，不等于有 n 个可闻声源。DDR/视频/声部快照单字节 ACK 不会被误用为普通活动掩码。
- `ACK x.x ms` 是主机发送请求到收到有效回复的往返时间，包含串口和 USB 等等待；不是键盘到耳机的演奏延迟。
- 主机协议尚无 PCM、电平或频谱回传。界面包络是参数示意；实际 HDMI 电平来自 FPGA 内部采样旁路。
- PING 超时时先核对端口、位流及 115200 baud。COM25 超时而 COM26 成功是本机已经定位过的接口选择问题。
- 旧位流对 `waveform=2` 返回 `status=3`，工具会提示需要新版位流并结束连接，不静默降级为其他音色。下载本轮 `impl/pnr/Prj1.fs` 后重新连接。

DDR 校准、自检与显示状态目前通过 CLI 查询：先断开 GUI 的串口连接，再运行 `python tools/instrument_cli.py --port COM26 memory-status`。该命令需要本轮 DDR 位流，标志定义见 [DDR 显示说明](ddr_display.md)。GUI 尚未提供 DDR 状态面板；离线模拟也不提供硬件存储状态。

完整声部状态查询为 `python tools/instrument_cli.py --port COM26 voice-status`，输出 8 位十六进制掩码、活动数量和 0–31 的活动编号。单次 `ping` 的输出明确标记为 `active_low8`。例如 `python tools/instrument_cli.py --port COM26 note-on 31 69 --waveform sine --velocity 0.2` 控制第 32 声部；测试完运行 `panic` 清音。`--dry-run` 可以检查报文而不打开串口。

硬件音频、正弦听感与端到端延迟的验证范围见 [verification.md](verification.md)。

## 音频链路延迟检测

主窗口底部“延迟检测”打开独立窗口，显示主机计时和最近一条合法声音命令的 FPGA 记录。窗口默认每秒请求一次；只在演奏队列空闲时开始，64 个快照字节之间均检查待发演奏命令，遇到任何待发命令立即让路并丢弃半份快照。关闭窗口取消后续查询。也可取消自动查询，仅点击“读取最近 FPGA 记录”。查询不会发起新声音或改写最近声音记录。旧位流不支持 `0x0E` 时提示升级，保持演奏连接；离线模式不伪造 FPGA 计数。

主机三项计时统一使用 `perf_counter`（本机为高分辨率 QPC），按每个成功声音命令单独显示：

| 显示项 | 起止点 |
|---|---|
| 提交 → 写串口 | NOTE_ON/OFF 回调入口至调用串口写入；包含参数转换、排队和报文准备 |
| 写串口 → 完整 ACK | 调用串口写入至收到序号与 opcode 匹配、CRC 正确的完整 ACK，即原有 `rtt_ms` |
| 提交 → 完整 ACK | 同一提交起点至收到完整 ACK，等于前两项之和 |

其他参数命令默认从 `worker.submit()` 入口计时。批量提交的每条命令保留同一意图起点，依次计算各自等待时间；合并替换采用新提交的起点。后台握手和自动查询没有用户提交起点，不会被当作输入延迟。离线模式只反映主机调度和控制模型执行，并明确标为模拟；不代表串口或开发板时间。

FPGA 快照通过 `LATENCY_STATUS (0x0E)` 的 `value=0..63` 读取，索引 0 锁存完整 64 字节，其余字节从同一快照返回。界面显示收包、提交、最近一帧合成计算、首个新状态样本、对应双声道数字帧串完、NOTE_ON 单声部非零贡献样本及串完时间，以及 ACK ready/发送完成时间。每项严格依据有效标志显示；未出现的端点显示“—”，有效的零时长正常显示为零。小于 1 ms 的值用微秒显示，例如 226 拍 / 50 MHz 为 4.52 µs。

“新状态样本”表示首次采用该命令新 revision 的样本，可能仍处在零电平起音。“NOTE_ON 非零贡献”仅表示指定声部经过混音缩放及 PCM16 量化后贡献不为零；其他声部可能相消，因此不能据此认定最终混音非零或已听到声音。数字输出终点是对应双声道帧最后一位的 BCK 上升沿，未包含 PT8211 模拟转换/滤波、耳机或声学传播。

只有当前连接最近一次成功声音 ACK 的序号、opcode、voice 和本地主机声音代次均与查询关联时，才显示“输入 → 数字输出”区间。每次成功声音 ACK 都递增本地代次，防止 8 位序号回绕后误匹配旧快照；新声音命令会立即使旧区间失效，旧 FPGA 阶段数据保留并标为“历史记录”。记录过期、端点缺失、ACK ready 无效或边界矛盾时不计算总延迟。

令 Q 为主机“提交 → 写串口”，H 为“提交 → 完整 ACK”，D 为 FPGA“UART 首同步起始位 → 数字输出端点”，A 为 FPGA“UART 首同步起始位 → ACK ready”。显示的范围为 `[Q + D, H − A + D]`。USB 去程和回程无法分别测得，不能把完整 RTT 与 FPGA 耗时直接相加并称为精确单程延迟。NOTE_ON 优先采用非零贡献帧串完端点，尚未到达时可采用新状态帧串完端点，并明确标注“可能仍为零”。

CLI 查询前先断开 GUI 的串口连接：

```powershell
python tools/instrument_cli.py --port COM26 latency-status
python tools/instrument_cli.py --port COM26 latency-status --json
python tools/instrument_cli.py --dry-run latency-status
```

CLI 保留原始时钟拍数及换算时间。单独查询没有原命令的主机提交时间，所以不报告输入到输出总延迟。完整读取包含 64 次停等事务，115200 baud 的纯报文传输约 111 ms，USB 和调度会增加耗时；GUI 会在字节之间让出演奏请求，不将整个读取作为不可打断批次。

## 声部起音检测

“延迟检测”窗口默认打开声部起音页：选择0…31声部，查看触发→PCM贡献和触发→DAC帧发送完成的时间，以及首次触发/活动声部重触发、等待/完成/测量取消等状态。32行表格是各槽最近查询的缓存，自动查询只更新选中槽；演奏命令优先。松键和参数调整不会抹掉已完成结果，同槽下一次NOTE_ON开始新记录。

“全链路0x0E”页保留原主机排队、串口及FPGA阶段和单程区间检测。两个页的记录用途不同；声部起音测量从FPGA提交开始，不能直接当作电脑键盘到模拟耳机的总时间。数字端点、功放启动静音、缺失值及CLI详见[声部起音说明](voice_onset.md)。
