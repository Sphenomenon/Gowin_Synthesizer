# DDR 画面中的音频反馈

`feedback_renderer` 向 DDR 后台帧缓冲顺序写出 1920×1080 像素。HDMI 扫描时钟和帧缓冲切换由显示/存储层负责，音频观察接口没有背压。2026-09-09 起，所有音频图来自 PT8211 最终串行 PCM 解码；新增双声道 FFT 和 MID-SIDE 结像，详见[输出分析](output_analysis.md)。

## 和弦显示规则

用户确认 16:20 的最低音 DDS 参考版仍有和弦抖动，并选择“整段匹配时更新，未匹配时保持并显示 HOLD；换音后重新捕获”。当前显示采用此规则：

1. 捕获 1024 个连续最终 PCM 的 M=(L+R)/2 样本（转为 Q1.31），在其中搜索全部 513 个长度为 512 的窗口。
2. 每个窗口的全部 512 点与上一次显示曲线比较。在 `sample >>> 23` 数值域，平均绝对差不超过 **4 单位**才接受。新布局纵向为 128 像素/满幅，相当于约 **2 屏幕像素**；旧 256 像素布局相当于 4 像素。取误差最小的窗口，平分时取较早者。门限限制整段平均误差，不是每点最大误差。
3. 接受时原样复制该窗口的 512 个 Q1.31 样本，显示 `TRIGGERED`。失配时保留全部旧曲线样本，显示 **`HOLD / WAITING FOR MATCH`**，继续等待下一次采集。
4. 首帧、演奏参数版本变化或完整采集块全零时直接建立新模板。换音、松键、变调、力度、音色、ADSR 参数和 PANIC 均触发重新捕获；PING 和诊断查询不会解除 HOLD。

匹配只决定是否更新显示，不平均波形、不修改任何发声相位或音频时钟。不同音高和弦可能长期没有满足门限的新窗口，此时 HOLD 持续显示，这是所选正常触发模式的行为。HOLD 期间 FFT、结像、左右峰值和状态仍按各自的新采集块刷新，它们与保留曲线的时间不同。释放尾音可能先被保持，完全静音后自动显示平线。

## 实际显示的量

- 波形：被接受窗口的 512 个连续最终 PCM 的 M 样本。采样率 48,828.125 Hz，显示窗口 10.48576 ms；每点横向两像素，相邻点画连接线，纵向约 128 像素对应幅值 1。HOLD 时显示上次接受的窗口。
- L/R 峰值条：最新无触发分析块的左右 PCM16 绝对峰值，跨度 20.97152 ms，包含 −32768；线性幅值，无结像自动增益，不是 RMS 或峰值保持。波形匹配仍使用其自身触发块的 M 峰值判断静音。
- 32 VOICES：最新采集块末尾的完整 32 位声部活动状态，包含尚未结束的释放尾音，不是每声部独立电平。底部两行各 16 格，第一行编号 01–16、第二行 17–32；对应协议声部 ID 0–31。绿色表示活动，灰色表示空闲。
- 32 格活动状态来自同一完整 32 位快照，最低位对应编号 01，最高位对应编号 32。新布局用格子显示，原 ACTIVE MASK 十六进制行让位于分析面板。
- IO ERRORS：最新采集块末尾的诊断字，高 16 位为音频欠载计数低 16 位，低 16 位为 UART 错误计数低 16 位，不是 ACK 返回码。
- MEM STATUS、UNDERRUNS、FRAME：帧开始时锁存的存储状态、扫描缺行计数、已完成后台写入帧计数。FRAME 不是 HDMI 刷新率。MEM STATUS 位定义见 [DDR 显示说明](ddr_display.md)。
- 页脚 BLOCK / DROPPED：无触发立体声分析块序号及该捕获器缓冲满时跳过的观察点数，32 位自然回绕，不代表音频丢样。HOLD 时继续更新。

频谱是独立 L/R 1024 点 Hann FFT，结像是同一未加窗块的 MID-SIDE 点图；没有 RMS。波形触发块和分析块的起点不保证相同，HOLD 明确标识保留曲线。

## 模块和存储

| 文件 | 职责 |
|---|---|
| `src/synth/synth_engine.v` / `synth_voice_bank.v` | 共享声部扫描累计最低音 DDS 参考；与混音样本对齐发布参考和演奏参数版本 |
| `src/video/feedback_capture.v` | 50 MHz 触发、两组 1024×32 RAM、跨时钟所有权、峰值/元数据；独立模块默认 512 点，由 renderer 配置为 1024 |
| `src/video/feedback_wave_align.v` | 100 MHz 整段窗口搜索、4 单位平均误差门限、独立 512×32 显示 RAM、HOLD 和重新捕获 |
| `src/audio/pt8211_observer.v` | 最终输出双槽 PCM 解码、同帧触发参考 |
| `src/video/output_audio_capture.v`, `output_audio_analysis.v` | 独立两组 1024×32 立体声 RAM、双 FFT、对数频带峰值、结像和左右峰值 |
| `src/video/feedback_dashboard.v` | 四段可停像素流水、文字/波形/频谱/结像/状态、32 个声部指示 |
| `src/video/feedback_renderer.v` | 等待匹配与分析完成、帧级快照、显示 RAM 读、双像素顺序流及背压 |

采集侧发布完整银行后保持内容及元数据，匹配和整帧渲染期间不可写。另一个银行并行等待触发并采集下一块，完成后等旧银行归还再发布。跨域同步请求/确认 toggle，`held_*` 多位元数据在握手期间保持，接收域额外等一拍稳定；采集 RAM 分别使用源时钟写和渲染时钟同步读。新增 `held_revision` / `snapshot_revision` 受现有 held→snapshot 最大延迟约束覆盖。

匹配器每点使用读/累计两拍，非负误差累计超过当前最佳完整分数后可提前结束该候选；这是精确剪枝，不会跳过更好的结果。18 位分数可容纳最大 `512×511=261632`。完整搜索为 `513×512×2=525312` 周期，接受后复制另需 1024 周期，加状态切换总计小于 530000 周期，在 100 MHz 下小于 5.3 ms。仅匹配器空闲时渲染器才读显示 RAM，HOLD 分支没有 RAM 写入。

## 采集触发和换音

`synth_voice_bank` 依次读取 32 个声部在当前音频帧开始时的状态，发声资格为活动且包络/力度非零。共享扫描过程中选择步进最小的非零频率声部，同音高取编号最小者；`synth_engine` 依据相邻帧所选参考声部的相位判断回绕。这条观察路径不改变振荡器相位。32 位 `trigger_reference` 布局：

| 位 | 含义 |
|---|---|
| 0 | DDS 参考有效 |
| 1 | 参考声部周期起点 |
| 7:2 | 参考声部编号 |
| 31:8 | 24 位演奏参数版本，自然回绕 |

成功提交的声音命令 `0x01..0x0A`、总体音量 `0x10` 和L/R平衡 `0x11` 使版本递增，即使数值与前次相同也重新捕获；无效命令、PING、内存/视频/声部诊断不递增。共享扫描完成后，版本与相位标记随对应混音样本一起发布，严格对齐 `sample_valid`；采集模块不依赖旧并行引擎的固定五拍延迟。现在该标记继续经过 PT8211 待发/在发寄存器，随实际双槽 PCM 解码输出后才进入波形捕获器。声部参考变化时先建立相位历史，再等待真实回绕。

采集中版本变化会取消尚未完成的块、清峰值及写索引，并等待新版本触发，避免一个模板拼入两次演奏的数据。已完成或已发布银行保持不可变，忙碌时已经排队的旧快照可能先显示，随后完整的新版本快照会替换模板。

有 DDS 参考时只接受其周期起点，忽略混音过零。无有效参考时先观察到样本 ≤ `-0x00100000` 才武装，随后首个非负有效样本成为第 0 点。历史只在 `sample_valid` 更新，双缓冲忙时也消费已发生的边沿，恢复后等待新事件。触发等待不计入块峰值或 OBS DROPPED。

无活动声部且样本为零时立即开始平线采集。其他无触发情况在第 8192 个有效等待样本自动开始（约 167.77 ms，再采集余下 1023 点约 20.95 ms）。参数 `TRIGGER_TIMEOUT_SAMPLES` 默认 8192，设 1 为立即自动采集，供独立 RAM 所有权测试使用。该超时只保证继续采集和更新状态，不强迫接受失配曲线。

## 渲染与刷新率

接口为 `start/frame_ready/busy/frame_done` 与 `pixel_valid/pixel_ready/pixel_data[63:0]`。匹配及 FFT/结像均完成后才置 `frame_ready`；在 `start && frame_ready` 时接受新帧。低 32 位是偶数 x，高 32 位是 x+1，各自低 24 位为 RGB888、高 8 位为零。每点占两像素，同拍两个像素共用一个显示 RAM 地址。

RAM 同步读与 dashboard A/B/C/D 组成五段流水，数据、valid、last 使用相同使能。背压期间地址、像素数据、坐标和结束标志保持。字体从原 `video_font_5x7` 输出完整 35 位字形，按固定行列取位，稳定吞吐为每周期两个像素。

32 个声部指示沿用波形区的 1024 像素宽度，槽宽 64 像素，正文使用 01–32 两位编号；新布局右侧放置结像和诊断。列索引直接取横坐标位段，行索引用纵坐标比较得到，不引入除法器。每条像素流水只寄存当前格选中的活动位，避免为两条流水重复寄存整份 32 位状态。32 格使用原有编号逻辑；分析布局将波形高度减半，匹配数值门限和 HDMI 光栅时序保留。

最后一个 beat 被写入器接受时释放两套采集银行和分析结果并结束渲染；最后 16 个像素已在写入器本地打包寄存器中。DDR 发布仍由 `ddr_frame_writer` 等待最后原生写命令/数据握手完成，再置 `frame_pending`，扫描器于垂直消隐换帧。

每帧 1,036,800 个双像素 beat，无背压光栅渲染约 10.36805 ms；匹配发生在渲染之前，下一块采集可与当前渲染并行。**1024 点采集每块约 20.97 ms，持续新画面上限约 47.7 帧/s**，实际还受触发等待、匹配、DDR 服务和帧缓冲交接影响。HDMI 光栅仍固定 **60 Hz**，没有新后台帧时重复完整前台帧。HOLD 时仪表盘仍更新，曲线接受次数可能远低于新画面次数。早期 512 点版约 60 个新画面/s 的实测不能套用到本版。

双银行均占用时只丢弃显示旁路观察点，音频继续运行。显示暂停时保留已经采集的块，恢复前两帧可能来自暂停期间。源、DDR 用户和像素观察域复位共同断言、各域同步释放；失锁取消采集所有权、显示模板和在途帧，不能复用旧 valid/last。音频/UART 使用独立系统复位。

## 验证和预览

- `tb_feedback_wave_align`：偏移 184 的最佳真实窗口、Q1.31 低位保留、4 匹配单位门限接受/5 单位拒绝、非稀疏点差异、HOLD 逐字不变、版本重捕获、全零、正负满幅及最坏搜索时长。
- `tb_feedback_stable_display`：显式配置四声部的共享引擎和真实四音和弦、每 1024 源时钟一个音频样本，经 1024 点 capture、匹配器和 renderer；要求每个采样周期恰好完成一次混音，核对显示 RAM 是同版本连续混音历史、HOLD 逐点不变、换音重捕获及完整光栅。协议测试缩小为 128×800，每帧 51200 beat；32 个声部灯和完整 1080p 像素分别由以下用例和预览补充验证。
- `tb_feedback_polyphonic`：独立 DDS/版本参考核对 9012 个样本、9 个原始快照、5 次参考切换，覆盖错开发音的 C4/E4/G4/C5、变调、不同音色、静音、释放、重触发、PANIC 和复位。
- `tb_feedback_trigger` / `tb_feedback_capture`：过零回退的 18 帧用例、滞回、无效输入、静音/直流、超时、双缓冲、满幅峰值、观察丢弃及复位。
- `tb_feedback_renderer`：DDS 参考连接、双像素次序、波形坐标、随机背压、帧级状态及末拍握手；1088×970 光栅覆盖全部 32 格，检查 `80010005` 活动掩码穿过实际 capture/renderer 后的像素，渲染期间改变源状态不得撕裂快照。
- `tb_feedback_dashboard`：遍历 32 个 one-hot 掩码，逐一确认仅相应格点亮；检查全部 01–32 两位十进制编号、八位十六进制活动字、格间距、HOLD 字形及 256 个字形的流水等价性。`tb_feedback_capture` 同时以覆盖最高位的互补掩码检查跨时钟元数据保持。

在装有 Icarus 的环境（本机 WSL）运行：

```sh
python3 scripts/run_tests.py
python3 scripts/render_feedback_preview.py --analysis
python3 scripts/render_feedback_preview.py --analysis --hold
```

`--analysis --hold` 先绘制曲线，再送入左右 +0.5 恒定块，逐点检查旧曲线保留、左右峰值更新为 PCM16 的 16384、结像清空并重画为新的直流点、HOLD 标题及完整光栅。输出 `build/feedback_preview/feedback_analysis_hold.png`。早期 32 声部归档在同一夹具中注入活动掩码 `80010005`，核对编号 01、03、17、32 点亮及完整掩码显示：[正常触发预览](images/feedback_32voices.png)、[HOLD 预览](images/feedback_32voices_hold.png)。这些图来自实际 RTL 像素，音频和 DDR 状态是测试夹具，不能当作板测截图。

当前[分析正常预览](images/feedback_analysis.png)、[分析 HOLD 预览](images/feedback_analysis_hold.png)增加独立左右 PCM 夹具，逐点检查 HOLD 保留波形而结像更新为新块。FFT 参数和限制见[输出分析](output_analysis.md)。
