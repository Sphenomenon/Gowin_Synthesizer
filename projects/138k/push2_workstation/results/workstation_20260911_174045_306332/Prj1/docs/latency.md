# 键盘输入到音频数字输出的延迟检测

GUI默认“声部起音”页和CLI `voice-onset`使用独立的0F记录：32声部各自保留最近NOTE_ON结果，松键后仍可查询。使用步骤与字段见[声部触发到数字发声检测](voice_onset.md)。本页说明“全链路0x0E”页的单条声音命令记录与主机时间关联。

主机当前采用有界异步收发与 `perf_counter` 高分辨率时间，旧截图的 16/31 ms 受粗时钟量化影响。真实串口 RTT 仍约 17 ms，但不再逐包阻塞后续就绪演奏。实测、音色预加载与重新启动步骤见[主机低延迟说明](host_latency.md)。

本轮检测从GUI按键回调、主机队列和串口事务，延伸到FPGA命令提交、样本计算以及PT8211双声道最后一位串行输出。计时电路只观察事件，不注入测试音、不修改演奏参数，也不改变32声部的226拍计算调度。

主机与FPGA没有同步时钟，所以界面分别给出主机时间、FPGA时间和可推导的输入到数字输出区间。区间不是把ACK往返时间加上FPGA时间得到的单程“实测值”。耳机DAC/功放/声学传播以及物理按键到操作系统回调的时间未测量；HDMI画面延迟本轮未加入。

## 使用

在更新位流、复位并重新连接GUI后，打开“延迟检测”窗口并选“全链路0x0E”页，演奏一个音符并保持片刻，读取最近一次声音命令的测量。

```powershell
python tools/instrument_gui.py --port COM26
python tools/instrument_cli.py --port COM26 latency-status
```

CLI仅查询最近记录，不自动演奏。关闭GUI串口连接后才用CLI访问同一端口。旧固件返回未知opcode时，GUI提示需要延迟检测位流，演奏连接继续工作。离线模式只显示本地主机处理信息，拒绝FPGA延迟查询，不伪造硬件计数。

完整查询含64个串口事务，115200baud下线路时间约111ms。GUI仅在检测窗口打开时低频查询，快照只保持一个索引在途；有新前台命令即中断并丢弃半份快照，演奏无须等该索引 ACK 才发送，晚到 ACK 只回收不发布。查询本身不覆盖声音记录。

## 测量端点

| 阶段 | 定义 |
| --- | --- |
| GUI排队 | NOTE_ON/OFF回调入口的单调时间，到实际`serial.write`入口；普通控制从提交队列入口计时 |
| 串口往返 | 同一次写入入口，到收到sequence/opcode匹配且CRC正确的完整ACK |
| 主机提交到ACK | 同一意图起点，到完整ACK；等于排队加往返 |
| FPGA请求收包 | 首个有效A5字节的同步后start bit检测，到最终CRC接受 |
| 等待提交 | CRC接受，到合法声音命令在音频帧起点锁存 |
| 计算 | 最近音频帧起点，到总体音量/平衡后的样本事件；当前32声部234个50MHz时钟（核心引擎仍226） |
| 首个新状态样本 | 首次携带本次命令新revision的样本产生事件 |
| 音符数字贡献 | 仅NOTE_ON：目标声部独立贡献经总体音量后，在至少一个声道量化为PCM16首次非零的样本事件 |
| 新状态双槽完成 | 对应新revision样本的左槽最后一位在BCK上升沿输出完成 |
| 音符双槽完成 | 携带上述目标声部非零贡献标签的PCM帧，左槽最后一位输出完成 |
| ACK就绪/完成 | 回复被UART发送器接纳；以及完整8字节ACK最后停止位结束 |

FPGA统一使用50MHz、32位自由运行计数器，分辨率20ns。UART起点是两级同步后的检测时刻，晚于管脚实际沿约2～3个系统周期。RX在末字节停止位中心验证，因此“收包完成”不是整个停止位结束。ACK完成则明确等待最后停止位全部发送完。

当前音源在提交帧N仍计算更新前状态；N+1样本才采用新状态。空闲声部NOTE_ON的N+1包络仍为零，通常N+2或更晚才有PCM贡献，因此不能以ACK或N+1的标签直接宣称开始有声。力度为零、零频率正弦、缓慢包络等可能长期没有有效贡献，未到达端点显示为空。NOTE_OFF的新状态样本也不代表释放尾音已经结束。其他声部发声不能替代目标声部的贡献；多声部混音可能抵消，独立贡献非零也不证明耳机可闻。

## 输入到数字输出区间

只关联同一连接、同一个本地主机声音事务与其FPGA记录。最近记录会被下一条合法声音命令替换，包括总体音量10和LR平衡11（记录渐变开始后的新版本首样本，非渐变完成）；PING、诊断、CRC错误和非法参数均不替换。主机8位sequence会回绕，关联同时要求本地事务代次一致，不能把旧快照匹配到新的同序号按键。

设Q为回调到串口写入，R为串口往返，A为FPGA首start到ACK就绪，D为同一首start到所选双槽输出端点，全部换算为毫秒。未知的USB/驱动去程耗时F满足`0 <= F <= R-A`，因此：

```
下界 = Q + D
上界 = Q + R - A + D
```

这利用同事务ACK提供保守界限，未假设去回程对称。使用ACK就绪而非最后停止位结束，避免主机UART在停止位中点已完成解码时出现错误的负回程假设。记录不匹配、缺少有效阶段、已过期或区间不自洽时不计算区间。时间换算基于标称50MHz，未校准板载晶振频偏。

## 0E诊断快照

请求仍为12字节、回复仍为8字节；`opcode=0E, voice=FF, flags=0, value=0…63`。index0在采样帧起点锁存64字节原子快照并返回byte0，后续索引返回同一副本。非0查询前必须先读0；非法index/flags或无快照返回status3，非法voice返回status2。

| 小端32位字索引 | 内容 |
| --- | --- |
| 0 | byte0=schema1，byte1=sequence，byte2=opcode，byte3=voice |
| 1 | 阶段有效标志，见下方 |
| 2 | trace_id，每次合法声音命令递增 |
| 3 | clock_hz，当前50000000 |
| 4 | 首start→CRC接受，周期数 |
| 5 | CRC接受→命令提交 |
| 6 | 命令提交→首个新状态样本 |
| 7 | 命令提交→NOTE_ON目标首次有效PCM贡献样本 |
| 8 | 命令提交→新状态双槽完成 |
| 9 | 命令提交→NOTE_ON目标贡献双槽完成 |
| 10 | 首start→ACK就绪 |
| 11 | 首start→ACK完整发送结束 |
| 12 | 最近一帧计算周期数 |
| 13 | 最近相邻音频帧起点间隔 |
| 14 | 快照时刻距本记录首start的周期数 |
| 15 | 尚未完成数字输出阶段即被下一声音命令替换的累计次数 |

字1：bit0=有效声音记录；bit1=新状态样本；bit2=NOTE_ON贡献样本；bit3=新状态双槽完成；bit4=NOTE_ON贡献双槽完成；bit5=ACK就绪；bit6=ACK完整发送结束；bit7=记录过期。高位保留为0。**有效位独立于周期数，0周期也可为有效测量。** 各端点只锁存第一次，后续同revision样本不覆盖。

计数按模2^32相减，跨一次回绕仍正确；记录年龄达到2^31周期（约42.95秒）后锁存过期标志，防止旧记录在再次回绕后看似新记录。过期标志到下一条合法声音命令或复位才清除。一次只保留最近声音记录，未实现逐事件日志FIFO。

硬件实现分布于`src/control/uart_rx.v`、`uart_tx.v`、`uart_control.v`的传输时间点，`src/synth/`的命令/样本标签，`src/audio/pt8211_tx.v`的真实消费和双槽标签，以及独立的`src/diagnostics/audio_latency_monitor.v`。观测数据不会驱动声部或DAC的数据与控制路径。
