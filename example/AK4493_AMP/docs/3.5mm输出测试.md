## 隔离模式出现周期性噗嗤与断音

用户反馈仅一边发声，约在有声的 3 秒段内出现 9 次噗嗤；噗嗤在静音段也存在，且会打断正常声音。随后确认是右耳、三段 TRS 插头，并表示直接将 SHUTDOWN 拉高。用户也确认“左右输入、反馈电阻均已补齐”，因此不再把原图缺少反馈当作当前实板已确定的故障。拉高节点、具体电压、是否断开原检测支路没有取得明确说明；用户认为这里应无问题。

连续三组 JTAG 报告为 `../reports/jtag_3p5mm_pops_0.json` 至 `_2.json`。共六个捕获点跨约 73.64 秒，帧计数和音频时钟计数按预期推进，所采样的 PDN、restart_n 为高、SMUTE 为低。跨采样间隔计算音频时钟约 12.287945MHz、帧率约 48kHz；未看到反复复位或明显停止的证据。汇总见 `../reports/headphone_pops_digital_summary.json`。这是稀疏的内部捕获，不能排除短暂的物理时钟、子板供电或使能异常；Bank5 电源监测也不是 U4 供电监测。

MAX9722 官方手册第 11 页说明：SHDN 低会关闭耳放和电荷泵，电源低于 UVLO 门限会停止工作，持续过热保护可能产生脉冲式输出。这些只是需要区分的机制，不是本次已确认根因。

为区分是否与播放/静音切换有关，新增 `CONTINUOUS_TONES=1`：warmup 后左 1kHz、右 1.5kHz 持续播放，保持 −42dBFS，不再周期切换声道或插入静音。标准、隔离、连续三种模式的 I²S 解码仿真均通过；连续模式额外检查所有稳定样本按 96 帧周期精确重复，跨原切换窗口没有断点。报告为 `../reports/simulation_continuous.json`。

构建 `../reports/build_20261024_024209_479935.json` 的 setup/hold 检查通过，综合确认 `CONTINUOUS_TONES=1`。SRAM 下载通过，UserCode `0x13802402`，证据为 `../reports/sram_radio_20261024_024255_334804.json`。`../reports/jtag_3p5mm_continuous.json` 捕获有效，内部音频时钟约 12,287,946.68Hz、帧率 47,999.98Hz，phase 恒为 3、PDN=1、SMUTE=0。

## 下一步：关联噗嗤与耳放供电，再定位左声道

先用同一副耳机在其他音源确认左右，或换已知正常的三段 TRS 耳机对比。示波器 DC 耦合，两路均对音频板 GND，约 100ms/格观察：

| 测点 | 预期与用途 |
| --- | --- |
| C85 非地端 / U4.3 PVDD | 约 +5V，观察噗嗤时是否跌落；此处来自独立 U9，CN 扬声器成功不证明这一路正常 |
| C92 非地端 / U4.7 PVSS | 电荷泵负电源，正常工作时通常接近 −PVDD，观察是否随噗嗤回零或反复启动 |

PVDD 若同步跌落，沿 U9 输入/输出及耳放负载查供电；PVDD 稳定而 PVSS 崩落时，查 SHDN 实际波形、飞跨电容 C88、储能电容 C92、PVSS/SVSS 接点及负载。二者稳定时，再对照 U4.2 与输出波形，区分使能变化、保护或模拟信号本身的异常。以上为判定路径，尚未取得本轮供电实测，不能据此宣布电荷泵或某个器件损坏。

左声道沿 C90 靠继电器一端（新增输入电阻之前）→ U4.14 OUTL → 插座左声道触点追踪；右声道对应 C91 → U4.12 OUTR。连续镜像下上游应分别有 1kHz / 1.5kHz。若 OUTL 有音而插头左触点无音，定位连接器和走线；若上游左信号有而 OUTL 无，再核查左声道焊接、反馈连接和 U4。闭环反相输入端接近虚地，不能因 U4.16 交流波形很小就认定输入信号丢失。
