# W-DEMO 手机音乐入口：源码与构建验证

日期：2026-10-31（Asia/Shanghai），包名 `cn.gowin.control`。本记录保留初始 `0.3.0-demo-d1`／`versionCode 14` 的来源与验证，并记录最终 `0.3.0-demo-d2`／`versionCode 15` 的能力页修正及独立 APK 身份。本阶段增加手机真实媒体入口，保留既有 BLE 录音对象和可靠下载路径；设备端 W-DEMO 候选另行验证。

## 实现范围

- “音乐”页通过系统 SAF 选取 `audio/*`，使用 `MediaPlayer` 异步准备文件、播放、暂停、定位和获取进度；不向 BLE 发送音频，也不新增报文编码。
- 媒体播放由 Android A2DP 路由发送。页面分别报告可用 A2DP 设备和 `MediaPlayer.routedDevice` 的实际输出；BLE 已连接不等于媒体音频已连接。
- 无 A2DP 输出时禁止开始播放；开始后两秒内未取得实际 A2DP 路由则暂停。媒体设备断开或路由丢失后暂停，并报告原因。
- 切换 App 内控制、录音、作品和音乐页面时，音乐可继续播放，便于边听边操作同一 W 候选的参数和录音下载。App 进入后台或丢失音频焦点后暂停；本阶段没有后台媒体服务。
- 来源音乐和本地录音试听互斥；原 BLE 服务、协议依赖方向、录音 CRC、持久化检查点和恢复路径保持原有职责。
- 文件读取仅使用 SAF 授权，不申请所有文件、媒体库或麦克风权限。

## 验收边界

### 初始 demo-d1 模拟器 UI／SAF 实测

独立设备 `dual138k-demo-d1`，序列 `emulator-5580`；Android 15／API 35、Google APIs ARM64 image revision 9、Emulator 37.2.13.0，1080×2400。使用原生 ARM64 与 Hypervisor.Framework；以无窗口、无音频、2 GB RAM／2 cores 启动，没有安装到连接的真实手机。

对上述同一 SHA256 的 APK 实测：

1. 冷启动，控制／录音／作品／音乐四页可访问；“音乐”页显示“蓝牙媒体未连接”。
2. 通过系统 SAF Downloads 选择真实 WAV，界面显示文件名和 1 秒时长。系统媒体服务确认 `cn.gowin.control` 的播放器处于 `state(4)`（PREPARED）、`renderer(null)`，并实际打开所选文件；系统 URI 权限记录为持久读授权 `persisted=0x1`。
3. 无 A2DP 时“播放到蓝牙”按钮显示禁用；点击其可见位置后仍为 PREPARED／无 renderer，没有启动模拟器扬声器播放。
4. 依次切换录音、作品、控制再返回音乐，文件及准备状态保留；退到系统主页再返回也保留。此次没有真实 A2DP 播放，不能据此宣称已验证播放中的页面持续性或后台暂停。
5. “连接蓝牙媒体音频”打开系统 Connected devices 设置；返回 App、打开更换文件后取消，原文件及准备状态保留。
6. App PID 全程为 3073，App crash 缓冲为空，进程退出记录无崩溃。独立 `uiautomator dump` 曾与 Android CLI 已运行的 UI instrumentation 冲突；该工具的 PID 4500 异常保留在原始 crash 日志，随后使用 Android CLI UI 树与截图核验，不记为 App 崩溃。

### 待实物验证

本记录确认源码、协议／BLE／数据回归、调试 APK 构建和以上模拟器检查。模拟器不能证明 A2DP 无线、138K SBC 解码、真实 DAC／HDMI 声画或与 BLE 录音下载并行时的连续性。

真实手机与同一 W-DEMO 位流需要共同验证：系统连接 138K 的媒体音频、选取真实音乐并从实际 A2DP 路由播放、25K 调参后的声音和画面一致、CPU 与 BLE 访问同一个录音对象、持续声画下完整下载及独立 WAV 校验。单板分时验证不等于双板并发验收。原 [0.1.0 验证](VALIDATION.md) 和 README 中的 0.2.10／25K 证据保留各自历史范围。
