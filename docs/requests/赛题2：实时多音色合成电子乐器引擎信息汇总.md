## 1. 赛题目标与指标

设计一套以 FPGA 为核心的实时多音色合成电子乐器。自主设计交互方式，采集演奏动作，在 FPGA 中逐音、逐样本实时合成，经 I2S 输出至 DAC 发声。

### 基础要求

| 项目 | 完整要求 | 来源 |
| --- | --- | --- |
| 交互形态 | 可采用电容触摸、光电感应、压力检测、无接触手势等自主设计方案，精准采集选音、和弦、触发、拨弦、力度等演奏指令，交互灵敏、稳定，适配演奏场景 | 指南正文第 13 页，PDF 第 15 页 |
| 独立控制维度 | 至少 **2 个独立可控演奏维度** | 同上 |
| 合成实现 | 完整音频生成通路全部基于 **FPGA HDL 硬件逻辑**，逐样本实时计算；可采用波表采样、加法合成、FM 调频、物理建模等合规算法 | 同上 |
| 基础复音 | **≥4 路独立声部同时并发发声** | 同上 |
| 声音控制 | 支持单音实时变调、ADSR 包络调控、多声部实时混音 | 同上 |
| 基础延迟 | 控制信号到音频输出总延迟 **≤10 ms** | 同上 |
| 输出 | 通过 **I2S 接口输出至 DAC** 解码发声 | 同上 |
| 禁止行为 | 直接播放预录 PCM 音频、预置推流、整段录音触发。输出声音必须由 FPGA 根据实时演奏指令逐音、逐样本生成 | 同上 |

### 拓展要求

| 方向 | 要求 | 来源 |
| --- | --- | --- |
| 大规模合成 | 复音数 **≥32**，**或**单音加法合成分量 **≥32 路**，**或**多条并行物理建模运算单元，发挥并行优势、提升振荡器吞吐量 | 指南正文第 13—14 页，PDF 第 15—16 页 |
| 多维表情 | **≥3 维**演奏表情调控，支持力度动态、滑音、颤音等 | 同上 |
| 多音色 | **≥2 种乐器音色**自由切换 | 同上 |
| 硬件效果器 | 在 FPGA 内实现混响、延迟、合唱等数字音频效果 | 同上 |
| 低延迟 | 演奏延迟 **≤5 ms**，且确定性、无抖动 | 同上 |
| 可视化 | 由 FPGA 硬件逻辑实时生成 LED 演奏指引、李萨如图形、实时频谱、波形显示等视听反馈 | 同上 |
| 脱机演奏辅助 | LED 曲目指引，辅助规范演奏节奏 | 同上 |
| 手机联动 | 可搭载蓝牙，与 App 实现在线曲谱下载、键位自定义、演奏录音回传等 | 同上 |

## 2. 振荡器、复音、吞吐量与现场验证

| 问题 | 指南要求或表格答复 | 来源与确定程度 |
| --- | --- | --- |
| 独立振荡器如何定义？ | 包含独立相位累加器、频率调控、包络控制的完整独立发声单元 | 指南正文第 14 页 |
| 不同算法如何统计？ | 单波表查表只计 1 个振荡器，不按波表所含谐波数量累加；加法合成按运算分量、FM 按调制运算器、物理建模按并行弦/模态单元统计 | 指南正文第 14 页 |
| 核心吞吐量指标是什么？ | **同时活跃可闻独立振荡器总数 × 实际音频输出采样率**；过采样不叠加加分 | 指南正文第 14 页 |
| 必须每个振荡器各占一套物理电路吗？ | 不必。一个音频采样周期内完成各独立振荡器运算，可以时分复用；允许分组并行、组内复用 | 技术 #101、#102、#109（第 63、64、71 行） |
| 4-lane TDM 每周期轮询 32 个 voice 怎么算？ | 若 32 个 voice 各有独立 phase、FCW、ADSR 状态，原表明确回答算 **32 个** | 赛事 #77（第 82 行） |
| 一个采样周期计算 128 个算子并混音可以吗？ | 表格答复认可这种高速时钟轮询方案 | 技术 #101（第 63 行） |
| 同一按键的失谐分量、复音数与单音加法分量乘积 ≥32 可以吗？ | 对该组合方案原表回答“可以的”；仍须满足独立、活跃、可闻等统计条件 | 赛事 #75（第 80 行） |
| 4 声部 × 每声部 4 个 FM 算子，是 16 振荡器还是 4 声部？拓展 ≥32 到底数什么？ | 回复是“我记得应该是按照振荡器数量是可以的”，并表示做 32 声部也合规。该答复未严谨拆解 16 个算子的可计入条件。应分别报告声部数与算子数，不能把它当成取消基础 ≥4 独立声部的正式解释 | 技术 #108（第 70 行），经验判断 |
| FM 调制器是否计入“同时活跃可闻独立振荡器”？ | **无回复**。指南写“FM 按调制运算器统计”，但该追问尚未澄清具体可闻判定 | 技术 #89（第 51 行） |
| DDS IP 生成 4 通道正弦是否算独立？ | 回复表示无法具体断定，须结合实际设计与赛题定义判断。原表没有直接确认“4 通道就等于 4 合规声部” | 技术 #84（第 46 行） |
| 波表实时插值算过采样吗？ | 回复认为边界不清，精妙优化可能有价值，最终看效果；**没有统一定义**。不应据此自行把内部插值倍数乘进得分吞吐量 | 技术 #104（第 66 行），非确定答复 |
| 现场如何验证？ | 提供测试模式，输出不同频率的声音，频谱中能观察到对应数量独立谱峰；提供 RTL 佐证纯硬件实时合成，排除预录播放 | 指南正文第 14 页 |
| “多路不同频率”要多路 I2S 吗？ | 一个输出通道即可；多个频率混入同一通道。表格建议板载音频输出加一份引至排针的 I2S，两者输出相同音频通道 | 技术 #110（第 72 行） |

## 11. 根据资料整理的实现与展示检查项

以下是基于上述资料的整理建议，不是新增官方规则。

- [ ] 至少 2 个可独立操控的演奏维度，能演示各维度的实际控制作用。
- [ ] 至少 4 路独立声部同时发声，逐样本实时合成，具备变调、包络和混音。
- [ ] 清楚说明音频、效果器、实时可视化均由 FPGA HDL 实现，外围 MCU 各承担什么功能。
- [ ] 保留可验证的 I2S 输出与 DAC 发声链路，能现场听清不同音色。
- [ ] 分别列出声部数、每声部振荡器/算子数、活跃可闻总数、实际输出采样率，不把内部过采样倍数计入吞吐量。
- [ ] 准备多频测试模式、频谱截图或现场测量，以及 RTL/状态存储/调度说明，证明独立性和实时生成。
- [ ] 对传感器、读取/消抖、FPGA 合成、DAC 输出分段测时，标明起止点，单独报告 FPGA 延迟与整机可测延迟。
- [ ] 拓展按所选方向展示 ≥32 规模、≥3 维表情、≥2 音色、效果器、≤5 ms 确定性延迟、实时可视化或手机联动。
- [ ] 报告、视频、队名及演示界面去除学校标识，写清自制、复用和外包部分。
- [ ] 线下测评前搭好仿真环境，能够独立完成基础 HDL 与状态机题；现场测评不用 AI。
- [ ] 核实借板归还要求，以及影响最终选型的未定事项。
