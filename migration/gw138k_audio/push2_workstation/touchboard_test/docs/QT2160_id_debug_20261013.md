# AT42QT2160 从通信不通到成功读取 ID：测试记录与注意事项

日期：2026-10-13；时间采用北京时间（Asia/Shanghai）。

本记录整理当天在现有 FPGA 工程上，通过 JTAG 调试触摸芯片、最终成功读取 ID 的过程。重点是地址确认、协议检查以及 STOP→START 间隔的修正。

**最终结果：使用 7 位地址 `0x0D`，成功读取芯片 ID `0x11`、版本 `0x40`，三次实板采集全部应答正常。**

用户已确认：测试期间曾更换不同的测试芯片，中间“成功 → 失败 → 成功”的变化由更换测试芯片造成。因此这些结果不作为同一芯片运行稳定性的判断依据，也不能据此认定重新下载本身修复了芯片故障。

## 2. 初始读取：先明确失败发生在哪一步

首先增加独立模块 `rtl/qt2160_id_reader.v`，使用不超过 100 kHz 的 I²C，读取寄存器 `0x00`（ID）和 `0x01`（版本）。SCL、SDA 采用开漏方式，只主动拉低，高电平由上拉产生。

首次及前几次测试出现过两类结果：

| 现象 | 调试记录 | 可以得出的结论 |
|---|---|---|
| 写地址 `0x1A` 即 NACK | ACK 位图 `0x00`，错误码 `1` | 该次测试对象没有应答写地址，尚未进入 ID 读取阶段 |
| 写地址及指针 `0x00` ACK，读地址 `0x1B` NACK | ACK 位图 `0x03`，错误码 `3` | 写阶段已有响应，但从写操作切换到读操作失败 |

在第二种情况下，重点转向写指针后的 STOP、下一次 START，以及读地址发送时序。

此时日志里的 `ID=0x00`、`Version=0x00` 是控制器初始化值。由于还没有真正收到 ID 数据，不能把它当成芯片返回值，也不能据此判定芯片 ID 不正确。

## 3. 四地址轮询：确认响应地址

为排查地址选择问题，将读取逻辑改为四地址轮询，每次读取结束等待 200 ms 后切换下一地址：

```text
0x0D → 0x17 → 0x44 → 0x6B → 0x0D …
```

地址对照如下。第一列地址是 7 位从机地址；写、读地址字节已经包含最低位的 R/W 位。

| A1 | A0 | 7 位地址 | 写地址字节 | 读地址字节 |
|---|---|---|---|---|
| 0 | 0 | `0x0D` | `0x1A` | `0x1B` |
| 0 | 1 | `0x17` | `0x2E` | `0x2F` |
| 1 | 0 | `0x44` | `0x88` | `0x89` |
| 1 | 1 | `0x6B` | `0xD6` | `0xD7` |

18:30 完成四地址版本编译、JTAG 下载和三轮采集，共 12 次：

| 地址 | 三次采集结果 |
|---|---|
| `0x0D` | 写地址、寄存器指针均 ACK，读地址 `0x1B` NACK |
| `0x17` | 写地址 NACK |
| `0x44` | 写地址 NACK |
| `0x6B` | 写地址 NACK |

只有 `0x0D` 在写阶段应答，与 A0/A1 接地的配置相符。继续尝试其他地址没有解决读阶段问题，下一步对照该芯片的专用协议及勘误。

## 4. 找到关键要求：STOP→START 必须至少间隔 50 µs

手册的读取流程要求：写入寄存器指针后，必须先发送 STOP，再发起新的 START，随后发送读地址。当前程序已经使用 STOP 分隔，没有使用 repeated START。

进一步检查 AT42QT2160 手册第 49 页“Known Issues”，发现明确的时序勘误：

> Provide a minimum 50 µs bus free time between a STOP and START condition to ensure reliable communication.

手册说明，普通 I²C 的 4.7 µs 总线空闲时间对 AT42QT2160 不足，尤其可能导致读取通信失败。

修正前，程序写入指针并发送 STOP 后，约 10 µs 就发起下一次 START。虽然符合普通 I²C 的最小空闲时间，但没有满足该芯片的 50 µs 勘误要求。这是本次查到并修正的明确协议时序问题。

必须区分两个等待：

| 等待位置 | 用途 | 本工程最终设置 |
|---|---|---|
| 一次完整读取结束，到下一次读取尝试 | 控制重试频率 | 200 ms |
| 写寄存器指针的 STOP，到读地址前的 START | 满足芯片内部通信处理要求 | 至少 100 µs |

两次完整尝试之间等 200 ms，不能代替同一次读取中写指针之后的等待。

## 5. 修改、验证及首次成功

在读取模块中增加 `BUS_FREE_CYCLES=5000`。50 MHz 时钟下，一个周期为 20 ns，5000 个周期对应 100 µs。

每次 START 前，确认同步后的 SCL、SDA 连续保持高电平至少 100 µs；如总线不空闲，就重新计时。写指针之后的 STOP→START 还包含原有 STOP_FREE 状态约 5 µs 的等待，因此该段间隔约为 105 µs。

修改完成后进行了以下验证：

1. 运行单地址、四地址两组协议仿真，检查正常读取、ACK/NACK、时钟延展、超时和地址回绕。
2. 在仿真中直接检查总线 STOP/START 边沿，共检查 26 个间隔，均不少于 100 µs。
3. 完整工程编译、布局布线、时序检查通过，再通过 JTAG 下载。
4. 实板再次轮询四个地址，各采集三次。

18:48 的实板结果：

| 地址 | 结果 | ACK 位图 | 错误码 |
|---|---|---|---|
| `0x0D` | 三次均返回 ID=`0x11`、Version=`0x40` | `0x07` | `0` |
| `0x17` | 写地址 NACK | `0x00` | `1` |
| `0x44` | 写地址 NACK | `0x00` | `1` |
| `0x6B` | 写地址 NACK | `0x00` | `1` |

延长空闲时间后，此前 `0x0D` 的读地址 NACK 消失，成功完成了 ID 与版本读取。其余地址不应答符合当前地址引脚配置。

## 6. 最终固件：只读取 0x0D

在成功确认地址之后，将顶层明确设置为 `SCAN_ADDRESSES=0`，只读取 `0x0D`，同时保留 100 µs 空闲时间要求。

18:58 重新编译并下载固定地址固件，三次采集均返回 ID=`0x11`、Version=`0x40`，全部 ACK、错误码为 0。最新一次 19:24 下载测试也得到相同的三次成功结果。

期间更换不同测试芯片产生的成功、失败变化，按用户说明归于测试对象变化；本记录不将其列为固件间歇性失效或重新下载修复故障的证据。

最终读取流程为：

```text
START
→ 0x1A（0x0D + 写）→ 从机 ACK
→ 0x00（ID 寄存器指针）→ 从机 ACK
→ STOP
→ 总线连续空闲至少 100 µs
→ START
→ 0x1B（0x0D + 读）→ 从机 ACK
→ ID 0x11 → 主机 ACK
→ Version 0x40 → 主机 NACK
→ STOP
```

最终参数与结果：

| 项目 | 设置或结果 |
|---|---|
| 地址模式 | 固定 `0x0D` |
| 总线速率 | 不超过 100 kHz |
| 上电等待 | 100 ms |
| START 前连续总线空闲 | 至少 100 µs |
| 完整读取后的重试等待 | 200 ms |
| 总线及延展超时 | 20 ms |
| ID / 版本 | `0x11` / `0x40` |
| ACK 位图 / 错误码 | `0x07` / `0` |
| 固定地址版本最终时序 | WNS=0.756 ns，WHS=0.050 ns，无失败端点 |

## 7. 注意事项

### 7.1 地址和读取协议

- A0/A1 均接地时，7 位地址为 `0x0D`。不要把线上发送的 `0x1A`、`0x1B` 当成 7 位地址。
- 写指针与读取之间必须使用 STOP，再使用 START。
- 必须遵守芯片勘误：STOP→START 至少 50 µs，本工程留到至少 100 µs。
- 本次只读取 ID 和版本，没有写入触摸配置参数，也没有验证触摸按键功能。写入 `0x00` 是设置寄存器指针。

### 7.2 串联电阻与上拉电阻

- SCL、SDA 各串联 100 Ω，通常可以用于减小振铃，在约 100 kHz 下通常不会阻止正常读取。
- 串联电阻不能代替上拉电阻。SCL、SDA 应分别通过上拉电阻接到兼容的电源电压，本配置为 3.3 V。
- 手册推荐上拉范围为 1–10 kΩ，4.7 kΩ 可作为常见起点；最终要按线路电容、低电平电流和波形选择。
- FPGA 内部上拉已开启，但较弱，建议使用外部上拉。手册要求 SCL、SDA 上升时间不超过 1 µs。
- 如发生 NACK，应在芯片侧观察波形。ILA 记录空闲为高，只能说明采样时刻的逻辑电平，不能证明模拟上升沿合格。

### 7.3 CHANGE

- CHANGE 是低有效开漏状态通知输出，不参与 I²C 地址选择。
- 当前程序主动读取 ID，只记录 CHANGE 电平，不依赖它触发读取；不用时可以不连接。
- 如以后用于检测触摸状态变化，应连接 FPGA 输入，并上拉到 3.3 V。
- 手册建议初始化时等待 CHANGE 拉低表示芯片已准备好；当前 ID 测试使用固定上电等待和重复尝试。CHANGE 不接时，其记录电平不能代表芯片是否已完成初始化。

### 7.4 RST

- RST 低有效，手册明确允许不用外部硬件复位时连接到 Vdd。因此芯片使用 3.3 V 供电时，RST 接 3.3 V 是允许的。
- 如需要调试复位，可改为通过例如 10 kΩ 电阻上拉，再预留拉低控制；手册要求复位低脉冲至少 10 µs。
- RST 直连 3.3 V 时不能直接把该节点短接到地进行复位。
- 当前 RST 未连接 FPGA，JTAG 重新下载不等于对触摸芯片执行了硬件复位。

### 7.5 测试对象与结果记录

- 更换芯片时记录芯片编号、丝印、连接条件、上电状态和对应采样，避免把不同测试对象的结果混在一起。
- 写地址 NACK、指针 NACK、读地址 NACK 应分别记录；写地址 NACK 发生在写指针后等待之前，不能直接归因于该段 STOP→START 时间不足。
- ACK 位图为 `0x07`、读取完整、错误码为 0、ID 为 `0x11`，才是本工程的成功识别条件。
- 未完整读取时，日志中的 `0x00` 是初始化值。`scan_status=COMPLETE` 表示采集完成，是否读到正确 ID 要看 `status` 和各次结果。
- 三次 JTAG 采集是三个独立完成结果，不等于已经完成全部运行期间的统计或触摸功能测试。
- 手册第 49 页另有多从机总线通信问题，建议给每颗 AT42QT2160 使用独立 I²C 总线。

### 7.6 JTAG 下载与工程文件

- 当前下载是 FPGA 易失性配置，未烧写启动存储器；掉电后需要重新 JTAG 下载，或另行制作启动镜像。
- 使用与 `.bit` 匹配的 `.ltx` 探针文件，避免错误解析调试数据。
- 当前下载脚本初始化 PS、配置 PL，并启动已有 ARM 程序；触摸测试使用专用脚本，不执行 HDMI、摄像头数据流核验。
- 完整工程重新编译时检查最终时序报告，不以布局布线中的中间估计值作为最终结论。
- 本次硬件连线和串联电阻条件来自用户说明；外部上拉阻值、模拟波形没有在本次测试中实测确认。
