# HDMI 无信号调查

更新：2026-09-08。本文记录只读核对结果和待实测项，不把 RTL 仿真或 STA 通过等同于显示器已锁定。

## 修复后的结果

15:06的官方PLL初始化版（SHA开头2ba120fe）在同板、同线、同显示器上手动下载并按S3后，用户确认稳定项目画面，显示器信息页1920×1080/60Hz，演奏可视化反馈正常。12次连续快照均DDR=0xCB、HPD=1、欠载0，像素平均频率约148.5MHz、扫描与渲染约60帧/s。该版本保持原频率参数、光栅、ELVDS与四路OSER10，引入当前官方ICP/LPF初始化；本次对照支持该初始化修复了实际失锁现象，但没有模拟抖动/眼图测量来确定某个具体电气数值。下文保留排查过程及旧版结果。

## 修复前的板测事实

用户重新下载第四路 OSER10 时钟修复版后，显示器仍提示“无信号”。该版 SHA-256：`7fc6c77eeb5a5e410b9f45dccf747f387a4bab7b552289f634536171f5842b46`，备份为 `build/hdmi_clock_fix_20260908.fs`；构建时间为 2026-09-08 14:20:38。

该版本 COM26 查询仍返回 `0xCB`：DDR 校准、BIST 完成、首帧有效及视频/DDR 时钟就绪标志为 1，没有 BIST 失败、读故障或欠载标志。`front_valid` 只能由像素域消隐请求跨域后置位，说明光栅至少推进过首帧；它不能证明持续刷新、准确频率或显示器锁定。视频就绪标志实际来自启钟流水末级，也不是频率测量值。14:49诊断版7fbf05f4已下载，最初UART无回复，按S3后恢复。12次完整快照均HPD=1、视频就绪/像素和扫描复位释放、串化器不在复位、DDR=0xCB、欠载=0；像素块数1450/1451，对应148.4800/148.5824MHz（量化±0.1024MHz），8.61s内vblank和渲染均推进517帧，约60帧/s。用户随后明确显示器指示灯反复在有信号/无信号之间跳变、无法进入菜单；此前的黑画面描述不能记为稳定视频。用户确认显示器、线材和接口与640×480成功显示时相同。原始数据见 [诊断版板测](evidence/com26_video_diagnostics_20260908.json)。

## 修复前已核对的数字路径

- C 版项目及已布线网表的 PLL 参数一致：第一级 `IDIV=1, FBDIV=1, MDIV=24+6/8, ODIV0=25`，由 50 MHz 得到标称 49.5 MHz；第二级 `MDIV=15, ODIV0=1` 得到 742.5 MHz，再由专用 CLKDIV `/5` 产生 148.5 MHz。两个 VCO 分别为 1237.5、742.5 MHz，符合 DS1239 的 650–1300 MHz 范围。未发现输出旁路或动态倍频被误启用。布线报告中串化时钟使用 `BANK3_HCLK0`。
- HDMI0 的 P/N、蓝通道 `{VS,HS}`、红绿通道控制 00、D0 到 D9 顺序和 2200×1125 正同步光栅已核对。K14 的 TX +5 V 使能保持与原成功 640×480 版相同的高电平。
- 原始 CLKDIV `/5` 为高 6 UI、低 4 UI；修复版时钟 OSER10 发送 `1111100000`，高低各 5 UI，周期 10 UI。实际 `dvi_tx_top` 加本机官方原语模型通过 9 个启动/相位场景，在统一转发时钟下降沿核对 3240 个三色 TMDS 字，无逐通道相位搜索；恢复直接转发像素时钟或反相时钟字均会被测试拒绝。该修复没有解决本次板上“无信号”。
- 此版 setup/hold 违例均为 0，114 个复位端点审计通过。详见 [验证记录](verification.md) 及 [修复版构建证据](evidence/build_evidence_hdmi_clock_fix_20260908.json)。

[UG986-1.2.7 Pinout](../../../Doc/GW官方/UG986-1.2.7_GW5AST-138器件Pinout手册.pdf) 的 **TrueLVDS PG484A，Bank3 True LVDS Pair** 表（手册第 77 页）明确列出当前四对管脚：

| 通道 | P/N 球位 | IO 对 |
|---|---|---|
| 时钟 | G15 / G16 | IOR105A/B |
| 蓝 | J14 / H14 | IOR103A/B |
| 绿 | J15 / H15 | IOR101A/B |
| 红 | K17 / J17 | IOR58A/B |

这些管脚具备 TLVDS 能力。[DS1239-1.0.3](../../../Doc/GW官方/DS1239-1.0.3_GW5AST系列FPGA产品数据手册.pdf) 表 2-1 将 LVDS25/TLVDS 列为支持 2.5/3.3 V Bank 供电、3.5/2.5/4.5/6 mA；LVCMOS33D 则是 3.3 V、8/4/12/16/24 mA，二者不是仅替换原语名称的等价配置。[UG304-1.3.7](../../../Doc/GW官方/用户指南/UG304-1.3.7_Arora_V可编程通用管脚(GPIO)用户指南.pdf) 第 2 页及 3.6.6 节区分 TLVDS 的电流输出与 ELVDS 的电压输出。若后续做 TLVDS 对照，必须同时核对 IO 类型、驱动设置、板上连接及接收端终端条件，并重新 PnR。

在上述 DS1239/UG304 中，**未找到分别给 ELVDS/LVCMOS33D 与 TLVDS 指定不同串行速率上限的明确表格**。DS1239 表 3-16 的 OSER10 1600 Mbps 脚注明确为 **IO 逻辑最高速度，实际速度由具体 IP 决定**，不能据此宣称当前 1485 Mbps 的输出缓冲、PCB、连接线及显示器链路已经满足要求，也不能无依据宣称 ELVDS 存在某个更低的固定上限。表 3-12 的差分输出电压/共模测试条件为 100 Ω 负载，亦不能代替实际 HDMI 连接器处的电气检查。

## 排查时的假设与判别方法

1. **实际频率或持续时钟异常。** 先用 50 MHz 参考窗口测像素计数，应对应 148.5 MHz，并观察光栅帧持续推进。若测得恰好 144 MHz，可针对第一级分数反馈未生效的假设继续定位；当前网表本身没有此错误。不要仅用 LOCK 或 STA 的时钟声明判定频率。
2. **连接器/接收端状态。** 读取 K13 HPD；HPD 与“显示器已锁定视频”不同。其极性、上拉和可否驱动以本板原理图为准，不能直接执行旧 demo README 中“拉高 HPD”的建议。若 HPD 正常且频率正确，检查 HDMI 连接器上的时钟、数据和供电，而非继续无依据修改光栅参数。
3. **PLL 模拟初始化或级联抖动。** 14:49及更早的视频版本沿用旧裸 PLL，`DYN_ICP_SEL/DYN_LPF_SEL=FALSE`；2026 年 `cam_dvi` 的 TMDS PLL 和本项目 DDR PLL 包含 `PLL_INIT`，扫描 ICP/LPF 并控制 RESET/LOCK。UG306-1.0.9 第 53 页说明 138K 的 PLL_init 控制；第 48 页同时明确静态 `ICP_SEL=X/LPF_RES=X` 表示软件自动计算，因此 X 并不证明未配置。PLL_INIT 没有 MDIV/ODIV 输出，不能用它替代频率诊断。若频率正确仍不能锁屏，可用当前工具针对 C 版生成的 PLL 初始化作为后续单变量对照。
4. **1485 Mbps 电气余量不足。** 这是待测假设，当前只能确认低速旧版曾显示成功及新数字链路测试通过。DS1239 表 3-18 脚注说 PLL 测试基于整数分频，抖动数据基于低抖动晶振输入；分数反馈后再级联 PLL 的模拟抖动、杂散和板上眼图不在本次数字原语测试中。先得到频率/HPD证据，再决定 PLL_INIT、输出电气或降低速率的对照测试。

未找到官方资料禁止 C 版小数反馈或两级 PLL 级联的依据，也未找到“裸 PLL 必定失败”的依据。本调查没有修改 RTL、SDC、CST 或硬件设置。

## PLL_INIT后续对照准备

当前官方helper的初始化时钟可独立于PLL参考输入；两个初始化器可统一使用板载50MHz、`CLK_PERIOD=20`。`MULTI_FAC`仅参与大于16和34的ROM分档比较，第一级用整数24与24.75逐项等价，第二级为15；实际分数倍率仍由PLL的`MDIV_SEL=24/MDIV_FRAC_SEL=6`控制。官方cam_dvi实际倍率22.25而生成wrapper设置MULTI_FAC=22，提供此整数写法的先例。后续若做对照，须接ICPSEL/LPFRES/O_RST、开启动态ICP/LPF选择、将原始LOCK交给helper并取O_LOCK，保留现有两级资格和串化器启动顺序。14:49诊断位流尚未包含PLL_INIT；基于平均频率正常但接收器反复失锁的实测，已完成包含官方初始化的对照版，保持PLL倍率、1080p时序、ELVDS输出及OSER10启动序列不变。
