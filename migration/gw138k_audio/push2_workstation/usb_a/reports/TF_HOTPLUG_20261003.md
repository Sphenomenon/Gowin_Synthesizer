# TF 热插拔验证（2026-10-03）

## 实现

- TF 座没有接卡检测脚。文件读卡器空闲时每秒读取一次 0 号扇区；正在读取扇区而 0.5 秒没有收到数据时，复位 TF 读卡器并重新扫描 FAT 根目录。
- 扫描失效时，跨时钟歌单先发送零首曲目，Push 清除旧选曲与指引；重新扫描结束后再发送文件名。TF 解码和 CNN 当次运行复位，DDR 中的 CNN 权重保留。

## 已验证

- `tb_tf_hotplug_probe`：空闲轮询、拔卡后读超时、读卡器复位与重新插入，PASS。
- `tb_playlist_bridge`：旧歌单失效及新歌单跨时钟重载，PASS。
- `tb_song_menu`：曲目数归零后清除选曲、重插后恢复边界，PASS。
- Gowin 0x61 位流综合、布局布线成功；PNR BSRAM 279/340。DDR 100 MHz 路径估计 Fmax 223.025 MHz。50 MHz、音频和 USB 时钟域仍有时序违例，分别估计 42.646、60.363、41.690 MHz。
- 0x61 已写入实体 138K 的 SRAM，CNN 模型 104478 字节上传后 DDR 回读 CRC 通过，板端状态 `E`，原始记录见 `reports/song_guide_model_upload_61_20261003.log`。

## 0x61 实体失败与 0x62 修正

用户在 0x61 板上拔卡后，Push 清单没有清空；把卡拿到电脑上改文件名再插回，清单仍未刷新。此前仿真只让读卡器处于 `READY`，漏掉了真实使用中常见的 `READ_A_FILE` 暂停状态：CNN 固定窗口分析完成后停止消费 PCM，DDR 音频环和 TF 捕获 FIFO 可以逐步填满，文件读取器因 `sector_allow=0` 暂停。此时没有待完成扇区，0x61 的超时器不运行；轮询也只允许在 `READY`，故拔卡永远不会被检测到。板端遥测没有暴露文件状态，故这是一种与现场结果一致的代码路径推断，而非对该次内部状态的直接测量。

0x62 让暂停的 `READ_A_FILE` 也读取 0 号扇区探测，且屏蔽探测扇区进入文件字节流。针对这一状态的仿真现已通过。0x62 构建、烧录和实体复测仍待完成。当前位流不会在卡始终保持插入但 FAT 根目录由别处修改时刷新；实际拔插依靠探测失败后的重新扫描。

回归对照：更新后的 `tb_tf_hotplug_probe` 使用 0x61 源码运行时在“暂停文件读取没有探测”处失败（`state=5 timer=0 inflight=0 probes=0`）；使用 0x62 源码时通过。0x62 还把文件状态、SD 状态、扇区忙、FIFO 是否允许下一扇区、目录扫描有效和拔卡故障历史放进模型状态 `E` 后的 `B138` 第二字低 16 位，供实体测试直接定位。

0x62 已上板，用户确认 TF 拔出超过 5 秒后 Push 清单仍未清空。该版的 DDR 用户时钟估计 Fmax 为 71.252 MHz（目标 100 MHz）；CNN 模型上传后的 DDR 回读 CRC 失败，状态 `F`，见 `reports/song_guide_model_upload_62_20261003.log`。其热插拔遥测只在模型状态 `E` 时输出，故这次无法从串口直接确定卡检测内部状态。Push USB 遥测仍报告 configured=1、屏幕 ACK=266、OUT 错误=0，说明屏幕链路在继续刷新，但不证明歌单输入变化。

0x63 把热插拔状态改为无条件通过 `B138` 输出，供模型 CRC 失败时诊断；探测成功后恢复被覆盖的文件扇区地址，并在仿真中验证继续读取目标扇区。布线选用时序优先的 place/route 选项，目标是恢复 DDR 模型回读可靠性。

0x63 已上板。用户确认 TF 卡保持拔出；串口先报告文件读取暂停（`fs=5, sector_allow=0, scan_done=1`），随后 `sector_busy` 从 0 变 1，证明暂停状态的主动探测已经触发。但该请求持续至少 20 秒，`scan_done` 不下降，`lost_seen` 仍为 0，Push 清单没有清空。0x63 的 watchdog 用底层 `rvalid_session` 清零计时，若该信号在不完整请求中活动，便可能永远不超时。0x64 改为只按整个扇区请求未完成的时长计时：请求结束或读卡器复位才清零；超过 0.5 秒重置读卡器。

## 0x64 实体复测

0x64 位流已写入实体 138K 的 SRAM。TF 卡保持拔出时，串口起初报告 `fs=5, card=8, sector_busy=1, scan_done=1`；约 0.6 秒后报告 `fs=1, card=1, scan_done=0`，确认超时复位与歌单失效。用户随后插入已改名的 TF 卡，确认 Push 屏幕显示新歌名。串口同时报告 `fs=5, scan_done=1, wav_ready=1`，采样率从旧文件的 44100 变为新文件的 48000。CNN 模型重新上传 104478 字节，DDR 回读校验通过，状态 `E`。

该次构建 PNR BSRAM 279/340；DDR 100 MHz 时钟域估计 Fmax 232.061 MHz。仍有其他时钟域的时序违例，不能据此声称全设计时序收敛。0x64 位流路径：`results/song_guide_hotplug64_20261003/Prj1/impl/pnr/Prj1.fs`。以上结论是一次拔卡、改名、重插的实体复测；没有据此推断反复热插拔或所有 TF 卡兼容性。

## 曲谱范围

MUSIC02 的 40 项仅来自文件开头约 1.99 秒的固定 172 帧分析窗，不是整首曲谱。当前 `cursor/score_count` 是该窗口内的指引进度。0x64 位流中的屏幕状态已改为 `2S EXCERPT`。整首分析需要续窗调度、尾窗处理、更大的曲谱存储与吞吐量优化。
